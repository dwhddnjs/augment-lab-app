## Context

26.21 "스타덤을 향한 여정" 패치로 무작위 총력전: 아수라장에 판마다 하나씩 적용되는 헤드라이너 8종이 들어왔다. 증강 데이터는 6aa3109 에서 반영했고, 이번에는 헤드라이너를 드래프트에 옮긴다. 진입 시 랜덤 결정 → 등장 연출 → 헤더 표시 → 헤드라이너별 규칙 → 얻은 것을 Drawer·아이템 화면·빌드 상세에 표시하고 저장한다.

## 확정한 결정

사용자 답변:

- **등장 풀**: 8종 균등 랜덤. 카페·꿀벌도 등장하고 드래프트 효과는 없다.
- **아펠리오스**: 게임 데이터대로 모루 2개. 스티커를 두 번 고르면 `능력치 모루 4개`로 합산 표시한다.
- **True Damage**: 설명만. 모루 상태를 만들지 않는다.
- **펜타킬 순서**: 스킬 → 증강 4회 → 스킬. 위키의 "첫 증강 다음"과 달라도 요청대로 간다.

기본값으로 정한 것:

- **표시명**: Riot 패치노트 표기(디스코·꿀벌)를 쓴다. 게임 내 제목은 우주 그루브·꿀벌 유랑단이다.
- **커맨드 라인**: 실버·골드 라운드만 나오고 프리즘은 해킹 리롤로만 얻는다(`COMMAND_LINE_ODDS`, 50:50). 처음엔 프리즘 라운드도 뒀지만 사용자 재조사로 바꿨다. 위키는 이 부분을 적지 않았고 나무위키의 "프리즘 미등장"과 맞다.
- **스티커 확률**: 공개된 값이 없어 슬롯별 40%(라운드당 평균 1.2장)로 둔다. `STICKER_CHANCE` 상수 하나로 조정한다.
- **스탯 합산**: 스티커 스탯은 텍스트로만 표시한다. 합산 패널은 지금도 증강 효과를 더하지 않는다.
- **`GoH_PentakillAug_*`**: 증강 JSON에 넣지 않는다. 뽑기 풀이 아니라서 `docs/index.html`·`EXPECTED` 검사도 건드리지 않는다.
- **커스텀 모드**: 헤드라이너를 적용하지 않는다.

## 구현

### 1. 새 데이터 도메인 `src/features/headliners/`

`aram`과 `builds`는 화면 도메인이라 서로 import 할 수 없다. 헤드라이너는 드래프트·아이템·빌드 상세가 함께 읽으므로 데이터 도메인으로 두고, `CLAUDE.md` 의 데이터 도메인 목록에도 추가한다.

- `types.ts`: `HeadlinerId`, `SkillKey`, `StickerId`, `BuildHeadliner { id: string; skills: SkillKey[]; stickers: string[] }`
- `rules.ts`: React·이미지·aram 의존 없는 순수 규칙. `ARAM_ROUNDS`(`use-aram.ts` 에서 이동, `picked-drawer.tsx` import 갱신), `HEADLINER_IDS`, `STICKER_IDS`, `STICKER_CHANCE`, `rollHeadliner`, `roundsFor`, `nextRarity`, `skillChoices`, `rollSticker`(슬롯 1개), `anvilCount`
- `assets.ts`: `require` 맵(로고 8, 멤버 초상 6). `lib/ddragon.ts` 의 `LOCAL_AUGMENT_ICONS` 와 같은 방식
- `data/headliners.{ko,en}.json`: 이름, 설명, 스티커 문구(`full`·카드 툴팁용 `short`), 스킬 카드명(헤비·파워·스래시·둠 / HEAVY·POWER·THRASH·DOOM)과 설명
- `hooks/use-headliners.ts`: `useLocalizedData` 로 로케일 분기
- `components/headliner-summary.tsx`: 공용 표시. 8장 참고

### 3. 챔피언 스킬 데이터

`Champion` 에는 스킬이 없고, 파일명은 `ApheliosQ_ClientTooltipWrapper.png` 처럼 규칙으로 추측할 수 없다.

- `scripts/fetch-data/fetch-champion-spells.ts`: `version.json` 의 16.16.1 고정으로 `championFull.json` 을 로케일별 1회씩 받아 `src/features/champions/data/champion-spells.{ko,en}.json` 생성 (`{ [championId]: { q|w|e|r: { name, image } } }`)
- `package.json` 의 `data:refresh` 끝에 연결. 빠뜨리면 다음 갱신 때 버전이 어긋난다
- `features/champions/hooks/use-champion-spells.ts`, `lib/ddragon.ts` 의 `spellImageUrl(file)` 추가
- `fetch-ddragon.ts` 는 건드리지 않는다. 실행하면 버전이 올라가 아이템·프리웜까지 함께 바뀐다

### 4. 드래프트 엔진 `src/features/aram/hooks/use-aram.ts`

- `drawNext`·`reroll`·`pick` 의 `useCallback` 을 제거한다. deps 를 손으로 적어 둬서 새 상태가 빠지면 첫 렌더 값에 고정된다
- 결과는 `progress: BuildHeadliner` 한 객체에 모은다. 계산은 `pick`·`pickSkill` 안에서만 하고 `nextProgress` 를 반환한다. 픽 commit 은 380ms 전 클로저로 돌기 때문에 다른 곳에서 고치면 덮어써진다
- `useAram(mode, forcedHeadliner?)`. `progress.id` 가 헤드라이너의 단일 출처
- **라운드 수**: 라운드 표시는 항상 4. K/DA 는 4라운드 뒤 보너스 선택이 한 번 더 있어 내부 선택 횟수만 `roundsFor(id)` = 5
- **펜타킬**: `needsSkillPick = 펜타킬 && (skills 0개 || (round >= rounds && skills 1개))`. `pickSkill(key)` 추가, 두 번째 선택이 `done`. `done` 이면 `setProgress` 를 건너뛴다. 안 그러면 전환 중 증강 카드가 다시 뜬다. 마지막 라운드 뒤에는 쓰지 않을 카드를 뽑지 않는다(`nextRound < rounds` 일 때만 `drawNext`)
- **HEARTSTEEL**: 슬롯 값은 별도 state `slotStickers: (StickerId | null)[]`. 라운드마다 3칸을 새로 굴리고, 리롤하면 그 슬롯만 다시 굴린다. `pick` 이 고른 슬롯의 스티커를 `progress.stickers` 에 누적
- **커맨드 라인**: 라운드 상태 `hackUsed`, 픽할 때 `rerolled` 와 함께 초기화. 훅은 `hacked: boolean` 반환
  ```ts
  const hacked = isCommandLine && !hackUsed; // 라운드는 COMMAND_LINE_ODDS 로 실버·골드만 나온다
  const up = hacked ? nextRarity(card.rarity) : null;
  const [replacement] = drawOfRarity(pool, up ?? card.rarity, 1);
  setHackUsed(true);
  ```
  이제 행이 한 등급이 아닐 수 있으니 `use-aram.ts:70` 주석도 고친다
- `pick` 반환값: `{ nextPicked, nextProgress, done }`
- K/DA + 혼돈 변환이면 증강이 최대 7개다. `build-storage.ts:28` 주석을 고친다

### 5. 등장 연출과 헤더

구현 중 사용자 피드백으로 처음 설계에서 바뀌었다. 아래가 최종안이다.

- `components/headliner-reveal.tsx` (신규): 공연 타이틀 카드. 헤더까지 덮는 어두운 전체 화면(라이트 모드에서도 어둡다), 왼쪽에 판 없는 큰 로고, 오른쪽에 이름. 조명은 `HeadlinerColors`(theme.ts)의 밴드 고유색 하나만 쓴다
- 약 2.6초 뒤 자동 종료, 아무 곳이나 탭하면 건너뜀. 300ms 페이드아웃 동안 터치를 흡수한다. 끝난 뒤에 `CardRow` 를 그려 카드 flip 이 재생된다
- 인트로 중에는 화면이 덮여 나가기·픽 현황 버튼을 누를 수 없고, Drawer 스와이프도 막는다(`swipeEnabled={introDone}`). 나가려면 탭으로 건너뛴 뒤 나간다
- **헤더**: 라운드 pill 밖 왼쪽에 판 없는 아이콘만 둔다. 이름은 표시하지 않고 VoiceOver 라벨로만 둔다. pill 은 헤더 정중앙을 유지한다. K/DA 는 게임 마스크에 얼음빛 그라데이션과 파란 글로우를 입힌 `kda-mark.png` 를 쓰고, 흰 로고는 라이트 모드에서 글자색으로 칠한다. HEARTSTEEL 은 검은 윤곽이 있어 칠하지 않는다
- 시작을 누르면 드래프트 화면을 시트 아래에 애니메이션 없이 깔고, 시트만 페이드로 걷는다(`animation: 'fade'` 를 한 프레임 전에 설정). 시트가 사라진 뒤에 빈 화면이 회전하고 무대가 밝아진다(`useLandscapeLock(AFTER_MODAL_MS)`). `/aram`·`/custom` 은 전환이 끝나면 나갈 때 쓸 페이드를 켠다(`_layout.tsx`)
- 스킬 선택 중에는 pill 라벨을 `스킬 강화` 로 바꾼다
- `pick-card.tsx`: 펼쳐지는 중인 카드는 고를 수 없다(`rotateY === 0` 일 때만 선택). 연출을 건너뛰는 연타가 다음 카드를 집지 않게 한다

### 6. 카드와 리롤 버튼

- `components/skill-card.tsx` (신규): 게임 카드 원본(`augmentcard_bg`, `augmentcard_frame_gold`, `augmenticon_defaultbacklayer_gold`, `abilityframe_gold`)을 쌓아 인게임과 같게 그린다. 위쪽 중앙 펜타킬 로고, 왼쪽 위 챔피언 초상, 문양 안의 스킬 아이콘과 `[Q]`, 색 강조 설명. DDragon 스킬 아이콘은 64px 이라 크게 키우면 깨져 34pt 로 쓴다. 리롤 없음
- `rarity-card-frame.tsx`: `variant?: 'kda'`. 핑크·보라 글로우 hex 는 예외 파일인 이 안에 둔다. 등급 프레임은 유지해 티어를 읽을 수 있게 하고, `compact` 에서는 무시한다. 기본값이면 커스텀 화면은 그대로다
- `aram-card.tsx`: `footer` prop 추가. `PickCard` 안쪽에 둬서 카드와 함께 움직인다. footer 가 있으면 카드·리롤 gap 을 `Spacing.two` 로 줄인다. `CARD_HEIGHT_RATIO` 는 건드리지 않는다
- HEARTSTEEL footer: 높이 28pt 고정 슬롯, 스티커 없는 슬롯도 비워 3장 정렬 유지. [초상 24pt] + 2줄(멤버명 / `short` 문구). 10/14 폰트, `allowFontScaling={false}`, 줄마다 `numberOfLines={1}` + `adjustsFontSizeToFit`. 카드 우상단에 살짝 기울인 원형 초상 스티커
- K/DA 보너스: `variant="kda"` + 카드 위 K/DA 마크(`KDA_MARK`). 카드 위 빈자리에 띄워 다른 라운드와 카드 위치가 같다
- `reroll-button.tsx`: `hackedArt` prop. 주면 원형 대신 금색 커맨드 라인 마크가 버튼이 되고, 누를 수 있을 때 주기적으로 번쩍이며 살짝 커졌다 돌아온다(`withRepeat`). 티어를 올리면 3개 모두 기본 리롤 버튼으로 돌아온다
- 커맨드 라인 아이콘은 게임 로고를 금색으로 입힌 `command-line-reroll.png` 와 번쩍임 레이어 `command-line-reroll-flash.png`. 헤더·등장 화면 로고도 같은 금색(`command-line.png`)이다. 라이트 모드 헤더와 리롤 버튼은 밝은 배경에 묻히지 않게 진한 금색으로 칠한다

카드 줄은 세로 가운데가 아니라 헤더 밑에서 화면 높이의 7% 내린 자리에 고정한다(`CARD_TOP_RATIO`). 어떤 헤드라이너든 카드 위치가 같다. 가장 긴 HEARTSTEEL 줄은 카드 + 2 + 툴팁 28 + 4 + 리롤 36 이다.

### 7. 저장

- `SavedBuild.headliner?: BuildHeadliner` (옛 빌드·커스텀 빌드는 없음)
- 경로: `commitPick` → `aram-items` 의 `headliner` JSON 파라미터 → `ItemSelectContent` → `useItemSelect` → `saveBuild`·`ItemDetailPanel`
- `build-storage.ts` 에 `parseBuildHeadliner(raw: unknown)`. 파싱 결과가 다음 저장 때 디스크를 덮어쓰므로 화이트리스트로 만들지 않는다. `id` 는 문자열인지만 보고, `skills` 는 값 필터링, `stickers` 는 문자열 배열로 유지한다. 깨진 값이면 `headliner` 키만 빼고 빌드는 살린다
- 파라미터 파싱은 `item-select-screen.tsx` 에서 메모 없이, try/catch 를 둔 작은 함수로 한다(딥링크 진입 가능)

### 8. Drawer·결과 표시

`HeadlinerSummary`(`headliner`, `championId`): `picked-drawer.tsx`, `item-detail-panel.tsx`, `build-detail-screen.tsx` 공용.

- 세로 1열, 텍스트 `flex: 1, minWidth: 0`. 가장 좁은 곳(아이템 패널 180pt) 기준으로 맞춘다. `DetailCardRow` 재사용
- `undefined` 나 모르는 id 면 null 반환. 옛 빌드·커스텀 빌드가 여기 해당한다
- 공통: 로고 + 이름 + 설명
- 펜타킬: 강화한 스킬 (아이콘, 키, 스킬명). 스킬 데이터가 없으면 키 글자만
- HEARTSTEEL: 고른 스티커를 멤버별로 묶어 `×n`, 전체 문구(`full`). 아펠리오스는 `능력치 모루 N개`
- 디스코: `골드 +1,000`

`SLOTS` 는 5 그대로 둔다. 게임의 5번째 증강 칸과 같아서 K/DA 는 `5/5` 로 끝나고, 초과분은 기존 `Math.max` 가 늘린다.
