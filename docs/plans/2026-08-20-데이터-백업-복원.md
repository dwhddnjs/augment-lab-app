# 데이터 백업 · 복원 · 초기화

## Context

앱의 사용자 데이터(저장된 빌드, 테마·언어 설정)는 전부 기기 로컬 AsyncStorage에만 있다.
계정 로그인이 없어(커뮤니티 탭은 아직 placeholder) 앱을 삭제하면 데이터가 함께 사라지고,
재설치해도 복구할 방법이 전혀 없다. 마이페이지에 **데이터 관리** 화면을 추가해
백업(`.alab` 파일 내보내기) / 복원(파일 불러오기) / 초기화를 제공한다.

결정 사항(사용자 확인 완료):
- 백업·초기화 범위 = 저장된 빌드 + 설정(테마·언어) **전부**
- 복원 = **전체 교체**(기존 데이터 덮어쓰기), 실행 전 확인 다이얼로그

## 대상 데이터

AsyncStorage 키 화이트리스트(`BACKUP_KEYS`):
- `builds:v1` — 저장된 빌드 ([src/lib/build-storage.ts](src/lib/build-storage.ts))
- `theme:v1` — 테마 선택 ([src/hooks/use-theme-preference.ts](src/hooks/use-theme-preference.ts))
- `locale:v1` — 언어 선택 ([src/hooks/use-locale.ts](src/hooks/use-locale.ts))

제외: 이미지 프리웜 완료 플래그(캐시, [src/lib/image-prewarm.ts](src/lib/image-prewarm.ts)),
supabase 세션 토큰(자격증명 — 백업 파일에 담지 않는다).

## 의존성 (2개 추가)

```bash
npx expo install expo-document-picker expo-sharing expo-file-system
```
`expo-file-system`은 이미 node_modules에 있으나(expo 코어 경유) package.json에 명시해 버전을 고정.
네이티브 모듈이 늘어나므로 **`npm run ios` 재빌드 필요**(dev-client).

## 파일 변경

### 신규 — `src/lib/backup-format.ts` (순수 함수, IO 없음)
```ts
export const BACKUP_KEYS = ['builds:v1', 'theme:v1', 'locale:v1'] as const;
export interface BackupFile { app: 'augment-lab'; version: 1; exportedAt: string;
                              data: Record<string, string> }  // AsyncStorage 원문(문자열) 그대로
serializeBackup(entries, exportedAt): string   // JSON.stringify, 2-space
parseBackup(text): BackupFile                  // 실패 시 throw — app/version/data 형태 검증,
                                               // 화이트리스트 밖 키는 무시, builds:v1은 JSON 배열인지까지 확인
buildFileName(exportedAt): string              // `augment-lab-2026-08-20.alab`
```
값은 AsyncStorage에 든 **문자열 그대로** 담는다(빌드 스키마를 다시 정의하지 않는다).

### 신규 — `src/lib/backup.ts` (IO)
- `exportBackup(): Promise<string>` — `multiGet(BACKUP_KEYS)` → `serializeBackup` →
  `new File(Paths.cache, buildFileName(...))`에 write → `file.uri` 반환
- `importBackup(uri): Promise<BackupFile>` — `new File(uri).text()` → `parseBackup`
- `applyBackup(file): Promise<void>` — `multiRemove(BACKUP_KEYS)` 후 `multiSet(있는 키만)` → `refreshStores()`
- `resetAllData(): Promise<void>` — `multiRemove(BACKUP_KEYS)` → `refreshStores()`
- `refreshStores()` — `reloadBuilds()` + `loadLocale()` + `loadThemePreference()` 병렬 호출.
  세 스토어 모두 이미 useSyncExternalStore 구독 구조라 emit만 되면 화면이 즉시 갱신된다.

### 수정 — `src/lib/build-storage.ts`
`export async function reloadBuilds()` 추가: `cache = null; await readAll();`
(`readAll`이 끝에 `emit()` 하므로 목록 화면이 자동 갱신 — 새 구독 배선 불필요)

### 수정 — `src/hooks/use-locale.ts`, `src/hooks/use-theme-preference.ts`
`loadLocale`/`loadThemePreference`가 저장값이 **없을 때 기본값으로 되돌리도록** 한 줄 수정
(`_locale = raw === 'en' ? 'en' : 'ko'`, `_pref = raw ?? 'system'` + `applyColorScheme` + `emit`).
현재는 값이 없으면 메모리 값을 유지해서 초기화 직후 옛 설정이 남는다. 앱 최초 기동 동작은 동일.

### 신규 — `src/features/mypage/components/settings-row.tsx`
[mypage-screen.tsx](src/features/mypage/screens/mypage-screen.tsx)의 로컬 `SettingsRow`를
그대로 추출(아이콘+라벨+값+chevron). `iconColor` 파라미터가 이미 있어 초기화 행만 `status.danger`로.

### 신규 — `src/features/mypage/screens/data-manage-screen.tsx`
마이페이지와 동일한 스택(`@expo/ui/swift-ui` `Host`/`List(insetGrouped)`/`Section`,
`key={mode}` remount 트릭 포함). 행 3개 + 각 동작:
| 행 | 아이콘 | 동작 |
|---|---|---|
| 데이터 복원 | `square.and.arrow.down` | `DocumentPicker.getDocumentAsync({ type:'*/*', copyToCacheDirectory:true })` → `importBackup` → 빌드 개수 담은 확인 Alert → `applyBackup` → 완료 Alert |
| 데이터 백업 | `square.and.arrow.up` | `exportBackup()` → `Sharing.shareAsync(uri, { UTI:'public.data', mimeType:'application/octet-stream' })` |
| 데이터 초기화 | `trash` (danger 색) | destructive Alert 확인 → `resetAllData()` → 완료 Alert |
- 진행 중 중복 탭 방지용 `busy` 상태 하나. 모든 실패는 catch해 실패 Alert(원문 메시지 노출 안 함).
- 텍스트는 전부 파일 상단 `const t = { ko, en }` + `useTranslation(t)` (CLAUDE.md i18n 규칙).

### 신규 — `src/app/(tabs)/(mypage)/data.tsx`
`export { default } from '@/features/mypage/screens/data-manage-screen'` 한 줄
(기존 [index.tsx](src/app/(tabs)/(mypage)/index.tsx)와 동일 패턴).

### 수정 — `src/app/(tabs)/(mypage)/_layout.tsx`
`<Stack.Screen name="data" options={{ title: translate('dataTitle') }} />` 추가(대형 타이틀 없이 push).

### 수정 — `src/features/mypage/screens/mypage-screen.tsx`
로컬 `SettingsRow` 정의 제거 → 새 컴포넌트 import. **일반 섹션 맨 아래**에
`데이터 관리`(`externaldrive`) 행 추가 → `router.push('/data')`.

## 검증

1. `npm install && npx tsc --noEmit && npm run lint`
2. `npx tsx scripts/check-backup.ts` — 신규 assert 자체 체크(러너 없으므로 tsx 단독 실행):
   직렬화→파싱 라운드트립, 잘못된 JSON·`app` 불일치·`version` 불일치·화이트리스트 밖 키 거부/무시.
3. iOS 시뮬레이터 실기 검증(`.agents/skills/verify/SKILL.md` 절차, `npm run ios` 재빌드 필요):
   - 빌드 2~3개 저장 + 테마를 다크로 바꾼 상태에서 시작
   - 마이페이지 → 데이터 관리 진입, 헤더/행 3개 렌더 확인(라이트·다크 양쪽)
   - **백업**: share sheet → "파일에 저장" → 파일 앱에 `augment-lab-<날짜>.alab` 생성 확인
   - **초기화**: 확인 다이얼로그 → 홈 탭 빌드 목록이 빈 상태, 테마가 시스템으로 복귀
   - **복원**: 파일 선택 → 확인 다이얼로그 → 빌드 목록·테마가 백업 시점으로 복구, 빌드 상세 진입 정상
   - 취소 경로(파일 선택 취소, 다이얼로그 취소)에서 아무 변화 없음
   - 손상 파일(텍스트 파일 이름만 `.alab`) 선택 시 실패 Alert만 뜨고 기존 데이터 유지
4. 결과를 `docs/verification/2026-08-20-데이터-백업-복원.md`에 기록(스크린샷은 커밋하지 않음).
5. 이 계획서를 `docs/plans/2026-08-20-데이터-백업-복원.md`로 저장(CLAUDE.md 규칙).

## 하지 않는 것

- `.alab` UTI 등록 / 파일 앱에서 앱으로 직접 열기 — 앱 내 복원 버튼으로 충분(필요해지면 app.json `CFBundleDocumentTypes`로 추가)
- 암호화·클라우드 동기화·자동 백업 — 요청 범위 밖
- 백업 파일 버전 마이그레이션 로직 — `version: 1` 하나뿐이라 불일치는 거부로 끝
