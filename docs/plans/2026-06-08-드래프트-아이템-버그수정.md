# 드래프트/아이템 선택 화면 자잘한 버그 수정

## Context

ARAM 증강 드래프트(`draft.tsx` → `draft-screen`)와 아이템 선택(`draft-items.tsx` → `item-select-screen`) 화면에서 사용자가 발견한 자잘한 버그 5건을 수정한다. 증강 데이터 문제 3건은 데이터 빌드 스크립트(`fill-augment-ko.mjs`, `fill-augment-icons.mjs`)의 매칭 버그에서 비롯됐고, 아이템 화면 문제 2건은 레이아웃/스타일 이슈다.

**근본 원인(데이터):** CommunityDragon `cherry-augments.json`에는 동일한 영문 이름의 증강이 2개씩(아레나용 + ARAM Mayhem용) 존재한다. 두 스크립트 모두 `Map`에 `normalize(name) → 값`으로 넣어 **나중 항목이 앞 항목을 덮어쓴다**. 그 결과 `heavy-hitter`/`with-haste`의 한국어 이름이 엉뚱한 "왕 귀여운 발사기"로, 여러 증강의 아이콘이 잘못된 스웜(Strawberry) 경로로 매칭됐다.

데이터 재생성은 네트워크 의존(30MB stringtable 다운로드)이고 같은 버그가 재현되므로, **타깃 JSON 직접 패치**로 처리한다.

## 수정 1 — 증강 데이터 (`src/features/augments/data/augments.{ko,en}.json`)

### 1a. 깨진 한국어 이름 + 잘못된 아이콘 교정
| id | ko name (현재→수정) | 아이콘 경로 (수정 후, ko/en 공통) |
|---|---|---|
| `heavy-hitter` | "왕 귀여운 발사기" → **"강타자"** | `/lol-game-data/assets/ASSETS/UX/Cherry/Augments/Icons/HeavyHitter_small.png` |
| `with-haste` | "왕 귀여운 발사기" → **"속행"** | `/lol-game-data/assets/ASSETS/UX/Cherry/Augments/Icons/WithHaste_small.png` |

- en.json의 `name`은 이미 정상("Heavy Hitter"/"With Haste") → **iconPath만** 위 경로로 교체.
- ko.json은 `name` + `iconPath` 둘 다 교체.

### 1b. `final-city-transit` 아이콘 교정
- 현재: `.../Strawberry/UpgradeSelection/Icons/Weapon/9189_Train.png` (잘못된 스웜 경로)
- CommunityDragon 확인 결과 정식 경로: `/lol-game-data/assets/ASSETS/UX/Kiwi/Augments/Icons/Nightstalking_small.png` (Kiwi = ARAM Mayhem, 파일명은 내부 코드네임)
- ko/en 양쪽 iconPath 교체. 이름은 "최후의 도시 대중교통"으로 정상이므로 유지.

### 1c. 비활성 증강 제거
- `fetch`, `quest-sneakerhead` 두 항목을 ko.json·en.json **양쪽에서 객체 통째로 삭제** (둘 다 description에 "currently disabled" 포함, 아이콘 깨짐).

> **구현 시 검증:** 1a·1b의 새 아이콘 URL을 `augmentImageUrl(path,'large')` 규칙으로 변환한 실제 URL에 `curl -sI`로 HTTP 200을 확인한 뒤 적용한다. `augmentImageUrl`은 `_small`→`_large` 치환 후 `game/` 경로를 사용(`src/lib/ddragon.ts:23`). 200이 아니면 `'small'` 경로(plugins root)도 확인하고, 둘 다 실패 시 해당 항목 아이콘은 보류하고 보고.

## 수정 2 — 아이템 그리드 출렁임 (문제 4)

`src/features/items/components/item-select-screen.tsx`

- 원인: `leftPanel`(기본 column flex) 안의 아이템 그리드 `ScrollView`(385행 부근)에 `flex` 지정이 없어, 필터 변경으로 행 수가 달라질 때 ScrollView 영역 높이가 내용에 따라 변하며 레이아웃이 출렁인다.
- 수정: 해당 그리드 `ScrollView`에 `style={{ flex: 1 }}` 추가 → 영역을 고정해 필터 전환 시에도 그리드 영역·셀 위치가 동일하게 유지된다. (셀 크기 `cellSize`는 이미 `bodyWidth` 기반 고정이므로 추가 변동 없음)
- 필터 바(`ScrollView horizontal`, 359행)는 그대로 두되, 위 변경으로 그 아래 그리드가 고정되어 "필터 탭은 고정, 아이템은 같은 자리" 요구를 충족한다.

## 수정 3 — 선택 슬롯 스타일 (문제 5)

`src/features/items/components/item-slot-grid.tsx`

사용자 선택: **심플 border 격자 + 아이콘 꽉 채움**.

- 루트 `GlassSurface` → 일반 `View`로 교체하고 외곽 border 유지(`colors.border.subtle`, `Radius.lg`, `overflow:'hidden'`). `GlassSurface` import 제거.
  - (디자인 규칙상 고밀도/소형 셀은 글라스 미적용이 권장되므로 위반 아님)
- 채워진 슬롯 아이콘: `styles.icon`의 `width/height` `80%` → **`100%`**, `slot`의 `padding` 축소(`Spacing.one`→`Spacing.half` 또는 0)해 아이콘이 칸을 꽉 채우게. `contentFit`은 `contain` 유지(아이템 아이콘 정사각 보존).
- 빈 슬롯 `+` placeholder는 유지(빈 칸 식별용). 내부 격자선(`borderRight`/`borderBottom`) 로직 유지 → 순수 border 라인 3×2.

## 변경하지 않는 것
- 데이터 빌드 스크립트(`fill-augment-*.mjs`) 자체는 이번엔 손대지 않음(JSON 직접 패치). 향후 재생성 시 동일 버그 재현 가능성은 별도 이슈.
- `glass-cannon`(이름 정상)도 스웜 경로를 쓰지만 사용자 미언급 → 이번 범위 제외.

## 검증
1. `npm run lint` 통과.
2. `grep -n "왕 귀여운 발사기\|\"id\": \"fetch\"\|\"id\": \"quest-sneakerhead\"\|9189_Train" src/features/augments/data/*.json` → 결과 없음.
3. 앱 실행(가로모드) → 드래프트에서 강타자/속행/최후의 도시 대중교통 카드의 이름·아이콘 정상 표시, fetch 카드 미등장 확인.
4. 아이템 선택 화면: 필터 탭을 여러 번 전환해도 그리드 영역과 셀 위치가 출렁이지 않음 확인.
5. 우측 선택 슬롯: 아이템 선택 시 칸을 꽉 채우는 아이콘, 심플 border 3×2 격자 확인.
