# 커스텀 모드 UI 다듬기

## Context

커스텀 모드(`/custom`)를 붙이면서 급하게 그린 UI가 남았다. 헤더 타이틀은 가로 화면에서 공간만 먹고, 증강 풀이 수백 개인데 검색이 없어 티어 필터로만 좁혀야 한다. 좌우 패널 경계가 흐리고, 드래그 고스트에 이름이 붙어 손가락 아래가 지저분하며, 티어 레일 아이콘(특히 `circle-outline` = 전체)이 의미를 못 준다. 설정 드로어는 insetGrouped 카드 위에 세그먼트가 얹혀 이중 박스로 보이고, 하단 두 액션이 chevron 탓에 화면 이동처럼 읽힌다.

결과: 커스텀 화면은 검색으로 증강을 바로 찾고 패널 경계가 또렷해진다.

(같이 시도했던 홈 모드 필터의 네이티브화는 7번 참고 — 철회했다.)

---

## 1. 커스텀 헤더 — 타이틀 제거, 증강 검색바

**[custom-screen.tsx](src/features/custom/screens/custom-screen.tsx:210)** — `<ThemedText type="heading">{translate("title")}</ThemedText>` 를 검색 필드로 교체. 헤더는 `[닫기][검색바][설정]` 3분할이 되고, 검색바는 `flex: 1` + `maxWidth: 360` + `alignSelf: center` 로 가운데를 차지한다(가로 화면이라 제한 없으면 과하게 넓어진다).

**새 파일 `src/features/custom/components/augment-search-field.tsx`**
- `GlassSurface glassStyle="clear"` 컨테이너 — 좌우 `GlassButton`이 리퀴드글라스 원형이라 톤이 맞는다. `height: 40`(버튼 44와 나란히), `borderRadius: Radius.full`, `borderWidth: StyleSheet.hairlineWidth` + `colors.border.subtle`.
- 안쪽: `MaterialCommunityIcons name="magnify"` (18, `colors.text.tertiary`) → RN `TextInput` (`flex: 1`, `color: colors.text.primary`, `placeholderTextColor: colors.text.tertiary`) → 값이 있을 때만 `close-circle` 클리어 버튼.
- `autoCorrect={false}` / `autoCapitalize="none"` / `returnKeyType="search"` — 같은 화면의 [champion-change-overlay.tsx:94](src/features/custom/components/champion-change-overlay.tsx:94) 입력과 동일.
- i18n: 파일 상단 `t` 사전. ko `"증강 이름을 입력해주세요"` / en `"Search augments by name"`.

**RN `TextInput`을 쓰는 이유**: `@expo/ui` 우선 원칙의 예외다. 이 헤더는 네이티브 `Stack` 헤더가 아니라 `transform`으로 움직이는 `<Drawer>` 안의 커스텀 View이고(파일 상단 주석 참고), SwiftUI `TextField` Host를 그 안에 넣으면 포커스·키보드 앵커가 drawer 변환과 얽힌다. 같은 화면의 챔피언 변경 오버레이도 이미 RN `TextInput`이다.

**검색 상태** — [use-custom-draft.ts](src/features/custom/hooks/use-custom-draft.ts:38): `const [query, setQuery] = useState("")` 추가, `filtered` 체인에 이름 매칭 필터를 한 줄 더한다(티어 필터 다음, 정렬 앞). 반환 객체에 `query`/`setQuery` 노출.

**매칭 함수 재사용** — [hangul.ts:16](src/lib/hangul.ts:16)의 `matchChampionName`이 초성 검색까지 이미 한다. 챔피언 전용 로직이 아니므로 `matchName`으로 rename하고 증강에도 쓴다. 호출부는 두 곳뿐: [use-champion-select.ts:95](src/features/champions/hooks/use-champion-select.ts:95), [champion-change-overlay.tsx:60](src/features/custom/components/champion-change-overlay.tsx:60).

## 2. 증강 리스트 컨테이너 border

**[augment-pick-grid.tsx](src/features/custom/components/augment-pick-grid.tsx:226)** — `styles.grid`(FlatList 자신의 `style`)에 `borderWidth: StyleSheet.hairlineWidth` + `borderRadius: Radius.lg` + `borderCurve: "continuous"` + `overflow: "hidden"`, 색은 인라인 `colors.border.subtle`.

FlatList를 새 `View`로 감싸지 말 것 — `GestureDetector`가 `Gesture.Native()`로 잡는 대상이 바로 그 FlatList이고, 사이에 View가 끼면 셀의 `blocksExternalGesture(listGesture)` 참조가 어긋나 드래그 중 리스트가 같이 흐른다(파일 상단 주석의 함정).

우측 `SelectedPanel`의 박스가 이미 같은 조합(`borderWidth: 1`, `Radius.lg`, `borderCurve`)이라 좌우가 대칭으로 읽힌다.

## 6. 설정 드로어 재정비

전부 **[custom-settings-drawer.tsx](src/features/custom/components/custom-settings-drawer.tsx)** 한 파일.

**a) 세그먼트 이중 컨테이너 제거** — `pickerModifiers`의 `listRowBackground(rowBg)`가 세그먼트 뒤에 insetGrouped 카드를 한 겹 더 깐다. `listRowBackground("clear")` + `listRowInsets({ top: 0, leading: 0, bottom: 0, trailing: 0 })` 로 바꿔 세그먼트만 남긴다. `"clear"`가 SwiftUI 시스템 컬러로 안 먹으면 `"#00000000"` 로 대체(같은 파일이 이미 `"secondaryLabel"` 계열 문자열 색을 쓰고 있어 시스템 컬러 이름이 통한다).

**b) 섹션 타이틀 축소** — `<Section title={...}>` 대신 `header` slot을 쓴다(`SectionProps.header` 지원 확인함):
```
<Section header={<Text modifiers={[font({ textStyle: "caption2" }), foregroundStyle({ type: "color", color: "secondaryLabel" })]}>{translate("mode")}</Text>}>
```

**c) 하단 액션 → 네이티브 버튼 2개** — `SettingsRow` 두 개(chevron 포함)를 걷어내고 swift-ui `Button`으로:
- 챔피언 변경: `buttonStyle("bordered")`, `controlSize("large")`, `tint(colors.accent.default)`, `systemImage="person.crop.circle"`
- 선택 초기화: `buttonStyle("bordered")`, `role="destructive"`, `tint(colors.status.danger.default)`, `systemImage="trash"`
- 두 버튼 모두 `listRowBackground("clear")` + `listRowInsets` 0 으로 행 카드를 없앤다.

`SettingsRow` 자체는 mypage가 계속 쓰므로 손대지 않는다(이 드로어가 유일한 다른 사용처였다 — import만 빠진다).

**d) 상단 spacing** — `styles.host` 에 `paddingTop: Spacing.three`. SafeAreaView top inset 위에 얹혀 첫 섹션이 드로어 천장에 붙던 것을 띄운다.

**e) 스크롤 인디케이터 제거** — `List`의 modifiers 배열에 `scrollIndicators("hidden")` 추가.

## 7. 홈 모드 필터 → 네이티브 세그먼트 (철회)

한 번 갈아끼웠다가 되돌렸다. SwiftUI `segmented` Picker 의 선택 인디케이터는 시스템
회색 고정이라 `tint` 가 닿지 않고(UIKit appearance 로만 바뀌는데 expo-ui 가 노출하지
않는다), `palette` 로 내려가면 트랙 없는 캡슐 나열이 되어 원래 디자인과 달라진다.
민트 pill + 슬라이드가 이 화면의 의도라 [mode-switch.tsx](../../src/features/builds/components/mode-switch.tsx)
의 reanimated 구현을 그대로 유지한다. `build-list-screen` 의 progress/changeMode 로직도
손대지 않았다.

1. **커스텀 검색** — 한글 이름·초성(예: `ㄱㅂ`)·영문 모두 걸리는지, 티어 필터와 AND로 동작하는지, 클리어 버튼이 목록을 되돌리는지, 키보드가 올라와도 그리드 드래그가 되는지.

3. **드로어** — 세그먼트 뒤 이중 카드가 사라졌는지, 섹션 타이틀이 작아졌는지, 두 버튼이 버튼으로 보이고 각각 동작하는지, 상단 여백과 인디케이터 없음 확인.
4. `npm run lint` 통과 (타입체크·lint는 검증이 아니라 전제).

# 2차 — 드로어 재정비 · 여백 다이어트 (같은 날)

1차를 굴려보고 나온 후속 요청. 상세 관찰은
[검증 기록](../verification/2026-08-27-커스텀-UI-2차-정리.md) 참고.

## 드로어

- **증강 개수 섹션 삭제.** `PickLimit`·`PICK_LIMITS`·`limit`/`setLimit` 과 `add()` 의 개수 판정,
  `AddResult` 의 `"limit"` 까지 같이 걷어냈다(UI 가 없으면 항상 무제한이라 죽은 코드다).
- **챔피언 변경 · 선택 초기화 버튼 삭제** → 커스텀 화면 챔피언 행으로 이동.
- **퀵모드 행 카드 제거**(`listRowBackground("clear")`), 라벨은 `Toggle` children `Text` 에
  `font(footnote)` — `label` prop 은 글자 크기를 못 준다.
- **간격**: 섹션 `header` 슬롯을 버리고 "제목+컨트롤"을 한 행 안 `VStack(spacing: 8)` 으로 묶었다.
  헤더 슬롯을 쓰면 제목↔컨트롤(28pt)과 그룹 사이(33pt)가 사실상 같아 묶음이 안 읽힌다.
  세 그룹을 한 `Section` 에 넣어 그룹 사이는 행 인셋(26~34pt)만 남긴다.
- **글자**: 섹션 제목 `caption`(12pt), 행 본문 `footnote`(13pt) — 세그먼트 글자와 같은 크기.
- **상단 여백**: `Host` 에 `paddingTop: Spacing.four`.
- **`ignoreSafeArea="all"`**: 드로어가 화면 trailing 끝이라 Host 가 창 안전영역을 물고 들어와
  컨트롤이 오른쪽 60pt 를 못 썼다.

`List` 를 걷어내고 순수 `VStack` 으로 짜보다가 되돌렸다 — `VStack` 은 제안 폭을 자식에게
강제하지 않아 세그먼트가 제 글자 폭까지 쪼그라들고, `frame({maxWidth})` 도 `matchContents` 도
해결이 아니었다(전자는 상한일 뿐, 후자는 세로만 켜도 가로를 건드린다).

## 커스텀 화면

- **챔피언 행 끝 아이콘 버튼 2개** — `account-switch-outline`(변경) / `trash-can-outline`(초기화,
  danger 색). 28pt 원형, `accessibilityLabel` 로 i18n.
- **검색 필드**: 높이 40 → 32, 테두리 제거하고 `glassStyle="regular"` 의 림에 맡김,
  아이콘 18 → 15, 글자 14 → 13, `maxWidth` 360 → 300.
- **하단 잘림**: `SafeAreaView` edges 에서 `bottom` 제거 → 리스트가 화면 끝까지 흐르고,
  그리드·담은목록 contentContainer 가 `insets.bottom` 만큼만 띄운다.
- **좌우 여백 통일**: 우측 패널 `paddingHorizontal` 16 → 8(그리드 contentContainer 와 동일),
  헤더 좌우 24 → 12, 헤더 상하 12/8 → 8/4.
- **4열 카드는 철회.** 3열·원래 치수 유지(`rarity-card-frame.tsx` 는 손대지 않음).

## 3차 — 마감 4건

- 증강 그리드 컨테이너 `borderRadius` 제거(테두리만 남긴다).
- 담은 목록 박스 `marginBottom: Spacing.two + insets.bottom` — 좌우 여백과 같은 값에
  홈 인디케이터만 더한다. 안쪽 `listContent` 의 인디케이터 보정은 중복이라 제거.
- 드로어 섹션 제목 색을 시스템 `secondaryLabel` → 테마 `colors.text.secondary`.
- **드롭존 하이라이트**: `custom-screen` 의 `dragged` 를 `dropActive` 로 내려보내
  드래그 중 박스를 `accent.default` 테두리 + `accent.subtle` 배경으로 바꾼다.
  굵기는 1 고정 — 2로 키우면 강조될 때마다 안쪽 목록이 1pt 밀린다.

## 4차 — 챔피언 변경 오버레이

- **세로 중앙**: `sheet` 의 `flex: 1` 을 버리고 `height: "90%"` + `safe` 에 `justifyContent`/
  `alignItems: center`. `SafeAreaView` edges 는 `["left","right"]` 만 — `bottom` 을 먹으면
  홈 인디케이터 21pt 만큼 위로 쏠려 "화면 중앙"이 아니게 된다.
- **닫기 ✕**: accent → 기본(흰색), `header` 에 `marginBottom: Spacing.two` 로 검색 입력과 분리.
- **하단 패딩 제거**: `gridContent.paddingBottom` 과 시트의 `paddingBottom` 을 둘 다 없애고
  `overflow: "hidden"` 으로 모서리만 클립 — 리스트가 시트 끝까지 흐른다.
