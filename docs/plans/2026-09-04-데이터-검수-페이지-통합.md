# 데이터 검수 페이지 통합 + 아레나 증강 설명 압축

## Context

증강 카드는 `rarity-card-frame.tsx`에서 `numberOfLines={6}` · `fontSize 8` 고정이라 설명이 길면 말줄임표로 잘린다. 사용자가 증강이 정확히 뭔지 모른 채 고르게 된다. 아레나 증강 200개 중 **ko 16개 / en 29개**가 6줄을 넘긴다.

그런데 이걸 눈으로 확인할 도구가 흩어져 있다. 검수 페이지가 칼바람(`docs/augment-check.html`)과 아레나(`docs/arena-check.html`)로 갈라져 있고, 진입점(`docs/index.html`)은 개수가 stale(222/201 → 실제 282/200)이며, 아이템은 아예 검수 페이지가 없다. 생성기 3개가 같은 CSS 팔레트와 아이콘 URL 로직을 각자 복붙해 들고 있다.

그래서 (1) 검수 페이지를 하나로 합치고 아이템까지 덮은 뒤, (2) 그 페이지에 "설명 잘림" 배지를 붙여 대상을 상시 식별 가능하게 만들고, (3) 잡힌 항목의 설명을 실제로 줄인다.

## 1. 파일 구성 — 3 → 1

| 처리 | 대상 |
|---|---|
| 신규 | `scripts/gen-data-check.mjs` (`gen-augment-check.mjs`를 베이스로) |
| 삭제 | `scripts/gen-augment-check.mjs`, `scripts/gen-arena-check.mjs`, `scripts/gen-check-index.mjs` |
| 삭제 | `docs/augment-check.html`, `docs/arena-check.html` |
| 산출 | `docs/index.html` ← 유일한 검수 페이지 |
| `git mv` | `docs/augment-desc-trimmed.json` → `docs/desc-edited.json` |
| 유지 | `docs/augment-diff.json` (`apply-mayhem-patch.mjs` 산출물) |

페이지가 하나뿐이니 진입 카드가 존재할 이유가 없다. 산출물을 `index.html`로 잡으면 stale 개수 문제가 파일째 사라지고 `docs/`를 열면 바로 뜬다. 리다이렉트 스텁은 안 만든다 — 구 파일을 가리키는 건 `docs/plans/*`(과거 기록, 고칠 대상 아님)와 `SKILL.md`뿐이고 `.github` 워크플로 자체가 없다.

순 라인: 752줄(374+281+97) → 약 470줄.

## 2. 필터 UI — 데이터셋 단일선택 + 문맥에 따라 숨는 하위 행

```
[검색]                                        초기화   N / M개
데이터  ● 칼바람·클래식 증강 282  ○ 아레나 증강 200  ○ 특수 증강 25
        ○ 아이템 192  ○ 프리즘 아이템 23
모드    (증강)   ● 전체 ○ 칼바람 213 ○ 클래식 187 ○ 양쪽 공유 156 ○ 미출시 38
        (아이템) ● 전체 192 ○ 칼바람 111 ○ 클래식 81 ○ 아레나 111
        (그 외)  행 숨김
등급    (증강·아레나) ● 전체 ○ 실버 ○ 골드 ○ 프리즘 / (그 외) 행 숨김
표시    (증강)   아이콘 공유 · 신규 · 수치 미확인 · 설명 수정됨 · 설명 잘림
        (아레나) 아이콘 공유 · 설명 수정됨 · 설명 잘림 · 레벨업 불가
        (특수)   아이콘 공유 · 설명 수정됨 · 설명 잘림
        (아이템·프리즘) 행 숨김
```

- 평평한 9칩 안은 기각: `미출시`는 증강의 부분집합, `양쪽 공유 156`은 자리가 없고, `아레나 아이템`은 `칼바람 아이템`과 **같은 111개 집합**이다. 모드×종류 격자도 기각 — 특수/프리즘/미출시가 구멍을 만들어 "결과 없음"이 뜨는 조합이 생긴다.
- 맞지 않는 칩은 비활성이 아니라 `display:none`. 칩 전부를 DOM에 뿌리고 `data-for="aug item"` 속성으로 표시만 토글, 데이터셋 전환 시 `mode/rarity/flags` 리셋. JS 10줄.
- **칩 라벨의 개수는 생성 시점에 박는다** — stale index 사고 재발 방지.
- 초기화·카운트는 `표시` 행 끝 → `.controls`(검색 줄)로 이동. 그 행이 아이템에서 숨겨지기 때문.
- 섹션 분할: 증강/아레나는 rarity 그룹(현행 유지), 특수·프리즘은 단일, 아이템은 `전설`/`신발`(`tags.includes('Boots')` → 생성 시 `boots` 불리언).

## 3. 데이터 임베드 — 약 360KB (현재 3파일 합 336KB와 비슷)

| 배열 | 항목 | 크기 |
|---|---|---|
| `AUG` | 282 | ~110KB |
| `ARENA` | 200 | ~78KB |
| `ITEMS` | 192 | ~83KB |
| `NUMBER_DIFFS` | 99 | 59KB |
| `SPECIAL` / `PRISM` | 25 / 23 | 12KB |

세 가지 절감:
1. **아레나 아이템 중복 임베드 없음.** `EXCLUDED_BOOT_IDS`(`1001,3168,3170,3171,3173,3174,3175`)는 칼바람 풀에 하나도 없어 아레나 아이템 = 칼바람 아이템 = 같은 111개다. `ITEMS` 배열 하나에 `modes: ['aram','arena'] | ['classic']` 플래그만 붙이고 아레나 칩은 그걸로 거른다. 제외 목록은 생성기에 그대로 적용해 둬 나중에 라이엇이 갈라놓으면 개수가 갈라져 눈에 띈다.
2. **진열 풀 192개만**(`aram-item-ids.json` 111 + `classic-item-ids.json` 81). 나머지 212개는 저장 빌드 역참조용이라 카드로 뜨지 않는다 — 검수 대상이 아니다. 154KB → 83KB.
3. **`cleanItemDesc` 평문화**(`gen-arena-check.mjs:22`에서 포팅). ko 설명 65.5KB → 23.7KB. 임베드 필드는 `id, ko, en, gold, boots, imageKey, descKo, descEn, modes`만 (`plaintext`·`stats`·`tags` 제외).

한 번에 DOM에 올라가는 카드 최대치는 282장(현행과 동일) — 가상화 불필요.

**`embed()`를 전 배열에 적용.** 현재 `gen-arena-check.mjs`는 맨 `JSON.stringify`라 설명에 `</script>`가 섞이면 페이지가 통째로 빈다. `gen-augment-check.mjs:73`의 `embed()`(`<` → `<`)로 통일.

아이콘 URL 3종을 한 곳에: 증강 3단 폴백(large→base→small), `cdragonItemIconUrl`(프리즘·특수), **일반 아이템용 ddragon**(`https://ddragon.leagueoflegends.com/cdn/${ver}/img/item/${imageKey}`, `ver`는 `src/lib/version.json`의 `ddragonVersion`을 읽어 상수로 인라인) — 세 번째는 신규분.

## 4. 줄수 추정 + 잘림 배지

`scripts/gen-data-check.mjs` 안 Node 측 함수. 브라우저 JS에는 넣지 않고 **생성 시점에 `lnKo`/`lnEn` 숫자로 임베드**한다(507행 × 20B ≈ 10KB).

```js
const CARD_DESC_WIDTH = 109;  // iPhone 15 landscape: cardWidth 141 - framePad 8*2 - content 4*2 - desc 4*2
const CARD_DESC_LINES = 6;    // rarity-card-frame.tsx numberOfLines={6}
function estimateCardLines(text)  // cleanAugmentDescription 적용된 문자열 → 줄 수
```

- 어절 단위 탐욕 줄바꿈(공백에서만 개행, 어절이 폭을 넘으면 강제 분할). 글자 폭: 한글·CJK 8, 대문자 5.4, 소문자 4.3, 숫자 4.5, 공백 2.2, 그 외 2.6.
- `// ponytail: 폰트 메트릭 근사. 어긋나면 여기 숫자만 조정` 주석으로 캘리브레이션 손잡이를 남긴다.
- 배지는 로케일별로 따로: `잘림 ko 7줄` / `잘림 en 8줄`. 한쪽만 넘치는 게 대부분(en 29 vs ko 16)이라 합치면 어느 쪽인지 모른다. 신규 클래스 `.xb`.
- 표시 토글 `설명 잘림` = `lnKo > 6 || lnEn > 6`. 헤더 스탯에 `설명 잘림 ko 22 · en 30`.
- 적용 대상은 `RarityCardFrame`을 타는 3종(칼바람·클래식 증강, 아레나 증강, 특수 증강 — `arena-reforge-card.tsx:45`가 `rarity: "gold"`를 붙여 같은 프레임으로 렌더). 아이템은 이 프레임을 안 쓰므로 제외.

**`check-augment-data.mjs`의 `LIMIT = 130`은 건드리지 않는다.** 지금 통과 중인데 정확한 추정기로 바꾸면 즉시 빨간불이 뜬다(ko 6건 — 전부 classic 전용이거나 미출시). 요구사항은 "페이지에서 식별"이지 "검사 실패"가 아니다. 설명을 실제로 줄인 뒤가 교체 시점 — 생성기에 그 취지의 `ponytail:` 주석을 남긴다.

## 5. "설명 수정됨" 라벨

`docs/desc-edited.json`, 데이터셋 키로 네임스페이스한 평면 id 배열:

```json
{ "aram": ["... 기존 74개 그대로 ..."], "arena": [], "special": [] }
```

아레나 200개 중 99개가 칼바람과 id가 겹치므로 단일 배열은 불가능하다. 파일을 하나 더 만드는 대신 키를 얹는다 — 로더는 `new Set(edited[key] ?? [])` 한 줄. 사유 필드(`{id, why}`)는 넣지 않는다: 기존 74건에 전부 손으로 써야 하고 사유는 이미 git 히스토리와 `docs/verification/`에 있다. 필요해지면 원소를 객체로 승격하고 `typeof x === 'string' ? x : x.id`로 정규화 — 한 줄. 라벨은 기존 `설명 축약` → **`설명 수정됨`**으로 통일, 클래스 `.tb` 재사용.

## 6. 아레나 설명 압축 (ko 16 + en 29)

사용자 결정: **ko·en 둘 다**, **제가 초안 제시 → 검토**.

1. 잘리는 항목의 현재 ko/en 원문과 **줄인 초안**을 한 표로 제시한다. 수치는 절대 건드리지 않고 서술만 압축 — 문장 결합, 중복 수식어 제거, 명시적 `\n` 정리.
2. 사용자가 고칠 것만 지정 → 교체.
3. 확정분을 `src/features/arena/data/augments.{ko,en}.json`에 반영하고 id를 `desc-edited.json`의 `arena` 배열에 추가.
4. 재생성 후 페이지에서 잘림 0건 확인.

## 7. 작업 순서

1. **`scripts/gen-data-check.mjs` 골격** — 5개 데이터셋 로더·병합·`embed()` 통일·아이콘 URL 3종. 확인: `node scripts/gen-data-check.mjs` → 브라우저로 열어 칩별 282/200/25/192/23, `no img` 0, 콘솔 에러 0.
2. **문맥 필터 행** — `data-for` 표시 토글, 전환 시 상태 리셋, 초기화·카운트 이동. 확인: 아이템 칩에서 등급·표시 행이 사라지는지, 아레나 아이템 111 = 칼바람 아이템 111인지, 검색어 없이 "결과 없음"이 뜨는 조합이 없는지.
3. **`estimateCardLines` + 잘림 배지** — 확인: 헤더 `설명 잘림 ko 22 · en 30`, 아레나 + `설명 잘림` 토글 → 45건, `불멸의 경계`(ko 9줄)·`Undying Guard`(en 11줄)가 맨 위.
4. **`docs/desc-edited.json`** — `git mv` 후 키로 감싼다. 확인: 칼바람 + `설명 수정됨` → 74건.
5. **구 파일 삭제** — 확인: `grep -rn "gen-augment-check\|gen-arena-check\|gen-check-index\|arena-check.html\|augment-check.html\|augment-desc-trimmed" . --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=plans --exclude-dir=verification` → SKILL.md와 `console.log` 문자열만.
6. **문서·문자열 갱신** — `.agents/skills/augment-check/SKILL.md`(frontmatter 경로, 13·20·51행, "설명 길이" 절에 6줄 추정 문단 + 아레나·아이템도 덮는다는 한 줄), `scripts/tag-augment-modes.mjs:201`, `scripts/apply-mayhem-patch.mjs:401`. 스킬 디렉터리명은 그대로 — 트리거 조건이 동일하고 바꾸면 `CLAUDE.md:11`까지 끌려온다.
7. **회귀 확인** — `node scripts/check-augment-data.mjs` 전부 ✓, `npm run lint`.
8. **설명 압축** (6절) — 초안 제시 → 확정 → 반영 → 재생성.
9. **플랜 문서 저장** — 이 문서를 `docs/plans/2026-09-04-데이터-검수-페이지-통합.md`로 저장 (CLAUDE.md 규칙).

## 검증

앱 런타임 코드는 **1~7단계에서 하나도 바뀌지 않는다**(검수 페이지는 개발용 정적 HTML). 시뮬레이터 검증이 필요한 건 8단계뿐:

- 아레나 드래프트를 굴려 압축 전 `불멸의 경계`가 실제로 잘리는지, 압축 후 6줄 안에 들어오는지 육안 확인. 로케일을 en으로 바꿔 `Undying Guard`도 같이 본다.
- 표본으로 7줄 경계선 항목(`지옥의 전도체` 78자) 하나를 봐서 추정 함수의 오차 방향을 잡는다 — 안 잘리면 `CARD_DESC_WIDTH`를 올린다.
- 결과를 `docs/verification/2026-09-04-아레나-증강-설명-압축.md`에 기록.
