# 26.23 — 신규 헤드라이너 4종 · 증강(신규/재출시/삭제) · 티어리스트 · 업데이트 후 아이콘 깜빡임

## Context

26.23(2026-11-18 KST) 패치로 아수라장에 헤드라이너 4종과 탱커 증강 4개가 들어왔고, 증강 3개의 수치가 바뀌었다.
사용자는 게임에서 사라졌던 "이빨 요정"이 다시 나오는 것을 봤다. 패치 노트에는 이 내용이 없다.
같이 해결할 문제가 하나 더 있다. 앱을 업데이트한 기존 사용자가 칼바람 드래프트를 하면 증강 아이콘이 깜빡인다.

## 조사 결과

### 증강: CDragon 16.22 → 16.23 `augment-lists.json` KIWI 풀

- **신규 4** (풀 242 → 243). 아이콘은 4개 모두 `_large` 가 HTTP 200 이다.
  - 요새화 Fortified (실버): 추가 방어력 25% 증가, 방어력 +20
  - 신비한 방호 Mystic Guard (실버): 추가 마법 저항력 25% 증가, 마법 저항력 +20
  - 점액 천지 Slime Time (실버): 6초마다 자동 시전, 40~80(+대상 최대 체력의 3~8%) 마법 피해. 챔피언에 맞으면 방울이 생기고, 밟으면 최대 체력의 6~15%를 회복한다. **아이콘은 CDragon 원본 경로가 `Cherry` 폴더다** (Kiwi 폴더는 세 변형 모두 404) → skill 의 "Kiwi 폴더만" 규칙에서 예외로 둔다
  - 더욱 굳건한 태세 Steadfaster Presence (골드): 강인함 20%, 추가 방어력·마법 저항력 16% 증가. 체력 40% 미만이면 두 배
- **풀에서 빠짐 3**: 상어 폭풍, 방출 역장, 격려하기 → `modes: []`
- **재출시**: Mayhem:Meta 분석(11-05)에 따르면 26.21 출시일(10-21)부터 12종이 서버에서 꺼졌다. 장인의 솜씨, 이빨 요정, 끝없는 학살, 눈 폭발, 상어 폭풍, 자연의 회복, 격려하기, 상어 미끼, 열의, 방출 역장, 말랑 찰싹 손, 영혼 폭탄이다. 핫픽스였고 패치 노트에는 없었다.
  - CDragon 풀에는 계속 남아 있어서 **앱은 12종 모두 줄곧 칼바람에 켜 둔 상태였다.** 따라서 데이터에 따로 "추가"할 것이 없다.
  - 26.23 에서 이 중 3종이 정식으로 삭제됐다. 나머지 9종(이빨 요정 포함)이 돌아왔다고 본다. 이빨 요정은 사용자가 게임에서 확인했다.
  - 9종은 앱 아이콘이 모두 `_large` 200 이다. 대신 티어리스트에는 없다. 집계 소스에 26.21 이후 표본이 없기 때문이다.
- **수치 변경 3**:
  - 붐 앤 베이스: 50~200 → 50~175
  - 튕기는 꿀벌: 피해량 50~100% → 60%
  - 구원: 재사용 90초 → 70초

### 티어리스트

- 앱 데이터는 26.21 이다.
- 소스 aram.gg(dtodo)의 최신은 `16.22.3`(집계일 11-15)이고, 16.23 은 404 다. 중국 서버라 패치가 늦게 들어온다.
- 지금 돌리면 26.22 로 오른다. 신규 4종과 재출시 9종은 소스가 26.23 을 낼 때까지 통계가 없다.

### 깜빡임 — 원인 2개 (`src/lib/image-prewarm.ts`, `src/hooks/use-image-prewarm.ts`)

1. 완료 플래그 키가 `prewarm:done:${ddragonVersion}`(16.16.1 고정)이다. 앱 업데이트로 증강이 추가돼도 키가 그대로라, 기존 사용자는 신규 아이콘을 미리 받지 않는다. 그 결과 카드가 flip 된 뒤 아이콘이 네트워크에서 늦게 뜬다.
2. expo-image 는 SDWebImage 를 쓰는데, 디스크 캐시 기본 `maxDiskAge` 가 1주이고 수정일 기준이다. 앱이 백그라운드로 갈 때 만료 파일을 지운다.
   - 그래서 설치 때 한 번 받는 설계는 1주 뒤에 무너진다. 업데이트하는 사용자는 대개 1주가 지난 상태라 전부 깜빡인다.
   - `maxDiskAge` 는 JS 에서 바꿀 수 없다. 노출되는 건 `Image.configureCache` 의 size·count 뿐이다. 앱이 CNG 라 네이티브를 고치려면 config plugin 이 필요하다.
   - `_large` 404 폴백은 원인이 아니다. 칼바람 237개 모두 `_large` 가 200 이다.

  - 마에스트로 설명은 "매 라운드 증강 4개 중 하나를 고릅니다." / "Choose from 4 Augments every round."
- `assets/headliners/{arcade,debonair,la-ilusion,maestro}.png`

  - `features/headliners/assets.ts` 에 등록한다. 흰 실루엣이면 `headliner-logo.tsx` 의 `WHITE_LOGOS` 에 넣어 라이트 모드 헤더에서 글자색으로 칠한다. 실물을 보고 판단한다.
- `constants/theme.ts` `HeadlinerColors` 에 4색을 추가한다. 로고에서 뽑은 대표색을 쓰고, 옅으면 무대에서 회색으로 탁해지므로 채도를 유지한다.
- 마에스트로 4장. 카드 수는 지금 3에 고정돼 있어 아래 네 곳을 `cardsFor(progress.id)` 로 바꾼다.
  - `features/aram/hooks/use-aram.ts`: `pickWeighted(..., 3)` 두 곳, `rerolled` 초기값과 라운드 리셋, 비 HEARTSTEEL `rollSlotStickers` 의 `[null×3]`
  - `components/ui/rarity-card-frame.tsx` `cardWidthFor(..., count)`: `gap*2 /3` → `gap*(count-1) /count`. 호출부는 aram 하나다. 가로 기기 대부분은 높이가 폭을 정하므로 카드 크기는 그대로다
  - `hooks/use-card-pick-anim.ts` `useCardPickAnim(count)`: `NO_EXIT`/`ALL_FLIP` 배열을 count 길이로 만든다
  - `features/aram/screens/aram-screen.tsx`: 위 둘에 count 를 넘긴다. 파일 머리의 "카드 3장" 주석도 고친다
- `scripts/check-headliners.ts`: `cardsFor` 를 검사하고, 13종 분포와 ko/en 키 일치를 확인한다(기존 루프가 `HEADLINER_IDS` 를 따른다).

### 2. 증강 (augment-check skill 절차)
1. `node scripts/apply-mayhem-patch.mjs --write` 로 신규 4개와 `docs/augment-diff.json` 을 만든다.
2. `node scripts/tag-augment-modes.mjs --write` 로 삭제된 3개를 `modes: []` 로 바꾸고 `augmentNameId` 를 확정한다.
3. 신규 4개의 ko/en 설명을 손으로 쓴다. 문장은 16.23 신규 해시 키의 공식 ko·en 문구로, 수치는 위키로 채운다. 6줄·130자 안에 맞춘다.
   - 4개 id 를 `docs/desc-edited.json` 에 추가한다.
4. 수치 변경 3건을 ko/en 에 반영한다.
5. `apply-mayhem-patch` 의 `numberDiffs` 에서 재출시 9종만 따로 본다. 패치로 바뀐 게 분명한 것만 고친다(일괄 반영 금지 원칙).
6. 아이콘 4개(`_large`)를 받아 눈으로 확인한다. 위키 `<이름>_mayhem_augment.png` 와 같은 그림인지 본다.
7. `check-augment-data.mjs` 의 `EXPECTED` 를 `{ total: 323, aram: 234, unreleased: 89 }` 로 갱신한다.
   - skill 문서의 개수 줄도 "26.23 풀 243 → 앱 234"로 고친다.
8. `tidy --write` → `check` → `tidy --selftest` → `gen-data-check`(`docs/index.html`) 순서로 돌린다.
- `LOCAL_AUGMENT_ICONS` 10개도 이제 CDragon `_large` 가 있다. skill 규칙상 지울 대상이지만 이번에는 둔다. 지우면 그 10개가 네트워크로 넘어가 이번에 고치는 깜빡임 표면이 넓어진다. 보고서에 적는다.

### 3. 티어리스트
- 증강 데이터를 바꾼 **다음에** `npm run data:tierlist` 를 돌린다(증강 풀로 조인하므로). 이어서 `npx tsx scripts/check-tierlist.ts`.
- 실행 시점에 소스가 16.23 을 내면 26.23 이 되고, 아니면 26.22 가 된다.

### 4. 깜빡임
- `src/lib/image-prewarm.ts`: `topUpPrewarm(urls: string[][])` 를 추가한다.
  - 체인의 어느 주소도 디스크에 없을 때만(`Image.getCachePathAsync(url)`) 남긴다.
  - 남은 것을 기존 `prefetchPool` 로 받는다. 진행 UI 는 없다.
  - `ponytail:` 주석을 단다: SDWebImage 1주 만료 때문에 매주 다시 받는다. 네이티브 `maxDiskAge` 를 켜면 없앨 수 있다.
- `src/hooks/use-image-prewarm.ts`
  - 완료 플래그가 있으면 설치 화면 없이 `topUpPrewarm(allUrls)` 를 백그라운드에서 돌린다.
  - `AppState` 가 `active` 로 돌아올 때도 같은 호출을 한다. 만료 파일 삭제가 백그라운드 진입 때 일어나기 때문이다.
  - `chains` 순서에서 증강을 맨 앞으로 옮긴다(드래프트가 첫 소비처).
- 첫 설치 흐름(진행률 설치 화면)과 플래그 키는 그대로 둔다.
- 드래프트 1라운드는 기존 카드별 `prefetchOne` 이 등장 연출(2.6초) 동안 받으므로 건드리지 않는다.

- **눈 폭발은 칼바람에서 뺐다** (`NOT_IN_ARAM` 에 `Snowbomb`).
