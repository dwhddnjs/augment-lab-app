# 1.6.1 출시 후 수정 4건


## Context

1.6.1을 스토어에 올리고 설치해 보니 네 가지 문제가 나왔다.

1. 홈 시작 카드의 랜덤 타일과 탭바 `+ → 칼바람`이 같은 동작이다.
2. 아이템 저장 → 빌드 상세 전환이 세 번에 한 번꼴로 세로 → 가로 → 세로로 흔들린 뒤에야 카드가 그려진다. 회전 문제는 이미 여러 번 고쳤다(가장 최근은 ee90664).
3. 빌드를 2개 만든 사용자에게 앱스토어 리뷰 다이얼로그를 띄우고 싶다.
4. 커스텀 진입 때 화면 위쪽에 빈 공간이 있다가 사라지면서 화면이 위아래로 움직인다.

2번은 "가끔"만 나므로 이번에는 원인을 로그로 확정한 뒤에 고친다. 그래서 시뮬레이터 계측 단계를 넣었다. 이 플랜을 승인하면 이 작업에 한해 시뮬레이터 사용을 허락한 것으로 본다(memory: feedback-no-verify-command 예외 조항).

## 1. 홈 랜덤 타일 제거

**결정:** 시작 카드에서 랜덤 타일을 뺀다. `+ → 칼바람`을 랜덤 시작의 유일한 진입점으로 둔다.

- 근거 1: 카드 제목이 "헤드라이너 선택"이다. 랜덤은 헤드라이너를 고르는 동작이 아니라서 카드의 범주에 맞지 않는다.
- 근거 2: `+`는 모든 탭에서 보이는 "만들기" 진입점이고 커스텀도 품고 있다. 시작 카드는 "이 헤드라이너로 바로"라는 지름길 역할만 한다.
- 근거 3: 사용자 예상대로, 위에 랜덤이 있으면 `+ → 칼바람`은 쓰이지 않는다.

수정할 파일:

- `src/features/builds/components/start-card.tsx`
  - 랜덤 `Tile`, `t.random`·`t.randomName`, `MaterialCommunityIcons` import 를 지운다.
  - `STAGE_LIGHTS` 는 지금 "랜덤 민트 + 앞 셋"이다. 이를 `LINEUP.slice(0, 4)` 색으로 바꾼다(처음 보이는 네 타일).
  - `onStart: (headliner: HeadlinerId) => void` 로 필수화한다. 파일 상단 주석을 갱신한다.
- `src/features/builds/screens/home-screen.tsx`
  - `startAram(headliner: HeadlinerId)` 로 바꾸고 상단 주석의 "랜덤 시작"을 지운다.

탭바 `+` 메뉴(`mode-select-overlay.tsx`)는 손대지 않는다.

## 2. 저장 → 빌드 상세 회전 흔들림 (핵심)

### 지금 흐름 (코드로 확인)

`handleSave` → `saveBuild` → `useCloseDraft.openBuild` 순서로 진행된다(`src/hooks/use-close-draft.ts`).

1. 시트(`select-champion-modal`)에 `close=cut` 을 `setParams` 로 건다. 2 rAF 기다린 뒤 루트를 `[(tabs), build/[id]?saved=1]` 로 `reset` 한다.
2. RNS(`RNSScreenStack.updateContainer`)는 push 를 먼저 처리하고 그다음 모달을 처리한다.
   - push: 루트 뷰가 창에서 떨어져 있으면 건너뛰었다가 `didMoveToWindow` 때 한다.
   - 모달: 시트의 `stackAnimation` 으로 닫힘 애니메이션 여부를 정해 `[시트, aram, aram-items]` 를 한 번에 닫는다.
3. 그 뒤 방향을 정하는 쪽이 여럿이다.
   - UIKit 이 닫힘 뒤 루트 마스크를 묻는다. expo 의 `ScreenOrientationViewController` 는 RNS 화면 중 방향이 설정된 것이 있으면 RNS 에 묻고, 없으면 `PORTRAIT_UP` 잠금을 쓴다.
   - RNS `enforceDesiredDeviceOrientation` 이 화면 등장, 전환 끝, 모달 처리 끝마다 `dispatch_async` 로 다시 돈다. 이 함수는 **기기 물리 방향**을 기준으로 회전을 요청한다.
   - 홈 스택은 `Dimensions` 가 세로로 바뀌는 순간 `key` 를 바꿔 통째로 다시 만든다(`src/app/(tabs)/(home)/_layout.tsx`).
   - 빌드 상세의 `transitionEnd` 가 `setOptions` 를 부른다.

|---|---|---|---|
| A | 2 rAF 대기가 모자라 시트의 `none` 이 네이티브에 반영되기 전에 reset 이 들어간다. 그러면 애니메이션 닫힘(페이드)이 되고, 가로로 배치된 루트가 보인 뒤에 돈다. | 저장 직후 `emit()` 으로 홈 목록이 다시 그려지며 JS 가 바쁠 때만 진다 | 시뮬레이터는 Mac CPU 라 빠르다 |
| B | 회전 도중, RNS `enforce` 가 가로가 섞인 과도 마스크를 읽고 **기기 방향(가로)** 으로 회전을 다시 요청한다. 세로→가로→세로 세 번 회전과 정확히 맞는다. | `dispatch_async` 실행 시점과 모달이 실제로 빠지는 시점의 순서에 달렸다 | 실기기는 손에 가로로 들려 있다. 시뮬레이터는 기본이 세로 기기 방향이다 |

### 2-1. 원인 확정 (시뮬레이터 계측, 임시 코드 — 커밋하지 않음)

- 네이티브 임시 로그는 node_modules 에 직접 넣고 `/prebuild` 절차로 다시 빌드한다. 끝나면 패키지를 재설치해 되돌린다. 로그에는 모두 `[ORI]` 접두사를 붙인다.
  - `RNSScreenWindowTraits.enforceDesiredDeviceOrientation`: 마스크, 기기 방향, 화면 방향, 요청 방향, 호출 직전 스택.
  - `ScreenOrientationViewController`: `viewWillTransition` 의 목표 크기와 시각. `supportedInterfaceOrientations` 반환값이 바뀔 때마다.
  - `RNSScreenStack`: 모달 닫힘의 `animated` 값. push 를 건너뛰었는지 / 실행했는지.
- JS 임시 로그: `useCloseDraft`(setParams·reset 시각), 루트 `Dimensions` 변화, 홈 재생성, 빌드 상세 `transitionEnd`.
- 수집: `xcrun simctl spawn <UDID> log stream --predicate 'eventMessage CONTAINS "[ORI]"'` 와 Metro 로그. 화면은 `recordVideo` 로 찍고 밝기·타이밍을 본다(memory: reference-transition-capture).
- 매트릭스: 기기 방향 세로 / 가로(Device ▸ Rotate) × 칼바람 → 아이템 → 저장 15회씩, 커스텀 저장 5회.
  - 시뮬레이터 조작은 `orca emulator` 로 하고, 가로 화면에서는 `tap (1-y) x` 로 변환한다(memory: feedback-orca-emulator-control).
- 판별:
  - `viewWillTransition` 이 L→P→L→P 로 찍힌 회차에서 가로를 요청한 주체를 찾는다.
  - `[ORI] enforce … request=landscape` 가 찍혔으면 B 다.
  - 그 회차의 닫힘이 `animated=YES` 면 A 다.
  - 홈 재생성 직후에 찍히면 C 다.

### 2-2. 수정

**확정 여부와 무관하게 넣는 것 (A 제거):** 시트 닫힘 방식을 저장 순간에 정하지 않고 드래프트를 띄울 때 정해 둔다. 저장 경로에서 경합 자체를 없앤다.

- `src/features/champions/hooks/use-champion-select.ts` `handleStart`
  - push 직전에 `router.setParams({ close: "cut" })` 를 건다.
  - 시트는 같은 커밋에서 props 만 바뀌고 사라지지 않으므로 반영이 보장된다. 시트 위에 드래프트가 뜬 동안에는 시트 애니메이션이 쓰이지 않는다.
- `src/hooks/use-close-draft.ts`
  - `openBuild`: setParams 와 `nextFrames` 를 지우고 바로 `resetTo(id)` 한다.
  - `exit`: `close: "fade"` 로 되돌리고 `nextFrames` 뒤 reset 한다. 여기서 경합이 지면 페이드 대신 컷이 되어 빈 화면이 0.35초 보인다. 기능에는 영향이 없다.
  - 상단 주석을 새 흐름으로 고친다.
- `src/app/_layout.tsx`: 시트 옵션 주석을 갱신한다. 판정식(`close === 'cut'`)은 그대로 둔다.

**계측 결과에 따라 넣는 것:**

- B로 확정되면: 회전이 끝나기 전에 방향을 다시 묻는 계기를 없앤다.
  - 빌드 상세를 reset 과 함께 깔지 않는다. 드래프트 묶음만 컷으로 닫고 `[(tabs)]` 로 돌린 뒤, 루트 창이 세로가 된 것(`Dimensions` 세로)을 확인하고 나서 빌드 상세를 `animation: none` 으로 push 한다.
  - 회전 중 push·`didShowViewController`·`viewWillAppear` 에서 오는 `enforce` 호출이 사라진다.
  - 그래도 남으면 RNS `enforceDesiredDeviceOrientation` 에 "모달 전환 중에는 건너뛰기" 가드를 `patch-package` 로 넣는다. 이 경우 `package.json` 에 `postinstall` 을 추가하고 패치 파일과 사유를 문서에 남긴다.
- C로 확정되면: 홈 재생성을 (tabs) 가 실제로 보일 때로 미룬다. 빌드 상세가 덮고 있으면 이미 있는 `stale` 플래그만 세운다. 홈 index 가 다시 포커스되고 전환이 끝나면 재생성한다.

## 4. 커스텀 진입 시 위아래 흔들림

**원인:** `CustomScreen` 은 가로 **크기**(onLayout)만 보고 본문을 그린다. 그런데 `InsetView` 가 쓰는 루트 안전 영역(`useSafeAreaInsets`)은 회전이 끝난 뒤에 늦게 바뀐다.

- 첫 프레임은 세로 inset(위 62, 좌우 0)이라 헤더가 62pt 내려와 있다.
- 가로 inset(위 0, 좌우 62)이 들어오면 헤더가 올라가고 본문이 옆으로 밀린다.
- 칼바람도 같은 현상이 있지만 등장 연출이 덮는다.

**수정:** 가로 게이트가 "가로 크기 + 가로 inset" 둘 다를 기다리게 한다. iPhone 은 가로에서 상태바가 숨으므로 위 inset 이 항상 0 이다.

- 새 파일 `src/hooks/use-landscape-ready.ts` 를 둔다.
  - `{ ready, size, onLayout }` 를 돌려준다. `size` 는 가로일 때만 담는다.
  - `size && insets.top === 0` 이 되면 `ready` 를 한 번 래치한다. 래치하는 이유는 기존 주석과 같다: 담아 둔 상태를 unmount 로 잃지 않기 위해서다.
- `custom-screen.tsx`·`item-select-screen.tsx` 에 같은 구조로 중복된 onLayout 게이트를 이 훅으로 바꾼다. 커스텀은 `size.w` 를 `screenW` 로 넘긴다.

## 실행 결과 (계획과 달라진 점)

- 2번의 실제 원인은 후보 A·B·C 중 어느 것도 아니었다. 흔들림과 빈 화면이 한 문제의 양면이었다.
  - 챔피언 시트(pageSheet)가 낀 묶음을 애니메이션 없이 닫으면 iOS 가 0.25초 기다리며 화면을 비운다.
  - 같은 순간 빌드 상세 push 전환(`'none'` 도 전환)이 진행 중이면 기다리지 않는다. 1.6.1 은 이 덕에 빈 화면이 없었다.
  - 대신 그 전환이 세로 회전보다 늦게 끝나면 iOS 가 가로로 되돌렸다가 다시 돌린다(흔들림).
  - 첫 수정(RNS 패치로 push 를 `animated:NO`)은 흔들림을 없앴지만 빈 화면 0.4초를 되살렸다. 사용자가 짚었고 걷어냈다.
  - 최종: push 는 그대로 두고, 저장으로 닫는 동안 가로를 붙잡았다가 빌드 상세 전환이 끝나면 세로로 푼다(`src/lib/orientation.ts`).
    같은 빌드 A/B 에서 붙잡기 없음은 부하 시 7/8 흔들림, 붙잡기 있음은 0/10 이었다. 빈 화면은 0 이다.
  - 나가기는 페이드로 닫는다(애니메이션 없이 닫으면 같은 빈 화면). 시트 값은 나가기 확인창이 떠 있는 동안만 fade 로 바꾼다(`useCloseDraft.confirmExit`).
  - A(시트 close 경합)도 실제로 재현돼 계획대로 고쳤다. B·C 는 실험으로 배제했다. 네이티브 패치·patch-package 는 남지 않았다.
