# 아레나 구조 정리

클래식·데이터관리 정리(`2026-08-25-클래식-데이터관리-구조정리.md`)에서 범위 밖으로 뒀던 아레나 feature를 이어서 정리한다.
목표는 동일: **UI와 동작은 그대로**, 이동·삭제·추출만 한다.

## 문제

- `use-arena.ts` 598줄에 규칙(라운드 순서·확률·가격)과 상태 전이가 섞여 있고, 끝에 28개 필드를 나열한 `useMemo` + 28줄 deps가 붙어 있었다(형제 훅 `use-aram.ts`는 평범한 객체를 반환한다. React Compiler가 켜져 있어 수동 메모는 프로젝트 규칙 위반이기도 하다).
- `arena-shop.tsx` 596줄 = 풀 계산 + 모루 오버레이 상태 + 셀 2종 렌더 + 카테고리 탭 + 레이아웃.
- 카드 선택/리롤 애니메이션(380ms/220ms, exit·entry 모드)이 **3곳**에 복붙(게임 화면·모루 오버레이·증강 강화 오버레이).
- 리롤 버튼 Pressable이 3개 카드 컴포넌트에 복붙. 카드 크기 계산식(9:14 역산)이 4곳.
- `sampleDistinct`가 칼바람·아레나에 각각, `id → 객체` 해석 패턴이 15곳.
- 골드 색 `#F2C766` 9곳 하드코딩(디자인 규칙 위반).
- 죽은 코드: `buyShard`(호출부 없음), `ShopOptionKind`, 프리즘 카드의 `price`/`affordable` prop과 정적 FadeIn 분기.

## 한 일

**신규 8개**
- `src/lib/arrays.ts` — `sampleDistinct` / `shuffle` / `pickRandom` / `resolveIds`
- `src/hooks/use-landscape-lock.ts` — 가로 잠금 + 화면 긴 변/짧은 변
- `src/features/arena/arena-rules.ts` — ARENA_STEPS·경제 수치·카드 추첨(순수 모듈, `aram/rarity-odds.ts` 선례를 따름)
- `src/features/arena/hooks/use-card-pick-anim.ts` — 선택/리롤 애니메이션 상태
- `arena-card-overlay.tsx` / `arena-reroll-button.tsx` / `arena-shop-cell.tsx` / `arena-shop-tabs.tsx`

**옮긴 것**
- 카드 비율·너비 계산(`CARD_ASPECT`, `CARD_ROW_PAD`, `cardWidthFor`) → `components/ui/rarity-card-frame.tsx`. 이미 14/9를 갖고 있던 공용 카드 프리미티브가 제자리다(칼바람·아레나 양쪽이 쓴다).
- 두 오버레이가 **자기 카드를 소유**하도록 정리 — 부모는 풀과 확정 처리만 넘긴다. `arena-shop`에서 70줄, `arena-screen`에서 35줄이 빠졌다.

**지운 것** — `buyShard`, `ShopOptionKind`, 프리즘 카드 가격/FadeIn 분기, `use-arena`의 `useMemo` 28필드 반환.
