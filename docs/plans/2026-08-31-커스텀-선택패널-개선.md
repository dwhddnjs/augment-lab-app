# 커스텀 모드 선택 패널 개선

- 날짜: 2026-08-31
- 대상: `src/features/custom/components/selected-panel.tsx`, `src/features/custom/screens/custom-screen.tsx`

## 배경

커스텀 모드를 실서버에 배포해 써 보니 우측 `SelectedPanel`의 피드백이 부족했다.

- 지금 담기는 칸이 어디인지 헤더 토글만 보고 알아야 했다(패널은 드래그 중에만 강조).
- 드래그 중 강조가 `backgroundColor: accent.subtle` 이라 담긴 행 위에 민트 톤이 덧씌워져
  목록이 읽히지 않았고, "여기 놓으라"는 지시도 없었다.
- 제거가 행 전체 탭이라 스크롤하다 오탭으로 지워졌다.
- 반대편 목록을 보려면 매번 헤더 토글까지 손을 옮겨야 했다.

## 변경

### 1. Props 정리

`dropTarget: PickTarget | null` → 셋으로 분리.

```ts
target: PickTarget;          // 현재 토글 상태 → 그 칸 테두리를 accent 로
dropping: boolean;           // 드래그 중 + 드롭 경계 안
onSwitchTarget: () => void;  // 반대편 칸을 탭했을 때 (draft.toggleTarget)
```

`dragged.kind` 는 항상 `draft.target` 과 같다(좌측 그리드가 `target` 으로 갈린다) —
종류를 다시 실어 보낼 필요가 없어 `dropping` boolean 하나로 줄었다.

### 2. 담기는 칸을 항상 테두리로 표시

`column(kind, count, body)` 안에서 `active = target === kind` 로 판정.
`borderColor: active ? colors.accent.default : colors.border.subtle`.
`borderWidth` 는 1 고정 유지 — 바꾸면 강조 때마다 안쪽 목록이 1pt 밀린다.

### 3. 드롭 지시는 오버레이 + 아이콘

`accent.subtle` 배경 제거. `active && dropping` 일 때만 `box` 안 마지막 자식으로
`StyleSheet.absoluteFill` + `pointerEvents="none"`, 배경 `colors.surface.overlay`,
중앙에 `MaterialCommunityIcons name="tray-arrow-down"` (28, `accent.default`).

### 4. 제거는 행 우측 마이너스 버튼

행 탭 = 제거를 없애고, 이름 뒤에 `minus-circle` (18, `status.danger.default`) 버튼 추가.
i18n `remove: "제거" / "Remove"`.

### 5. 칸을 탭하면 목록 전환

반대편 칸을 누르면 `onSwitchTarget()`(= `draft.toggleTarget`) + `Haptics.selectionAsync()`.
같은 종류 칸은 `onPress`가 `undefined`라 무반응.

**칸 전체를 Pressable 하나로 감싸면 안 된다** — 부모가 터치를 먼저 잡아 안쪽 FlatList 가
스크롤을 못 한다(검증 중 확인한 회귀). 그래서 라벨 머리 · 각 행 · 목록 아래 빈 자리
(`ListFooterComponent` + `contentContainerStyle.flexGrow: 1`)가 각자 같은 `onPress` 를 든다.

## 2차 수정 (같은 날, 실기 확인 후)

배포본을 다시 만져 보고 나온 요청 5건.

### 6. 제거 버튼을 모서리 배지로

행 우측 중앙의 `minus-circle` (18, `status.danger.default`) 은 목록을 훑을 때마다
빨간 점이 먼저 읽혀 과했다. 오른쪽 **위 모서리**로 올리고 `close-circle-outline`
(14, `colors.text.tertiary`) 로 낮췄다 — 지울 때만 눈에 들어오는 무게.

```ts
removeBadge: { position: "absolute", top: Spacing.half, right: Spacing.half }
```

`row` 의 `paddingRight` 가 배지 폭(`REMOVE_BADGE + Spacing.half`)을 비워 두므로
이름이 배지 아래로 흘러들지 않는다.

### 7. 이름은 한 줄 + 말줄임

`numberOfLines={2}` → `1`. 두 줄로 늘어나 행 높이가 들쭉날쭉하던 것도 같이 사라졌다.

### 8. 이름 폭 확보

칸이 5:5 라 여유가 없다. 아이콘–이름 `gap` 을 `Spacing.two`→`Spacing.one`,
배지 여백을 `Spacing.one`→`Spacing.half` 로 조여 이름에 6pt 를 더 줬다.
"맬모셔스의…" → "맬모셔스의 아귀" 처럼 대부분의 이름이 잘리지 않고 들어간다.

### 9. 빈 칸·목록 아래 빈 자리도 탭 타깃

두 군데가 탭을 못 받고 있었다.

- `styles.empty` 에 `flex: 1` — 빈 칸은 점선 슬롯 높이만 Pressable 이었다.
- `ListFooterComponentStyle: styles.listFiller` — **FlatList 가 footer 를 감싸는
  wrapper View 는 높이 auto 라 footer 의 `flex: 1` 이 0 으로 접힌다.** 목록이 일부만
  찬 칸의 아래 여백을 눌러도 전환되지 않던 원인.

### 10. 드롭 아이콘 교체

`tray-arrow-down` 은 말 그대로 다운로드/받은함으로 읽혔다.
→ `hand-pointing-down` (아래를 가리키는 손).

## 3차 수정 (같은 날)

### 11. 드롭 아이콘을 원형 화살표로

`hand-pointing-down` 은 28pt 에서 손 모양이 뭉툭했다 → `arrow-down-circle`
(민트 채움 원 + 아래 화살표). 오버레이 위에서 형태가 또렷하고 방향이 바로 읽힌다.

### 12. 커스텀 그리드에서만 카드 글로우 제거

`RarityCardFrame` 의 `boxShadow: rs.outerGlow` 는 카드를 한 장씩 크게 보여주는
칼바람·아레나에서는 재질을 살리지만, 3열로 촘촘히 붙는 커스텀 그리드에서는 서로 번져
카드 경계가 흐려진다.

```ts
noShadow?: boolean;   // RarityCardFrame
boxShadow: noShadow ? undefined : rs.outerGlow
```

`augment-pick-grid.tsx` 한 곳에서만 `noShadow` 를 넘긴다 —
`aram-card` · `arena-augment-card` · `arena-reforge-card` 는 그대로다.

## 4차 수정 (같은 날)

### 13. 드롭 아이콘을 선(outline)으로

`arrow-down-circle` 은 원이 통째로 민트로 채워져 오버레이 위에서 덩어리로 읽혔다
→ `arrow-down-circle-outline`.

### 14. 행 아이콘 배경이 라이트에서 밝은 회색이었다

`colors.surface.sunken` 은 다크 `#0A0B0D` / 라이트 `#E5E5EA` 다. 증강·아이템 아이콘은
**어두운 배경 자산**이라 라이트에서 회색 판 위에 아이콘이 뜬 것처럼 보였다.
→ 둘 다 `HeroOverlay.cardBase`(`#0A0B0D`, 테마를 타지 않는다). 빌드 상세의
`AugmentTile background` 와 같은 값이고, 다크에서는 `surface.sunken` 과 문자 그대로
같은 색이라 다크 화면은 바뀌지 않는다.

### 15. 나가기 — 홈 전환 뒤에 회전

`lockOrientation` → `dismissTo("/")` 순서였다. 회전이 먼저 걸려 **커스텀 화면이 떠 있는
채로** 기기가 돌아, 가로 레이아웃이 세로로 찌그러지는 게 그대로 보였다.
순서를 뒤집고, 회전을 dismiss 애니메이션 뒤로 미룬다.

```ts
router.dismissTo("/");
setTimeout(() => {
  void lockOrientation(ScreenOrientation.OrientationLock.PORTRAIT_UP);
}, EXIT_ROTATE_DELAY_MS);   // 420ms
```

`InteractionManager.runAfterInteractions` 는 쓸 수 없다 — 네이티브 스택
(react-native-screens)의 dismiss 는 InteractionManager 핸들을 만들지 않아 콜백이
곧바로 실행된다(시뮬레이터에서 확인: 여전히 커스텀 화면이 회전했다).

같은 exit 패턴이 `aram-screen` · `arena-screen` · `use-item-select` 에도 있다
(6차에서 함께 맞췄다).

## 5차 수정 (같은 날)

### 16. 라이트 모드 희귀도 색 톤 다운

라이트 짝(silver `#5A6068` / gold `#8A6410` / prismatic `#6D3FC4`)이 흰 배경 대비
6.3~6.7:1 이라 안전한 대신 먹빛으로 진해 "티어 색"으로 안 읽혔다.

먼저 **다크 팔레트로 통일**해 봤다가 되돌렸다 — 흰 배경에서 prismatic 이 1.38:1,
gold 가 1.92:1 이라 선택 패널의 증강 이름이 배경에 묻혔다(시뮬레이터에서 확인).

대신 라이트 짝을 다크 쪽으로 당겨 다시 잡았다. 4.6:1(본문 AA 하한)에서 한 번,
요청으로 한 번 더 낮춰 **3.5:1** 이 최종이다.

```ts
silver:    "#5A6068" → "#828A93"   // 6.35 → 3.50
gold:      "#8A6410" → "#AD821F"   // 5.37 → 3.51
prismatic: "#6D3FC4" → "#9877DA"   // 6.65 → 3.51
```

11pt 이름은 본문 텍스트 AA(4.5:1)를 밑돈다 — UI 요소 기준(3:1)만 남는다.
색을 더 살리려면 값을 더 내리지 말고, 이름을 `text.primary` 로 돌리고 티어 색은
보더·타일에만 남기는 쪽으로 갈 것.

## 6차 수정 (같은 날)

### 17. 나가기 회전 순서를 네 화면에 통일

15번을 칼바람·클래식(`aram-screen`) · 아레나(`arena-screen`) · 아이템 선택
(`use-item-select`)에도 적용했다. 같은 3줄을 네 번 쓰지 않으려고 `lib/orientation.ts`
에 헬퍼 하나를 둔다.

```ts
export function lockPortraitAfterExit(): void {
  setTimeout(() => {
    void lockOrientation(ScreenOrientation.OrientationLock.PORTRAIT_UP);
  }, EXIT_ROTATE_DELAY_MS);   // 420ms
}
```

각 화면의 나가기는 `router.dismissTo("/"); lockPortraitAfterExit();` 두 줄이 된다.
왜 먼저 걸면 안 되는지, 왜 `InteractionManager` 는 못 쓰는지는 헬퍼 주석에 한 번만 적었다.

세 화면은 `ScreenOrientation.lockAsync(...).catch(() => {})` 를 직접 부르고 있었는데
이 참에 `lockOrientation` 래퍼로 통일했다(Alert dismiss 중 호출이라 lockAsync 의
Promise 가 resolve 되지 않을 수 있는 그 구간이다). `aram-screen` 과 `custom-screen`
은 이걸로 `ScreenOrientation` import 자체가 필요 없어졌다.

### 18. 챔피언 선택 화면이 세로를 주장한다

클래식 시작 시 뜨는 라운드 질문 Alert 이 **가로로** 떴다(그리드는 세로인데 Alert 만
90° 누움). Alert 은 새 presentation 이라 그 순간 지원 방향을 다시 계산하는데,
가로 잠금이 남은 채로 이 화면에 들어오면 그 잠금을 읽어 가로로 그린다.

원인은 비대칭이었다 — 가로 화면 넷은 `useLandscapeLock` 으로 **포커스마다** 가로를
주장하는데, 세로 쪽은 "나가는 화면이 나가면서 한 번 돌려준다"가 전부라 도착 시점의
방향이 직전 상태에 달려 있었다.

`use-champion-select` 의 `useFocusEffect` 에서 `PORTRAIT_UP` 을 건다 —
`useLandscapeLock` 의 대칭이고, Alert 을 띄우기 전에 방향이 확정된다.
`handleStart` 의 `LANDSCAPE` 는 이 화면을 replace 로 떠나며 걸리므로 덮이지 않는다.
