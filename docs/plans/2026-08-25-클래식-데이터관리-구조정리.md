# 클래식·데이터관리 추가 후 구조 정리

## Context

클래식 모드(`cddafd1`)와 데이터 관리 UI(`5455160`, `2026-08-21`)가 얹히면서 코드가 몇 군데 어긋났다.

- **중복**: 같은 이름의 `cleanItemDescription()`이 두 파일(`items/text.ts`, `items/item-text.ts`)에 서로 다른 동작으로 존재한다. 모드 파라미터 파싱(`modeParam === "classic" ? ...`)이 화면 3곳에 복붙돼 있다. 탭 스택 3개가 같은 `screenOptions` 5줄을 각자 들고 있다.
- **죽은 코드**: 로컬 저장(`build-storage`)으로 갈아탄 뒤 남은 Supabase 원격 저장 코드 3파일, Expo 템플릿 잔재 UI 4파일, 실제 폴백이 아닌 `glass-chip.tsx` 1파일이 그대로 있다. `item-text.ts`의 export 3개는 아무도 안 쓴다.
- **비대한 화면 파일**: 세그먼트 스위치 애니메이션이 `build-list-screen.tsx`(527줄)에 통째로 들어 있고, 아이템 그리드 계산이 `item-select-screen.tsx`(358줄)에 섞여 있다. 같은 프로젝트에 이미 `use-champion-select.ts`라는 분리 패턴이 있는데 아이템 쪽만 안 따랐다.
- **위치 규칙 이탈**: `item-filters.ts`가 로케일 JSON 자리인 `data/`에 있다. `mypage` 화면 2개만 default export다(나머지 screens는 전부 named).

**목표는 앱스토어 심사 직전 코드 정리다. UI와 동작은 1픽셀도 바뀌면 안 된다.** 따라서 이 작업은 전부 *이동·삭제·개명*이고, 스타일 값과 JSX 구조는 복사해 옮기기만 한다. 계산식·애니메이션 타이밍·조건 분기는 손대지 않는다.

범위는 **클래식·데이터관리·공용**으로 한정한다. 아레나(`arena-shop.tsx` 596줄, `use-arena.ts` 598줄)는 이번 기능과 무관하므로 건드리지 않는다 — 단, 아이템 텍스트 유틸 통합 때문에 아레나 컴포넌트 2개의 **import 한 줄씩만** 바뀐다.

## 3. 중복 통합

### 3-1. 아이템 텍스트 유틸 두 파일 → 한 파일

지금 `cleanItemDescription`이라는 **같은 이름의 함수가 두 개**이고 동작이 다르다. 읽는 사람이 어느 쪽인지 import 경로로만 구분해야 한다.

`item-text.ts`를 없애고 [src/features/items/text.ts](src/features/items/text.ts) 하나로 합치며, 이름을 역할로 가른다 (**본문은 그대로 복사, 로직 무변경**):

| 새 이름 | 하는 일 | 출처 |
|---|---|---|
| `itemDescriptionText(raw)` | 태그만 걷어낸 전체 평문(스탯 줄 포함) | 기존 `item-text.ts::cleanItemDescription` |
| `cleanItemDescription(raw)` | 고유 효과만(`<stats>` 블록 제외) | 기존 `text.ts::cleanItemDescription` (이름 유지) |
| `prismaticStatSummary` / `prismaticEffectSummary` | 프리즘 아이템 스탯/효과 분리 | 그대로 이동, 내부에서 `itemDescriptionText` 호출 |

호출부 3곳:
- [src/features/builds/components/build-item-row.tsx:14](src/features/builds/components/build-item-row.tsx:14) — 경로·이름 그대로, 변경 없음
- `arena-item-pick-card.tsx:13` — `cleanItemDescription` → `itemDescriptionText` (동작 동일)
- `arena-prismatic-card.tsx:15` — import 경로만 `item-text` → `text`

### 3-2. 모드 파라미터 파싱 3중복 → `game-modes.ts`

[src/constants/game-modes.ts](src/constants/game-modes.ts)에 두 함수를 더한다. 이 파일 주석이 이미 "모드 메타의 단일 출처"라고 선언하고 있으므로 자연스러운 자리다.

```ts
export function parseGameMode(param: string | undefined): GameMode
/** 드래프트 화면(칼바람·클래식) 전용. */

```

## 4. 파일 분리 — 가독성

### 4-1. `build-list-screen.tsx` 527줄 → 약 270줄

세그먼트 스위치 UI가 화면 파일의 절반을 차지한다. 신규 [src/features/builds/components/mode-switch.tsx](src/features/builds/components/mode-switch.tsx)로 **그대로 오려낸다**:

- `useSegmentColor` 훅, `ModeLabel`, `ModeIcon`, `AnimatedIcon` (파일 내부용)
- `export ModeSegmentedControl` — 상단 글래스 트랙 + 슬라이딩 thumb + 라벨
- `export HeaderModeToggle` — 헤더 우측 원형 토글
- 관련 상수(`HEADER_CIRCLE`, `HEADER_SEG`)와 스타일 9개(`switchWrap`·`switchTrack`·`switchInner`·`thumb`·`switchSegment`·`switchLabel`·`headerToggle`·`headerSegment`·`headerCircle`)

화면에는 상태(`mode`/`lastMode`/`progress`/`selected`/`changeMode`/`switchHeight`/`showHeaderToggle`)와 `SectionList`만 남는다. `progress` SharedValue는 지금도 화면이 소유해 prop으로 내려주므로 **소유권 구조가 바뀌지 않는다** — 260ms 타이밍, thumb 퍼센트 너비, 색 보간 모두 값 그대로 이동.

### 4-2. `item-select-screen.tsx` 358줄 → 약 180줄

이미 있는 [use-champion-select.ts](src/features/champions/hooks/use-champion-select.ts) 패턴을 그대로 따라 신규 `src/features/items/hooks/use-item-select.ts`로 로직을 옮긴다:

- 파생값: `modeItems`, `champion`, `displayItems`, `paddedItems`, `rows`, `cellSize`, `selectedItems`, `itemStatsList`
- 상태: `activeFilter`, `selectedIds`, `saving`, `gridWidth`, `augmentGridWidth`
- 핸들러: `handleItemPress`, `saveAndOpenBuild`, `handleExit`
- 아이콘 prefetch `useFocusEffect` (`useCallback` 유지 — Expo Router 예외 규칙)
- 상수 `MAX_ITEMS`/`NUM_COLS`/`CELL_GAP` 이동, `MAX_ITEMS`는 헤더가 쓰므로 export

화면은 landscape 가드 + 헤더 + 좌7:우3 레이아웃만 남는다. `ItemSelectContent` 분리 구조와 `<SafeAreaView edges>` 설정은 그대로.
