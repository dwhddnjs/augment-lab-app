# 커스텀 모드 — 증강 자유 선택 화면

## Context

지금 칼바람·클래식·아레나는 전부 **3장 중 1픽** 드래프트다. 게임을 재현하는 데는 맞지만,
"내가 원하는 증강 조합을 짜본다"는 건 불가능하다. 뽑히는 대로만 담을 수 있다.

커스텀 모드는 그 제약을 걷어낸 샌드박스다. 전체 증강 풀을 펼쳐놓고 사용자가 직접 골라
담는다. 뽑기가 없으니 라운드도 리롤도 없고, 대신 **드래그 앤 드롭**으로 카드를 집어
"선택된 증강" 박스에 떨구는 조작이 화면의 중심이 된다.

**이번 턴 범위는 증강 선택 화면까지.** 출구는 X 버튼뿐이고 만든 조합은 저장되지 않는다.
아이템 선택·빌드 저장은 다음 턴에 기존 `/aram-items` 화면을 재사용해 붙인다
(§8에 이음매를 명시).

확정된 결정:
- 커스텀 버튼 아이콘 = MaterialCommunityIcons `tune-variant`
- 증강 화면과 아이템 화면은 **분리** (한 화면 통합 안 함)
- 저장 시 mode는 칼바람/클래식 — `GameMode`에 `custom`을 넣지 않는다

---

## 1. 진입점 — `GameMode`를 건드리지 않고 버튼만 늘린다

`GameMode`(`src/lib/build-storage.ts:18`)는 **저장 스키마 타입**이다. 여기에 `custom`을
넣으면 `mode-switch.tsx`가 `GAME_MODES`를 map하므로 홈 세그먼트가 자동으로 4칸이 되고,
헤더 토글이 `(34+8)×4 = 168pt`로 늘어 large title과 부딪힌다
(`docs/plans/2026-08-21-클래식-모드-추가.md:182-185`가 126pt에서 이미 경고한 구간).
게다가 커스텀 결과물은 칼바람/클래식으로 저장되므로 저장 타입에 `custom`이 있으면 안 된다.

대신 **"어느 화면으로 가는가"** 축을 하나 더 만든다 — `src/constants/game-modes.ts`에 추가:

```ts
/** `+` 오버레이가 띄우는 진입점. 저장 모드(GameMode)가 아니라 목적지 화면이다.
 *  커스텀은 결과를 칼바람/클래식으로 저장하므로 GameMode 에는 넣지 않는다. */
export type LaunchMode = GameMode | "custom";
export const LAUNCH_MODES: LaunchMode[] = [...GAME_MODES, "custom"];
export const LAUNCH_ICONS: Record<LaunchMode, keyof typeof MaterialCommunityIcons.glyphMap> = {
  ...MODE_ICONS,
  custom: "tune-variant",
};
export const LAUNCH_LABELS = {
  ko: { ...MODE_LABELS.ko, custom: "커스텀" },
  en: { ...MODE_LABELS.en, custom: "Custom" },
};
export function parseLaunchMode(param: string | undefined): LaunchMode {
  return LAUNCH_MODES.includes(param as LaunchMode) ? (param as LaunchMode) : "aram";
}
```

기존 `GAME_MODES`/`MODE_ICONS`/`MODE_LABELS`/`parseGameMode`는 **무수정**. 홈 세그먼트·빌드
배지는 계속 3모드만 본다.

`mode-select-overlay.tsx`는 import 3개와 `MODES` 한 줄을 `LAUNCH_*`로 치환. 배열이
`.reverse()`되므로 위→아래가 `커스텀 / 아레나 / 클래식 / 칼바람`이 되어 **기존 3개 위치가
그대로 유지되고 커스텀만 맨 위에 붙는다.**

**4번째 버튼이 `+`를 가리지 않는지 좌표 확인 (수정 불필요):**

| | iPhone 15/16 Pro (852) | iPhone SE (667) |
|---|---|---|
| paddingBottom (`insets.bottom+50+16`) | 100 | 66 |
| 스택 하단 y | 752 | 601 |
| 스택 높이 (4×60 + 3×16) | 288 | 288 |
| 스택 상단 y | 464 | 313 |
| `+` 탭 중심 y | ~793 | ~642 |

스택은 `justifyContent:"flex-end"`라 **위로만** 자란다. 하단이 `+`보다 41pt 위이므로 가릴
수 없고, SE에서도 상단 오버플로가 없다.

## 2. 목적지 분기 — 삼항을 Record로 (알려진 함정 제거)

`use-champion-select.ts:147`의 `mode === "arena" ? "/arena" : "/aram"`은
`game-modes.ts:32-34` 주석이 경고한 바로 그 패턴이다 — **새 모드가 조용히 `/aram`으로
흡수된다(클래식이 실제로 그랬다).** `parseGameMode`만 매핑으로 방어됐고 여기는 안 됐다.

```ts
const mode: LaunchMode = parseLaunchMode(params.mode);   // :85

// Record 라 모드를 추가하면 컴파일 에러로 잡힌다.
const GO: Record<LaunchMode, (championId: string, rounds: number) => void> = {
  aram:    (championId, rounds) => router.replace({ pathname: "/aram",  params: { championId, mode: "aram",    rounds: String(rounds) } }),
  classic: (championId, rounds) => router.replace({ pathname: "/aram",  params: { championId, mode: "classic", rounds: String(rounds) } }),
  arena:   (championId)         => router.replace({ pathname: "/arena", params: { championId } }),
  custom:  (championId)         => router.replace({ pathname: "/custom", params: { championId } }),
};
GO[mode](championId, rounds);
```

나머지는 무수정으로 통과한다 — `:100` `showBravery = mode === "arena"`(커스텀엔 용기 셀
없음, 의도), `:141` 간식 알럿(커스텀은 라운드 개념이 없어 4가 들어오고 `GO.custom`이
무시), `:144` `lockOrientation(LANDSCAPE)`(커스텀도 가로), `startingRef` 연타 가드.

## 3. 화면 레이아웃 — 6.5 : 4.5

`item-select-screen.tsx`의 **자체 `onLayout` 측정 래퍼 패턴**을 그대로 쓴다(모달 위에 떠서
window 치수가 늦게 따라온다). `useLandscapeLock()` + `if (!isLandscape) return <ThemedView/>`
가드도 동일.

iPhone 15/16 Pro 가로 852×393, landscape safe area left/right ≈ 59, bottom 21 기준:

```
content W = 852 − 59×2                       = 734
header  H = 12 + 44(GlassButton) + 8         = 64
body    H = 393 − 21 − 64                    = 308

leftW  = round(734 × 6.5/11)                 = 434     ← 6.5:4.5 는 합 11
rightW = 734 − 434                           = 300
티어 레일 44 (ItemFilterBar 의 SIDE_TAB_WIDTH 재사용)
grid W = 434 − 44                            = 390
cardW  = floor((390 − 8×2 − 8×2) / 3)        = 119     ← PAD=GAP=Spacing.two, COLS=3
cardH  = round(119 × CARD_ASPECT)            = 185     → 약 1.6행이 보인다
```

iPhone 16 Pro(874×402)에서는 cardW 123.

**열 수 = 3 확정.** 4열이면 cardW 87pt인데 `RarityCardFrame`의 `iconSize=72`가 카드 폭의
83%를 먹어 아이콘 덩어리가 된다. 3열의 119~123pt는 현재 aram 화면 카드 폭(141pt)에 가까워
**`RarityCardFrame`을 손대지 않고 그대로 쓸 수 있다.**

`cardWidthFor()`는 **재사용하지 않는다** — 화면 전체 폭을 3등분하는 함수라 434pt 패널에
안 맞고, `screenH × heightRatio` 상한은 스크롤 그리드 전제가 아니다. `CARD_ASPECT`와
`RarityCardFrame`만 재사용하고 폭은 그리드 안에서 한 줄로 계산한다.

flex 대신 **계산된 폭을 명시**(`width: leftW` / `width: rightW`)한다 — 드롭 판정 경계와
실제 레이아웃이 같은 숫자에서 나와야 한다.

**티어 필터는 좌측 세로 레일(44pt).** 요구사항 "카드 리스트 옆"을 문자 그대로 만족하고
세로 공간을 0 먹는다. `item-filter-bar.tsx`의 아이콘 + 활성 점 패턴을 그대로 따른다.
색은 `AugmentRarityColors[rarity].border`, 전체 칩만 `colors.text.tertiary`.

> 알려진 한계: cardW 119에서 `RarityCardFrame` 설명(8px × 6줄)이 3~4줄로 잘린다.
> **현재 aram 화면(141pt)에서도 이미 잘리고 있다.** 시뮬레이터에서 보고 못 봐주겠으면
> 그때 `iconSize?: number = 72` prop 한 줄을 추가한다. 미리 넣지 않는다.

## 4. 드래그 앤 드롭 — 라이브러리 추가 없이

`draggable-flatlist`류는 "리스트 내부 재정렬"이 본체라 우리 케이스(리스트 → 다른 패널로
반출)에 안 맞는다. 필요한 건 Pan 하나와 절대배치 고스트 하나뿐이다.

**스크롤 충돌 해소** — 확인된 API(RNGH 2.31.2):

```ts
// 그리드 레벨에서 1개만 생성 (useRef 로 인스턴스 고정)
const listGesture = useRef(Gesture.Native()).current;
<GestureDetector gesture={listGesture}><FlatList numColumns={3} .../></GestureDetector>

// 셀 레벨 — 카드마다
const pan = Gesture.Pan()
  .enabled(!quickMode)                  // 퀵모드면 드래그 자체를 끈다
  .activateAfterLongPress(180)          // 짧은 스와이프 = 스크롤, 길게 누르면 = 드래그
  .blocksExternalGesture(listGesture);  // 활성화되면 FlatList 스크롤을 막는다
```

`activateAfterLongPress`만으로는 부족하다 — 롱프레스 후 손가락을 움직이면 네이티브
ScrollView도 같이 스크롤된다. `blocksExternalGesture`가 반드시 있어야 한다.
`simultaneousWithExternalGesture`는 **쓰면 안 된다**(둘 다 동시 인식 = 같이 스크롤).

Drawer 충돌도 차단: `<Drawer swipeEnabled={false}>`. 우측 가장자리로 카드를 끌면 drawer가
열려버린다. 오버레이 탭 닫기는 `swipeEnabled`와 무관하게 동작하므로 닫는 길은 남는다.

**고스트는 화면 최상단 absolute 하나.** FlatList가 children을 클리핑해서 카드마다 렌더하면
좌측 패널 경계에서 잘려 우측까지 못 간다. `custom-screen.tsx` 최상위에
`<Animated.View pointerEvents="none">` 하나를 두고, 내용은 `AugmentTile size={64}` + 이름
1줄(185pt 카드가 손가락을 따라다니면 우측 패널을 통째로 가린다). `opacity 0.9`,
`scale 1.05`, `Elevation.level3`.

**드롭 판정에 `measure()`는 불필요.** 경계가 이미 우리가 계산한 상수다:

```ts
dropBoundary.value = insets.left + Math.round(bodyW * 6.5 / 11);  // shared value
// worklet 안에서: e.absoluteX > dropBoundary.value
```

`useAnimatedRef` + `measure()`는 비동기 측정 레이스만 늘리고 얻는 게 없다.

**`GestureHandlerRootView` 명시 배치 불필요** — `<Drawer>`가 자기 children을 그것으로
감싼다(`react-native-drawer-layout/lib/module/views/Drawer.native.js:273`, 확인 완료).
화면 전체가 Drawer children이라 `GestureDetector`의 `__DEV__` throw 조건을 만족한다.
숨은 의존이므로 `custom-screen.tsx` 상단에 주석으로 못 박는다.

**worklet ↔ JS**: `runOnJS` 대신 `react-native-worklets`의 `scheduleOnRN`(이미 설치됨,
export 확인 완료). 햅틱은 네이티브 모듈이라 worklet에서 못 부르므로 JS 콜백 안에서:

| 시점 | 햅틱 |
|---|---|
| 집을 때 | `impactAsync(Medium)` |
| 성공 드롭 | `impactAsync(Light)` |
| 중복 / 개수 제한 초과 | `notificationAsync(Warning)` + 담기지 않음 |

퀵모드일 때는 `Pressable onPress` → `add()` + `impactAsync(Light)`. 드래그 모드에서 탭은
no-op(드래그가 기본이라는 요구사항).

**`expo-haptics` 설치 필요** — 미설치 확인됨. RN `Vibration`은 iOS에서 통짜 진동이라
taptic click이 아니다. 네이티브 모듈이므로 `/prebuild`로 리빌드해야 한다.

## 5. 상태 — 전부 화면 로컬

`use-locale.ts`식 전역 스토어를 만들지 않는다. 이 설정을 읽는 곳이 이 화면 하나뿐이고,
이번 턴에는 조합이 저장조차 되지 않는 스크래치패드다. 정렬 순서를 AsyncStorage에
영속화하는 건 추측성 요구다.

`src/features/custom/hooks/use-custom-draft.ts`:

```ts
championId: string          // params 초기값 → 이후 로컬 state (챔피언 변경용)
mode: DraftMode             // "aram" | "classic"
tier: AugmentRarity | null  // 티어 필터
sort: "default" | "name" | "rarity"
limit: 4 | 5 | 6 | null     // null = 무제한 (기본값)
quickMode: boolean          // 기본 false = 드래그앤드롭
picked: Augment[]

pool = useAugmentPool(mode)   // ← useAugments 아님. 모드 태그 없는 38개가 섞이면 안 된다
list = pool.filter(tier).sort(sort)
add(a) / remove(id) / clear()
```

`add`는 중복이면 no-op, `limit !== null && picked.length >= limit`이면 거부(false 반환 →
경고 햅틱). 정렬: `default`=원본 순서 / `name`=`localeCompare(name, locale)` /
`rarity`=prismatic > gold > silver 후 이름. 파생값은 React Compiler가 처리하므로
`useMemo` 수동 추가 금지.

**모드 전환 시 새 풀에 없는 증강은 그냥 둔다(코드 0줄).** 공유 증강은 한 레코드에
`modes: ["aram","classic"]`로 담겨 id 중복이 없으니 담긴 배열은 항상 유효하다. 다만
칼바람 전용 증강을 담은 뒤 클래식으로 바꾸면 **실제로는 불가능한 조합이 남는다** — 이번
턴은 저장하지 않는 샌드박스이고 drawer의 "선택 초기화"가 탈출구이므로 감수한다.
`ponytail:` 주석으로 남기고, 다음 턴에 저장을 붙일 때 여기에 유효성 검사를 넣는다.

## 6. 헤더 + Drawer

헤더: 좌 `GlassButton systemImage="xmark" role="cancel"` → 확인 Alert → `PORTRAIT_UP` →
`dismissTo("/")` (aram-screen과 동일). 우 `GlassButton systemImage="slider.horizontal.3"`
→ drawer open.

Drawer는 `aram-screen.tsx:212`와 같은 형태(`drawerPosition="right"`, `drawerType="front"`,
`width = Math.min(340, screenW * 0.38)`) + `swipeEnabled={false}`.

**내용물은 `@expo/ui/swift-ui` `List`+`Section`** — 정확히 "설정 폼"이고 expo-ui 스킬이
컨트롤 UI에 이걸 1순위로 못 박았다. drawer content는 평범한 RN View이고 SwiftUI `Host`는
그 안에서 UIView 서브트리로 살므로 가로/세로와 무관하다(고정 폭 컨테이너라 `Host
style={{flex:1}}`이 구체 크기를 받는다).

| Section | 컨트롤 | 값 |
|---|---|---|
| 모드 | `Picker` segmented | 칼바람 / 클래식 |
| 증강 | `Toggle` 퀵모드 | 기본 off(=드래그앤드롭) |
| | `Picker` segmented 개수 제한 | 4 / 5 / 6 / 무제한(기본) |
| | `Picker` segmented 정렬 | 기본 / 이름순 / 티어순 |
| 액션 | `SettingsRow` 선택 초기화 | `colors.status.danger.default` |
| | `SettingsRow` 챔피언 변경 | drawer 닫고 오버레이 open |

가드레일:
- `Picker`는 반드시 `pickerStyle("segmented")` — 기본(menu)은 popover를 띄우는데 drawer는
  Reanimated transform으로 움직이는 뷰라 앵커가 어긋난다. segmented는 인라인이라 무관.
- `mypage-screen.tsx:112`의 `<Host key={mode} colorScheme={mode}>` remount 워크어라운드를
  그대로 복사(런타임 테마 전환 시 tint가 안 따라오는 expo-ui 버그).
- **폴백**: 시뮬레이터에서 swift-ui List가 가로 drawer에서 깨지면(빈 화면/잘림) RN
  `Pressable` 세그먼트로 내려간다. 판단은 검증 20~21번 항목에서.

클래식의 "5"는 바론 간식 10개 룰에 근거가 있지만, 옵션 목록은 모드와 무관하게
4/5/6/무제한을 고정 노출한다(커스텀의 취지가 자유도이므로 모드로 옵션을 잠그지 않는다).

`SettingsRow`는 `src/features/mypage/components/settings-row.tsx`에 있는데 feature 간
import 금지에 걸린다. 폴더 규칙 6("2개 이상 feature에서 쓰이면 승격")에 따라
**`src/components/ui/settings-row.tsx`로 이동**하고 mypage의 import 1줄을 고친다.

## 7. 챔피언 변경 — 라우팅하지 않는다

화면 내부 절대배치 오버레이로 해결한다. 모달 push가 나쁜 이유 셋: expo-router에 반환값
API가 없어 결과를 받으려면 모듈 스토어 + `use-champion-select` 특수분기를 둘 다 만들어야
하고, 가로 잠금 화면 위에 모달을 present하면 native large-title + 검색바가 뭉개지며 알려진
orientation 해제 버그 구간에 들어가고, 돌아올 때 `/custom`이 remount되면 담아둔 증강이
날아간다.

`championId`를 params 초기값으로만 받고 이후 **로컬 state**로 들면 교체가 `setState`
한 번이다.

`ChampionSelectGrid`는 재사용하지 않는다 — `numColumns={4}` 하드코딩에 셀 `width:"25%"`,
`contentInsetAdjustmentBehavior="automatic"`(native large-title 스크롤 연동 전제)이라
가로에서 셀이 180pt 괴물이 되고, 고치려면 prop을 여러 개 뚫어야 하며 애초에 feature 간
import다. 대신 오버레이를 최소로 새로 짠다(~80줄): `TextInput` 검색 +
`matchChampionName`(`@/lib/hangul`, 초성 지원) + `RemoteImage` 8열 그리드. 쓰는 건
`useChampions()` 훅과 lib뿐이라 폴더 규칙 위반이 없다(`picked-drawer.tsx`가 이미 하는
수준의 의존).

## 8. 다음 턴(`/aram-items`) 이음매

헤더 우측, 필터 버튼 왼쪽에 완료 버튼 자리만 비워두고 이번 턴엔 렌더하지 않는다.
`use-custom-draft`가 반환하는 `picked: Augment[]` / `mode: DraftMode`가 **이미
`/aram-items`가 기대하는 정확한 형태**(`item-select-screen.tsx:36-45`)이므로 어댑터가
필요 없다:

```ts
router.replace({ pathname: "/aram-items",
  params: { picked: JSON.stringify(picked), championId, mode } });
```

`mode`가 `DraftMode`라 `parseDraftMode`와 `saveBuild({ mode })`가 무수정으로 받는다.

## 검증

`.agents/skills/verify/SKILL.md` 절차로 iOS 시뮬레이터에서 직접 굴리고 결과를
`docs/verification/2026-08-26-커스텀-모드.md`에 기록. 타입체크·lint 통과는 검증이 아니다.

**진입/라우팅**
1. `+` → 원형 버튼 4개(위부터 커스텀/아레나/클래식/칼바람), 아이콘 `tune-variant`, **하단 `+` 버튼이 안 가려짐**
2. 커스텀 → 챔피언 모달이 기존과 동일(용기 셀 없음, 간식 알럿 없음)
3. ✓ → **가로 전환 후** 커스텀 화면(세로로 떴다 reflow되지 않는지)
4. **회귀**: 칼바람 / 클래식(간식 예=5, 아니오=4) / 아레나 각 1회 — 목적지 Record 교체로 깨진 게 없는지

**레이아웃**
5. 6.5:4.5 분할, 좌측 3열, 카드 잘림/겹침 없음
6. 노치 쪽 safe area — 헤더 버튼이 기기 끝·홈 인디케이터 제스처 영역에 안 걸림(item-select-screen이 실제로 겪은 문제)
7. `RarityCardFrame` 설명 잘림 정도 육안 판정 → 못 봐주면 `iconSize` prop 추가

**필터/정렬**
8. 티어 레일 전체/실버/골드/프리즘 → 해당 티어만
9. 정렬 3종 반영, **ko/en 전환 시 이름순이 로케일에 맞게** 재정렬

**드래그 앤 드롭 (핵심)**
10. 카드를 짧게 위아래 스와이프 → **리스트가 스크롤됨**
11. 길게 눌러 → **햅틱 + 반투명 고스트**가 손가락을 따라옴
12. 드래그 중 **리스트가 같이 스크롤되지 않음** (`blocksExternalGesture` 검증 포인트)
13. 고스트가 **패널 경계에서 안 잘리고** 우측까지 넘어감
14. 우측에 놓으면 **햅틱 + 행 추가**, 좌측 그 카드에 **체크 표시**
15. 좌측에서 놓으면 아무 일 없이 고스트만 사라짐
16. 드래그로 우측 끝까지 가도 **drawer가 안 열림**(`swipeEnabled={false}`)
17. 같은 증강 두 번 드롭 → 중복 안 됨
18. 개수 제한 4로 두고 5번째 → **경고 햅틱 + 안 담김**
19. 선택 행 탭 → 제거되고 좌측 체크 해제

**Drawer**
20. 필터 아이콘 → 우측 drawer, swift-ui `List`가 **가로에서 안 깨지고** 렌더 (깨지면 §6 폴백)
21. segmented `Picker` 3개가 값 반영, 라이트/다크 전환 시 tint 따라옴(`key={mode}` 검증)
22. 모드 칼바람↔클래식 → **좌측 풀이 실제로 바뀜**(칼바람 211 / 클래식 187). 담은 증강은 우측에 유지
23. 퀵모드 ON → **탭 한 번에 담김**, 드래그 안 걸림. OFF → 원복
24. 선택 초기화 → 우측 비고 좌측 체크 전부 해제
25. 챔피언 변경 → 오버레이 → 초성 검색("ㅇㄹㄹ") 동작 → **우측 챔피언만 바뀌고 담은 증강 유지**, 세로로 안 돌아감

**나가기**
26. X → Alert → 종료 시 **세로 복귀** 후 홈. Alert 뜨는 동안 세로로 안 돌아감
27. 취소 누르면 가로 유지
