# 부팅 시 전역 이미지 Prewarm — 첫 설치 빈 화면 제거

## Context (왜 하는가)

앱은 챔피언/증강/아이템 아이콘을 전부 CDN(DDragon·CommunityDragon)에서 받아 쓴다. 현재 prefetch는 **화면에 진입한 뒤(`useFocusEffect`)** 시작하므로, 첫 설치 후 챔피언 선택·드래프트·아이템 화면에 처음 들어가면 캐시가 비어 **빈 화면을 보다가 수 초 뒤에야 아이콘이 뜬다**. placeholder 박스로 가리는 건 사용자가 명시적으로 거부 — "박스 말고 진짜 아이콘이 보여야 한다".

근본 해결: **앱 부팅 시점에 전체 이미지를 미리 받아 디스크 캐시에 적재(prewarm)**한다. `Image.prefetch`는 멱등이라 한 번 받으면 재설치 전까지 영구 캐시되고, 이후 부팅에선 네트워크를 안 탄다.

**확정된 방향(사용자 선택):**
- **범위 = 전체**: 챔피언 square(172) + 증강 large(222) + ARAM 아이템(111) + 역할 아이콘(6) ≈ **9MB**. 현재 로케일 1개 기준.
- **첫 실행 동작 = 하이브리드**: 부팅 즉시 백그라운드 전체 prewarm 시작 + **첫 실행에 한해** 스플래시를 "핵심(챔피언 square + 역할 아이콘 ≈ 3.4MB) 완료 OR 타임아웃"까지만 짧게 유지. 두 번째 실행부터는 게이트 없이 즉시 진입(캐시 히트).

## 작업 1 — Prewarm 오케스트레이션 유틸 (신규)

**`src/lib/image-prewarm.ts`** (순수 유틸 — React 훅 아님, lib 규칙 충족)

- 데이터는 기존 훅들과 동일하게 `require`로 직접 로드: `champions.{locale}.json`, `augments.{locale}.json`, `items.{locale}.json`, `aram-item-ids.json`.
- URL 빌더는 **`src/lib/ddragon.ts`의 기존 함수 재사용**: `championSquareUrl(imageKey)`, `championClassIconUrl(tag)`, `augmentImageUrl(iconPath, 'large')`, `itemImageUrl(imageKey)`.
- 우선순위 그룹으로 URL 묶음 생성:
  - **core**: 챔피언 square 전체 + 역할 아이콘(`CHAMPION_TAGS` 6종). (첫 도달 화면 = 챔피언 선택)
  - **rest**: 증강 large 전체 + ARAM 아이템 아이콘.
- `prewarmImages({ locale, onCoreDone })`:
  - `Image.prefetch(coreUrls, { cachePolicy: 'memory-disk' })` 를 먼저 `await` → 끝나면 `onCoreDone()` 호출(스플래시 해제 신호).
  - 이어서 `rest`를 백그라운드로 prefetch(블로킹 안 함).
  - 대량 동시 요청 방지를 위해 그룹 내부를 적당한 배치(예: 40개씩)로 끊어 순차 prefetch.
- **스킵 플래그**: `AsyncStorage`에 `prewarm:done:<ddragonVersion>` 기록. 이미 완료면 core await 없이 `onCoreDone()` 즉시 호출(게이트 없음), rest는 멱등이라 가볍게 백그라운드 호출만. 버전(`version.json`의 `ddragonVersion`)이 바뀌면 자동 재실행. (AsyncStorage 사용 패턴은 `src/lib/build-storage.ts`·`use-locale.ts` 참고)

## 작업 2 — 부팅 훅 (신규)

**`src/hooks/use-image-prewarm.ts`** (여러 feature 데이터를 데움 → 글로벌 훅, `src/hooks/` 규칙 충족)

- `useImagePrewarm(): { splashReady: boolean }`.
- 마운트 시 1회: `useLocale()`로 현재 로케일 확보 → `prewarmImages` 실행.
- `onCoreDone` 또는 **타임아웃(약 4초)** 중 먼저 오는 쪽에서 `splashReady = true`. (네트워크가 느려도 무한 대기 금지 — 빈 화면보다 낫고, 캡 이후엔 어차피 화면별 focus prefetch 백업이 받는다.)
- 첫 실행이 아니면(스킵 플래그 존재) 즉시 `splashReady = true`.

## 작업 3 — 스플래시 게이트 연결

**`src/components/navigation/animated-icon.tsx`** — `AnimatedSplashOverlay`에 `ready: boolean` prop 추가.
- `ready === false` 동안: 페이드아웃 키프레임을 **시작하지 않고** 풀스크린 솔리드(`backgroundSolidColor`)를 정적으로 유지.
- `ready === true`가 되는 순간: 기존 `splashKeyframe`(600ms 페이드아웃) 시작 → 완료 시 언마운트. (기존 애니메이션 로직 그대로, 트리거만 `ready`로 변경)

**`src/app/_layout.tsx`** — `const { splashReady } = useImagePrewarm();` 호출 후 `<AnimatedSplashOverlay ready={splashReady} />`로 전달.

## 작업 4 — 기존 focus prefetch 정리(유지)

화면별 `useFocusEffect` prefetch(`champion-select-screen`, `item-select-screen`, `draft-screen`)는 **백업으로 유지**한다. prewarm이 이미 채웠으면 캐시 히트라 무비용이고, 타임아웃 캡으로 일부 못 받은 경우·증강 리롤 같은 동적 케이스를 커버한다. (중복이지만 멱등이라 안전)

## 검증

```bash
npm run lint
npx expo prebuild --clean   # 아이콘/스플래시 네이티브 반영(이전 단계 포함)
npm run ios
```

- **앱 데이터/캐시 완전 삭제 후 첫 실행**: 스플래시가 평소보다 약간 길게(core 받는 동안, 최대 ~4초) 유지된 뒤 사라지고, 챔피언 선택 모달 진입 시 **빈 화면 없이** 아이콘이 바로 보인다.
- 그 직후 드래프트·아이템 화면 진입 시에도 대부분 즉시 표시(부팅 후 백그라운드로 rest까지 받았으므로). 아주 빠르게 연속 진입하면 일부만 늦을 수 있으나 focus prefetch가 받음.
- **두 번째 실행부터**: 스플래시 지연 없이 기존처럼 600ms 후 사라지고, 모든 아이콘 즉시 표시(디스크 캐시 히트).
- Network Link Conditioner로 느린 네트워크에서 타임아웃 캡(4초) 후 스플래시가 풀리는지 확인.

## 메모

- 로케일 전환 시 챔피언/증강/아이템 **이름** JSON만 바뀌고 이미지 URL(imageKey/iconPath)은 동일 → 이미지 재prewarm 불필요. core URL은 로케일 무관하므로 plan대로면 자동 처리.
