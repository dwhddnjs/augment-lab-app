# 티어리스트 챔피언 모달 — 아이템 섹션 정확도 + UI 교체

## Context

`tierlist-champion-modal` 하단 아이템 섹션이 (1) 추천이 부정확하고 (2) 카드 행 6개가 세로를 너무 먹는다.

**원인(실측)**: `scripts/fetch-data/fetch-tierlist.ts`가 dtodo `build.coreItems`(코어 빌드)를 버리고
`build.situationalItems`(코어를 **뺀** 상황템 풀)에서 **승률순** top 6만 뽑는다.
- 코어에 들어간 강철심장은 상황템 풀에 애초에 없다 → 현재 데이터 탱커 46명 중 강철심장 **4명**.
- 승률순이라 게임이 길어져야 사는 방템(대자연의 힘·케이닉 루컨)이 생존자 편향으로 위에 뜬다.
- 소스 자체는 멀쩡하다: 같은 응답의 `coreItems[0]`이 세주아니·초가스·사이온·마오카이·알리스타·노틸러스·탐켄치·오른·문도·레오나·브라움 11/12명 모두 **강철심장+헤르메스+X** (아무무만 태양불꽃 — 정상).

목표: 소스가 이미 준 빌드 데이터를 제대로 쓰고, 참고 이미지처럼 **아이콘 격자**로 압축한다.

## 데이터 매핑 (dtodo `build` = 최다 픽 빌드 1개)

| 이미지 섹션 | 소스 | 판단 |
|---|---|---|
| 시작 아이템 | `startingItems` | **제외** — 표본이 챔피언 대부분 1~11판(오른만 341). 보여주면 거짓말 |
| 빌드 순서 + 완성 아이템 | `coreItems[0].itemIds`(구매 순서 3개) + `itemExtensions` step 1→2→3 | **한 섹션 "빌드 순서"로 합침** — 구성품 단위 순서 데이터는 없다. 완성템 5~6개 |
| 상황별 아이템 | `situationalItems`(판수 내림차순) − 빌드 순서에 이미 있는 것 | 9~11개 |
| 우상단 스펠 + % | `summonerSpells[0]` ids + pickRate | 포함 |

확장 경로 도출(샘플 18명 검증 완료): 코어 id를 정렬한 키와 `coreItemIds` 정렬 키가 같은 extension만 → step마다 "지금까지 추가한 아이템을 모두 포함하는 후보 중 games 최다"를 골라 새 id 1개를 붙인다. 후보가 없으면 거기서 멈춘다(5개로 끝나는 챔피언 있음).
결과 예: 초가스 `강철심장→헤르메스→워모그→가시갑옷→케이닉→끝없는절망`, 야스오 `광전사→몰왕→불멸의철갑궁→무대→죽무→피바`.

## 변경

### 1. `scripts/fetch-data/fetch-tierlist.ts`
- `top()`·`N_ITEM` 삭제. 아이템 루프를 위 매핑으로 교체 (`ponytail:` 주석 — 탐욕 경로, step 표본 없으면 짧아짐).
- 상황템 `MIN_GAMES` 필터는 유지(저픽 챔피언 노이즈 방지). 승률 계산(`wins/games`)은 삭제 — 더 이상 표시 안 함.
- CDragon `default/v1/summoner-spells.json` 한 번 받아, 쓰인 스펠만 `spellIcons: { "4": iconPath }`로 tierlist.json 최상위에 싣는다(로케일 무관 — 이름 안 씀).
- 행 스키마: `items: Entry[]` → `build: string[]`, `situational: string[]`, `spells: [number, number]`, `spellPick: number`. `usedItems`는 build+situational 합집합.
- 로그 한 줄: 앱 `champions.ko.json` tags에 Tank인 챔피언 중 `build`에 강철심장(3084) 포함 수 — 매 fetch마다 정확도 회귀 확인용.
- 실행: `npm run data:tierlist` (3~5분) → `tierlist.json`, `tierlist-items.{ko,en}.json` 재생성.

### 2. `src/features/tierlist/tiers.ts`
- `TierEntry` 삭제, `TierRow`에 위 4필드 반영. `export const spellIcons = data.spellIcons`.

### 3. `src/features/tierlist/screens/tierlist-champion-screen.tsx`
- `DetailCardRow`·`meta()` 제거(컴포넌트 파일 자체는 builds/arena가 계속 사용).
- "아이템" heading 행을 `flexDirection: row, space-between`으로 — 우측에 스펠 pill(`surface.raised` 배경 + 스펠 아이콘 2개 + 픽률 `color="accent"`). 이미지 우상단 위치와 같고 세로 한 줄 절약.
- 로컬 함수 `itemGroup(label, ids)` 하나로 두 섹션 렌더: 기존 증강 그룹과 같은 `ThemedText type="label" color="secondary"` 라벨 + `flexWrap` 행에 `RemoteImage` 44pt(`Radius.md`, gap `Spacing.two`). 402pt 폭에서 한 줄 7개 → 빌드 1줄, 상황템 2줄.
- 스펠 아이콘은 `cdragonItemIconUrl(iconPath)` 재사용(경로 규칙 동일, URL 200 확인함).
- i18n 키: `buildOrder`(빌드 순서/Build Order), `situational`(상황별 아이템/Situational), `spellPick`은 숫자만이라 불필요. `games` 키 삭제.
- 헤더 주석(1~8행) 갱신.

### 4. `src/components/ui/remote-image.tsx`
- `accessibilityLabel?: string` prop 추가 → `Image`에 전달. 아이콘만 남으니 VoiceOver·ax 트리에 아이템 이름이 필요하다(검증에서 ax로 이름 대조에도 씀).

검수 페이지(`docs/index.html`) 재생성 불필요 — `tierlist/data/`는 augment-check 대상 아님.

## 검증

1. **데이터 정확도** (fetch 직후)
   - 스크립트 로그의 탱커 강철심장 포함률 (현재 4/46 → 기대 대다수; 빠진 챔피언은 이름 나열해 타당성 확인)
   - 탱커·딜러·AP 몇 명을 op.gg/u.gg ARAM 빌드와 교차 대조 → 결과를 검증 문서에 기록
2. **시뮬레이터** (`/prebuild` 절차 — `orca emulator attach <UDID>` → `ax`로 요소 찾아 tap)
   - 티어리스트 탭 → 세주아니(탱커)·야스오(딜러)·말파이트 모달 열기, 스크롤해 아이템 섹션
   - 확인: 빌드 순서 첫 아이콘 ax 라벨이 "강철심장", 상황템과 중복 없음, 스펠 pill 표시, 다크/라이트, ko/en 라벨
3. **사용자 확인용 스크린샷**: `xcrun simctl io <UDID> screenshot <scratchpad>/*.png` → PNG를 data URI로 임베드한 **Artifact 페이지** 게시 후 링크 전달(모바일에서 열람). 스크린샷은 커밋 안 함.
4. 기록: `docs/plans/2026-09-17-티어리스트-아이템-빌드.md`(이 플랜), `docs/verification/2026-09-17-티어리스트-아이템-빌드.md`. `npm run lint`.
