# 증강연구소 네이티브 마이그레이션 — 작업 체계 수립 플랜

## Context

- RN(Expo SDK 56)을 걷어내고 **iOS = SwiftUI**, **Android = Kotlin + Jetpack Compose**로 다시 만든다.
- Android는 신규 등록 대신 Google Play의 기존 앱 **porcana(`com.porcana`)** 리스팅을 증강연구소로 바꿔치기한다.
  - 목적: 신규 개인 계정 앱에 걸리는 **12인·14일 비공개 테스트**를 피하는 것.
  - 이 요건은 앱 단위로, *프로덕션 접근 권한*을 얻을 때만 걸린다.
- 순서는 **iOS 전부 → Android 전부**.
- 작업은 피처 단위로 잘게 쪼갠다. 목표는 두 가지다.
  - **여러 세션이 동시에 돌아도 서로 파일을 건드리지 않는다**(소유 경로 분리).
  - 완료할 때마다 체크·기록해서 다음 세션이 곧바로 이어받는다.
- Pro 플랜 5시간 한도가 **95%에 도달하면** 자동으로 경고가 들어온다. 그때 기록 → 커밋 → push 후 멈춘다.

**이번 실행의 산출물은 문서와 작업 장치뿐이다.** 앱 코드는 쓰지 않는다.

## 확인된 사실

- **현재 앱 규모**
  - TS/TSX 14,427줄, 라우트 18개
  - 번들 ID `com.augmentlab`, 버전 1.6.2, 최소 iOS 16.4
  - 사용 도구: Xcode 26.5, Android Studio·SDK·JDK 17 설치됨
- **porcana** (`~/Desktop/porcana-app`)
  - Expo 앱, `android.package = com.porcana`
  - versionCode는 EAS가 원격 관리한다(`appVersionSource: remote`)
  - `eas.json`의 submit track이 `internal`이다 → **프로덕션 출시 여부부터 확인해야 한다**
- **업로드 키**
  - `~/Desktop/google keys/porcana/@dwhddnjs__porcana-app.jks`와 `upload_cert.pem`이 있다 → Play App Signing을 쓰는 것으로 추정
  - 업로드 키를 잃어버려도 Play Console에서 재설정할 수 있다(공식 문서 확인)
- **Play 요건**: 2026-08-31부터 신규 앱과 업데이트 모두 **targetSdk 36**이 필요하다.
- **기존 사용자 데이터 위치(iOS)**
  - AsyncStorage: `Library/Application Support/com.augmentlab/RCTAsyncLocalStorage_V1/manifest.json`
  - 1024자를 넘는 값은 `md5(key)` 이름의 별도 파일에 있다(`builds:v1` → `970e875d66bf736ae9a9465c34219ef6`)
  - 옮길 키: `builds:v1`, `theme:v1`, `locale:v1`, `review:requested`, `prewarm:done:<ver>`
  - 이미지 캐시는 SDWebImage 기본 캐시를 쓴다(`expo-image` 내부 구현)
- **한도 감지 장치**
  - 사용자 statusline(`~/.claude/statusline-command.sh`)이 이미 5시간 사용률을 `~/.claude/state/five-hour-pct`(`"pct epoch"`)에 쓰고 있다
  - 이 파일을 읽는 훅만 없다
- **`/ship` 제약**
  - 사용자가 직접 입력해야만 실행된다. 모델이 호출할 수 없다.
  - PR 생성 + 리뷰 + 최대 7일 감시까지 해서 토큰을 많이 쓴다.
  - → 95%일 때는 "기록 → 커밋 → push"만 자동으로 하고, `/ship`은 사용자에게 안내한다.

## 기본값으로 정한 결정 (질문 없이 진행 — 바꾸려면 플랜 승인 전에 말해 줄 것)

**공통**
1. **저장소 구조**: 같은 저장소 안에 `native/ios/`, `native/android/`를 둔다.
   - RN 앱은 Android 출시까지 그대로 둔다(핫픽스 경로 유지).
   - 마지막 작업 R-01에서 RN을 제거하고 JSON을 `data/`로 옮긴다.
2. **데이터 JSON은 옮기지 않는다.** 세 앱 모두 `src/features/*/data/*.json`을 그대로 읽는다.
   - iOS는 빌드 스크립트로 번들에 복사하고, Android는 `assets.srcDirs`로 연결한다.
   - 덕분에 `npm run data:refresh`와 `augment-check` 절차를 그대로 쓴다.
3. **동작은 RN과 똑같이 맞춘다.** 고의로 바꾸는 것은 하나뿐이다.
   - 신규 설치 시 언어 = 기기 언어(한국어면 ko, 그 외는 en). 저장값이 있으면 저장값을 쓴다. Android 글로벌 출시 때문이다.
   - 개선 아이디어는 `README`의 "마이그레이션 후 개선 후보"에만 적는다.

**iOS**
4. **최소 iOS 17.0** (`@Observable` 사용). iOS 16 사용자는 1.6.2에 머문다.
5. **순수 로직은 로컬 Swift 패키지 `AugmentCore`에 둔다.**
   - 대상: 모델, 데이터 로드, 규칙 엔진, 저장 형식 파싱, 백업 형식, 초성 검색, 스탯 계산.
   - `swift test`가 macOS에서 바로 돈다 → **시뮬레이터 없이 테스트**(메모리 규칙 "시뮬레이터 확인 금지"와 맞음).
   - 기존 `scripts/check-*.ts`의 검증 항목을 그대로 테스트로 옮긴다.
6. **Xcode 프로젝트는 Xcode 16+ 동기화 폴더**(objectVersion 77)로 만든다.
   - 파일을 추가해도 `project.pbxproj`가 바뀌지 않는다 → 병렬 세션끼리 pbxproj 충돌이 없다.
7. **의존성은 3개뿐**이고, 추가는 I-00에서만 한다.
   - SDWebImageSwiftUI: 기존 SDWebImage 캐시와 이어지고, 디스크 캐시 만료(`maxDiskAge`)를 무제한으로 둔다
   - PostHog iOS
   - Sentry Cocoa
8. **Glass·탭**: RN과 같은 분기를 쓴다.
   - iOS 26+: 시스템 Liquid Glass, TabView, `+` 탭은 search 역할로 둔다.
   - 26 미만: 단색 폴백과 커스텀 탭바.

**Android**
9. **ID**: `applicationId = com.porcana`(영구 고정), 코드 `namespace = com.augmentlab`.
   - 모듈은 하나(`:app`) — 단위 테스트가 JVM에서 바로 돈다.
   - 스택: Compose + Navigation(type-safe) + kotlinx.serialization + Coil 3 + SharedPreferences, PostHog/Sentry Android.
   - minSdk 26, targetSdk 36.
   - 디자인은 iOS 26 미만 폴백 디자인을 기준으로 삼는다(glass 대신 단색, 커스텀 탭바).
10. **porcana 잔여 데이터**: 첫 실행 때 기기에 남은 porcana 데이터(RN `RKStorage` DB, 로그인 토큰)를 지운다.

## 멀티 세션 규칙 (README에 기록)

**작업 시작**
- 1 작업 = 1 브랜치 `native/<ID>` = 1 워크트리 `.claude/worktrees/<ID>`.
  - `.claude/worktrees/`는 이미 gitignore되어 있다.
  - 시작 명령: `git worktree add .claude/worktrees/<ID> -b native/<ID> dev`
- **브랜치가 곧 "진행 중" 표시**다. `status.sh`가 `git branch --list 'native/*'`로 보여 준다.
  - 따로 잠금 장치를 두지 않는다. 사용자가 세션마다 작업 ID를 지정한다.
- `depends`의 작업이 dev에 머지된 뒤에만 시작한다.

**작업 중 — 손대도 되는 범위**
- 수정할 수 있는 것은 **자기 `owns` 경로와 자기 작업 파일뿐**이다.
- 공용 파일(라우트, 토큰, Core 모델, 빌드 설정)은 웨이브 0 작업이 소유한다. 웨이브 0이 끝나면 동결한다.
- 공용 파일을 바꿔야 하면 작업을 멈추지 않는다.
  1. 자기 폴더 안에 임시로 구현한다.
  2. 작업 파일의 "승격 후보"에 적는다.
  3. 나중에 별도의 짧은 직렬 작업으로 반영한다.
- **스텁 계약으로 화면끼리 분리한다.**
  - I-06a가 모든 라우트와 각 피처의 진입 View를 시그니처 고정 스텁으로 먼저 만든다.
    - 예: `struct AramScreen: View { let params: AramParams }`
  - 이후 그 파일은 해당 피처 작업이 소유한다.
  - 다른 화면에 끼워 넣는 조각(예: 홈 안의 `TopTierSection`)도 스텁을 먼저 만든다.
  - 화면 이동은 I-06의 `Router` API만 호출한다.
- **빌드는 워크트리별로 분리한다.**
  - iOS는 `-derivedDataPath .build/ios`(`.gitignore`에 `.build/` 추가), Android는 워크트리마다 자체 Gradle 빌드를 쓴다.
  - 세션은 컴파일과 단위 테스트까지만 한다. 시뮬레이터 실행은 사용자가 한다.

**작업 완료**
- 작업 파일의 `status`를 `done`으로 바꾼다.
- 커밋 → push → `gh pr create --base dev`로 PR을 연다. 리뷰까지 원하면 사용자가 `/ship`을 입력한다.
- 사용자가 화면을 확인하고 머지한다. dev에 반영되면 그때 완료로 본다.

**공유 상태판을 두지 않는 이유**
- 상태는 각 작업 파일의 frontmatter에만 있다.
- `README`의 작업 표는 고정 정보(ID·범위·의존)만 담는다.
- → 여러 세션이 같은 파일을 고칠 일이 없어 머지 충돌이 0이다.

**동시 세션 수**
- 5시간 한도는 계정 전체가 공유한다. Pro 플랜에서는 **동시에 2~3개 세션**을 권장한다.

## 95% 한도 장치

- **추가 파일**
  - 훅 스크립트 `.claude/hooks/usage-guard.sh` (커밋 → 모든 워크트리에 자동 적용)
  - 프로젝트 `.claude/settings.json`에 `PostToolUse`(matcher `*`)와 `UserPromptSubmit` 훅 추가 (`update-config` 스킬로 작성)
- **동작**
  1. `~/.claude/state/five-hour-pct`를 읽는다. 15분보다 오래된 값은 무시한다.
  2. 95% 이상이고, 이번 세션에 아직 경고하지 않았으면 → `hookSpecificOutput.additionalContext`로 지시를 넣는다.
     - 지시 내용: "지금 단계까지만 끝내고 ① 진행 기록 ② 커밋 ③ push ④ `/ship` 안내 후 정지. 새 단계 시작 금지"
     - 세션별 표시 파일 `~/.claude/state/usage-guard-<session_id>`를 만든다.
  3. 95% 미만으로 떨어지면(새 5시간 창) 표시 파일을 지운다.
- **평소 대비책**: 체크리스트 한 단계를 마칠 때마다 체크하고 로컬 커밋한다. 한도 때문에 갑자기 끊겨도 잃는 것은 진행 중이던 한 단계뿐이다.
- **한계**
  - statusline 스크립트가 사용률 파일을 쓰는 데 의존한다. statusline을 바꾸면 이 줄을 유지해야 한다.
  - `rate_limits` 값은 세션의 첫 응답 이후에만 들어온다.

## 포르카나 전환 설명서 (`porcana-to-augmentlab.md`) 목차

0. **사전 확인 (하나라도 안 되면 이 방법은 쓸 수 없다)**
   - porcana가 **프로덕션 트랙에 출시돼 있는가**
   - 같은 개발자 계정인가
   - Play App Signing을 쓰는가
   - 업로드 키 비밀번호와 alias를 아는가 — `eas credentials -p android`에서 확인. 잃어버렸다면 업로드 키 재설정 절차를 따른다.
   - 현재 versionCode — `eas build:version:get -p android` 또는 Play Console에서 확인
1. **바뀌지 않는 것과 바뀌는 것**
   - 그대로: 패키지명 `com.porcana`와 스토어 URL, 리뷰·평점·설치 수
   - 바뀜: 이름, 아이콘, 스크린샷, 설명, 카테고리, 콘텐츠 등급, 데이터 보안, 개인정보처리방침
2. **빌드 설정**: `applicationId`, versionCode(> 기존 값), versionName 2.0.0, `keystore.properties`(gitignore), targetSdk 36
3. **Play Console 순서 (체크박스)**
   - 앱 콘텐츠: 개인정보처리방침, 로그인 없음, 콘텐츠 등급 재설문, 데이터 보안(PostHog 분석·세션 리플레이, Sentry 진단)
   - 스토어 등록정보: ko·en 이름, 짧은·전체 설명, 512 아이콘, 1024×500 그래픽, 스크린샷
   - 제목에 타사 상표를 넣지 않는다. 설명 끝에 Riot 고지문을 넣는다.
   - 내부 테스트로 직접 설치해 확인 → 프로덕션 출시. 출시 노트에 "포르카나 서비스 종료, 증강연구소로 전환"을 공지한다.
4. **기존 porcana 정리**
   - 서버(`api.porcana.co.kr` / Supabase)의 회원 개인정보를 파기하거나 고지한다
   - EAS Update를 더 이상 게시하지 않는다
   - iOS porcana는 별개라 영향이 없다
5. **위험 요소**
   - 기존 평점이 그대로 따라온다
   - "앱이 완전히 바뀌는 업데이트"를 금지하는 문구는 확인한 공식 문서 범위에 없었다. 다만 공지를 생략하면 기만 정책에 걸릴 위험이 있다.
6. **대안 한 줄**: 조직 계정(D-U-N-S)은 12인 테스트 대상이 아니다.
