# 아레나 증강·아이템 검수 및 아이콘/텍스트 개선

날짜: 2026-07-01

## 배경 (왜)

아레나 검수 페이지(`docs/arena-check.html`)에서 발견된 문제 정리:

1. **흐린 흰색 아이콘** — 일부 증강 아이콘이 흐릿한 흰색 라인아트로 표시됨.
   - 근본 원인(curl로 검증): `AugmentImage`(`src/components/ui/augment-image.tsx`)는
     large(256px, CDragon `/game/.../_large.png`) → small(64px) → 글리프 순으로 폴백한다.
     지적된 아이콘들은 CDragon `/game` 경로에 **large 자산이 없어(HTTP 404)** 64px small로
     폴백되고, 해당 아이콘이 채도 0의 흰색 라인아트라 어두운 카드에서 흐릿하게 보였다.
2. **희생: 골드/실버/프리즘** — 셋 다 `gohsacrificefor_small.png`(실버톤)을 공유해 등급 구분 불가.
3. **placeholder 증강** — "증강 없음"(null-augment, 디버그용)이 데이터에 섞여 있었음.
4. **프리즘 아이템 고유효과 텍스트 과도하게 김** — 핵심만 남겨야 함.

## 결정 사항

- 아이콘 교체는 **지적된 항목만**(전수 교체 X).
- 희생 3종은 **등급별 톤으로 분리**.
- placeholder는 **"증강 없음"만 제거**.
- **404/405는 유지** — CDragon `cherry-augments.json`에 정식 등록된 실제 이스터에그 증강
  (404=실버, 405=프리즘, "모자" 메커니즘으로 "양손잡이"와 연결, 아이콘 large 정상 200).

## 수행 결과

### 1. 흐림 근본 원인 = 베이스 파일 미사용 → augmentImageUrl 폴백 추가

**진짜 원인**: 라이엇 공식 데이터(`cdragon/arena/en_us.json`)가 가리키는 컬러 아이콘은 대부분
`_large.png`지만, 일부 증강(은수저·샌드위치·마법소녀·마트료시카·맹독 등)은 `_large`가 없고(404)
**접미사 없는 베이스 파일**(`silver_spoon.png` 등)에만 컬러가 있다. 앱의 `augmentImageUrl`은
`_large`만 시도하고 실패 시 흰색 `_small`로 폴백해 흰색이 나왔다. 블리츠는 베이스 파일을 쓴다.

**근본 수정** — 폴백 체인을 `_large` → base(접미사 없음) → `_small` → 글리프로 확장:
- `src/lib/ddragon.ts` — `augmentImageUrl(iconPath, 'base')` 분기 추가(`_small` 접미사 제거).
- `src/components/ui/augment-image.tsx` — `Step` 0~3으로 확장(large→base→small→glyph).
- `scripts/gen-arena-check.mjs`, `scripts/gen-augment-check.mjs` — 검수 페이지 onerror 체인도 동일.

이로써 흐림 5개(은수저·샌드위치·마법소녀·마트료시카·맹독)는 **원본 iconPath 그대로 컬러**로 나온다.
ARAM 흐린 아이콘들도 자동으로 혜택.

### 1-a. 희생 3종 — 등급별 **원본** 아이콘 발견·적용 (블리츠와 동일)

공식 `cherry-augments.json`상 희생 3종(id 302/303/304)의 `augmentSmallIconPath`는 셋 다
`GoHSacrificeFor_small.png` 하나로 동일하다. 그래서 처음엔 등급 구분이 불가하다고 보고 다른
아이콘(응징의 천사 등)을 지정했었다. **그러나 CDragon `/game` 경로를 직접 파보니 등급별 large
파일이 실제로 따로 존재**한다(블리츠가 쓰는 것). 같은 "상승 막대그래프+화살표" 모양에 등급색만 다름:

| 증강 | rarity | 원본 파일 (`_large` 200) | 색 |
|---|---|---|---|
| 희생: 골드 | gold | `gohsacrificeforgold_large.png` | 금색 |
| 희생: 실버 | silver | `gohsacrificefor_large.png` (base, 실버 전용 없음) | 은청색 |
| 희생: 프리즘 | prismatic | `gohsacrificeforprismatic_large.png` | 홀로그램 |

- iconPath는 `..._small.png`로 저장(앱 `augmentImageUrl`이 `_large`로 치환 → 첫 시도에서 컬러 200).
- 실버 전용(`gohsacrificeforsilver_*`)·base(`gohsacrificefor.png`)는 404 → 실버는 base `_large` 사용.
- 파일: `src/features/arena/data/augments.{ko,en}.json` (id 기반, ko/en 동일).

### 1-b. 칼바람 "공포"(terror) 아이콘 등급 보정

- gold 증강인데 iconPath가 `GenericAbilityAugmentIcon_Prismatic.png`(프리즘 제네릭)이라 프리즘 아이콘으로
  표시됨 → `GenericAbilityAugmentIcon_Gold.png`(골드 제네릭)로 교체.
- 파일: `src/features/augments/data/augments.{ko,en}.json` (terror 1줄, ko/en 동일).

### 2. "증강 없음"(null-augment) 제거

- `augments.{ko,en}.json`에서 삭제. 201→200개. 다른 코드 참조 없음.

### 3. 프리즘 아이템 텍스트 단축 (23종)

- 데이터 흐름: `prismatic-items.{ko,en}.json`이 앱 노출 소스이며,
  `scripts/fetch-data/fetch-arena.ts`가 `prismatic-overrides.{ko,en}.json`을 머지해 생성
  (`fetch-arena.ts:188`). 따라서 **overrides + items 양쪽**을 함께 수정해 재fetch에도 유지.
- 단축 원칙: 능력치(스탯) 줄 유지 + 패시브를 핵심 1~2문장으로 요약, 부수 수치 스케일링 생략.
- HTML(`<mainText>`) 원본 항목들도 평문으로 통일해 23종 전부 override에 정의(전부 260자 이하).
- 파일: `prismatic-overrides.{ko,en}.json`(23키), `prismatic-items.{ko,en}.json`(23개 description).

### 4. 검수 페이지 재생성

- `node scripts/gen-arena-check.mjs` → `docs/arena-check.html` 갱신
  (증강 200 · 프리즘 23 · 특수 25 · 실버 67/골드 76/프리즘 57).

## 검증

- 교체 아이콘 8종 `_large.png` 모두 HTTP 200(GET, HEAD는 CDragon이 403 반환하므로 사용 금지).
- JSON 파싱 정상. augments ko=en=200, prismatic ko=en=23, id 세트 완전 일치.
- 검수 페이지에 "증강 없음" 사라짐, 교체 아이콘 반영 확인.
