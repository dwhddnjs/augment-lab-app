# 배포 전 수정 4건 + 클래식/데이터 관리 검수

## Context

`cddafd1`로 **클래식 드래프트**와 **데이터 관리 UI 개편**이 들어갔고 이제 배포를 준비한다.
배포 전에 (a) 눈에 걸리는 UI 결함 4건을 고치고, (b) 이번에 추가한 두 기능을 시뮬레이터에서
직접 굴려 검수한다.

수정해야 할 것:

1. `+` 오버레이의 클래식 아이콘(`history` — 되감기 시계)이 마음에 안 든다 → **`chess-rook`**(사용자 선택)
2. 메인 빌드 카드에 모드 구분감이 없다 — 필터를 바꿔도 카드가 똑같아 보인다 → 카드 우상단 모드 마킹
3. 빌드 상세에도 모드 마킹이 없다 → **챔피언 헤더 우측, 날짜 위**(사용자 선택)
4. 클래식 진입 시 알럿 → 모달 닫힘 → 가로 전환이 칼바람과 같은 타이밍으로 떨어져야 한다

## 사전 확인된 현황

- 모드 아이콘은 **SF Symbol이 아니라 `@expo/vector-icons/MaterialCommunityIcons`**.
  `chess-rook`은 설치된 glyphmap에 존재함(확인 완료).
- **모드 메타가 3중복 상태**다. 이번에 소비처가 2곳 더 늘어나므로 먼저 한 곳으로 모은다:
  | 항목 | 위치 |
  |---|---|
  | 아이콘 | [mode-select-overlay.tsx:23-32](src/components/navigation/mode-select-overlay.tsx:23) · [build-list-screen.tsx:74-81](src/features/builds/screens/build-list-screen.tsx:74) |
  | ko/en 라벨 | 같은 두 파일 (`mode-select-overlay.tsx:18-21`, `build-list-screen.tsx:50-52,61-63`) |
  | 모드 순서 | 오버레이 `[arena, classic, aram]`(FAB에서 가까운 아래부터) · 목록 `[aram, classic, arena]` — **의도적으로 다름** |
- 카드/상세 모두 `build.mode`가 이미 컴포넌트 안에 들어와 있어 **추가 prop이 필요 없다**.
- `HeroOverlay.chipBg`([theme.ts:191](src/constants/theme.ts:191))가 "날짜 칩 배경"용으로 정의만 되고
  **아무도 안 쓰는 상태** → 카드 배지 배경으로 그대로 재사용.
- 클래식 알럿은 이미 **가로 전환 전**에 뜬다([use-champion-select.ts:124](src/features/champions/hooks/use-champion-select.ts:124)).
  코드 순서상으론 칼바람과 동일 경로인데 체감이 다르다면 원인은 **iOS Alert dismiss 애니메이션과
  `lockAsync`의 경합**일 가능성이 높다 — 그래서 4번은 **재현 → 원인 확정 → 수정** 순서로 간다.
- 같은 함수에서 발견된 실제 버그 2건(아래 4번에 포함).

### 5. 클래식 알럿 → 가로 전환 타이밍 — [use-champion-select.ts](src/features/champions/hooks/use-champion-select.ts) **(요청 4)**

**먼저 시뮬레이터에서 현재 동작을 재현**한다(칼바람과 나란히 비교, 회전 시점·모달 잔상 관찰).
관찰 결과에 따라:

- **회전이 늦거나 안 걸리면** → 원인은 iOS `UIAlertController` dismiss 애니메이션 중
  `lockAsync`가 호출되는 것. Alert이 완전히 내려간 뒤 잠그도록 `askClassicRounds`가
  **dismiss 완료 후에 resolve**하게 고친다. 그러면 그 뒤 코드(`lockAsync` → `replace`)는
  칼바람과 **문자 그대로 동일한 경로**가 된다.
- **이미 정상이면** 그대로 두고 검증 문서에만 기록. (문서
  [2026-08-21-클래식-모드-추가.md:45](docs/verification/2026-08-21-클래식-모드-추가.md:45)가
  "가로 전환 **후** 다이얼로그"라고 적혀 있으나 최종 코드는 전(前)이다 — 이 스테일 기록도 바로잡는다.)

같은 함수에서 확인된 **실제 버그 2건을 함께 고친다**(이 함수를 어차피 건드리므로):
1. Alert을 버튼 없이 dismiss하면 `onPress`가 안 불려 Promise가 영원히 pending →
   `handleStart`가 await에 걸려 ✓ 버튼이 죽는다. `cancelable: false`로 막는다.
2. 중복 실행 가드 없음 — 알럿 대기 중 ✓ 를 또 누르면 알럿이 쌓인다. `useRef` 가드 추가.

## 검증 (`.agents/skills/verify/SKILL.md` 절차)

**타입체크·lint 통과는 검증이 아니다.** 앱을 띄워 관찰한 것만 기록한다.

빌드/실행: `attach` **먼저** → `xcodebuild`(workspace `ios/AugmentLab.xcworkspace`, scheme `AugmentLab`)
→ `simctl install` + `launch`. 네이티브 변경이 없으므로 prebuild/pod install 불필요.
좌표 환산 **`point = px × 0.4374`(가로·세로 동일 배율)** — 세로를 `874/1879`로 잡으면 44pt
글래스 버튼이 전부 빗나간다(과거 오진 사례).
