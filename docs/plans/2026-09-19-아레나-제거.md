# 아레나 모드 제거

## Context — 판단: 제거한다

1. **추가했던 이유가 이미 사라졌다.** 아레나는 "증강연구소에 콘텐츠가 부족해서" 넣었다(2026-06-24). 그 뒤로 클래식(08-21), 커스텀(08-26), 커스텀 아이템(08-28), 티어리스트(09-08), 티어리스트 아이템 추천(09-17)이 들어왔다. 콘텐츠 부족 문제는 이제 칼바람 쪽 기능으로 해결됐다.
2. **타겟이 다르다.** 앱의 정체성은 "칼바람 아수라장 증강"이다. 아레나 유저는 다른 모드의 다른 유저층이다. `tiers.ts` 주석에도 적혀 있듯이 아레나는 지표 자체가 다르다(승률이 아니라 8인 2인팀 평균 등수).
3. **충실도가 구조적으로 낮다.** 칼바람 드래프트는 실제 게임 흐름(3장 중 1픽 + 리롤)과 거의 1:1로 맞는다. 아레나 시뮬은 게임을 결정하는 변수를 뺀 채 돌아간다: 라운드 승패에 따른 골드, 2인팀 시너지, 전투 결과. 결과가 틀린 시뮬레이터는 아레나를 아는 유저에게는 신뢰를 깎고, 모르는 유저는 애초에 들어가지 않는다.
4. **유지 비용이 제일 크다.** TS/TSX 약 2.4k줄 + JSON 약 3.7k줄 + 별도 데이터 파이프라인(`fetch-arena.ts`) + 검수 페이지 3개 데이터셋 + 빌드 카드/상세 분기가 붙어 있다. 시즌이 바뀌어 규칙이 개편되면 `arena-rules.ts`/`use-arena.ts`/상점을 다시 짜야 한다. 가장 큰 기능이 가장 주변부 유저를 위한 것이다.
5. **지금까지 들인 20개 커밋은 매몰비용이다.** 판단 근거가 아니다. 분석 도구가 없어 사용량 근거도 없다. 사용량 데이터가 있었다면 유일한 반론이 될 수 있었다.

부수 효과: 모든 모드가 하나의 드래프트 플로우를 공유하게 된다. 따라서 `GameMode === DraftMode`가 되고, 빌드 카드·상세·프리워밍·챔피언 선택의 아레나 분기가 전부 사라진다.

→ 아레나 drawer UI 개선은 하지 않는다(제거로 대상이 사라짐).

## 사용자 데이터

- 기존 로컬 아레나 빌드는 **`readAll()`에서 `mode === 'arena'`를 걸러 버린다**. 백업 복원도 `reloadBuilds → readAll`을 거치므로 필터는 이 한 곳에만 둔다. 다음 저장/삭제 때 디스크에서도 빠진다.
- 아레나 데이터 없이는 그릴 수 없으므로 read-only 보존은 하지 않는다. 다음 버전 릴리즈 노트에 "아레나 모드 종료, 저장된 아레나 빌드 삭제"를 적는다.
