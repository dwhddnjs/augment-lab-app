## 배경

장인픽(그웬·벨베스)이 S로 올라오고 징크스 같은 주력픽이 빠져서 다른 집계 사이트와
어긋났다. 소스(aram.gg)가 이미 `stats.tier`(1~5)를 주고 다른 사이트는 전부 그 값을
쓴다는 걸 확인해, 우리도 그대로 쓰도록 바꿨다. 매핑은 `1+2→S / 3→A / 4→B / 5→승률로 C·D 반분`.

  `matchName` 로직은 이번 변경에서 건드리지 않았다.
- **문서 함정**: `.agents/skills/verify/SKILL.md` 가 존재하지 않는

### Steps

1. `orca emulator tap 0.5 0.012`(상태바)로 최상단 → S 배너 확인:

2. `orca emulator gesture` 로 C 섹션까지 스크롤 — 1차 버전(티어색 승률)에서 승률이
   픽률보다 어두운 것을 확인하고 accent 로 교체.
3. accent 적용 후 최상단 재확인: 승률 전부 민트, 픽률은 회색 유지, 카드 테두리는
   티어색 그대로.

### Findings

- `orca emulator gesture` 는 포인트에 `type`(`begin`/`move`/`end`)이 필요하다.
  `[{"type":"begin","x":0.5,"y":0.75},{"type":"move",…},{"type":"end",…}]` 형태여야 하고,
  begin→end 두 점만 주면 롱프레스로 먹힌다. 중간 `move` 를 3개쯤 끼우면 스와이프로 인식된다.
  1회 스와이프가 약 2화면 이동한다.
- 최상단 복귀는 스와이프 반복보다 상태바 탭(`tap 0.5 0.012`)이 확실하다.

### 데이터 — 12개 → 전량 123개

희귀도별 상위 4개(총 12개)만 담던 것을 챔피언당 전량으로 바꿨다. 증강별 소스 티어(1~4)도
같이 싣는다 — 카드의 S/A/B/C 배지가 그 값이다.

객체 배열(`{id, score, games, tier}`) 그대로 전량을 담으면 **1.33MB**가 된다(앱에서 가장 큰
데이터 파일이 217KB, 전체가 1.6MB인 걸 감안하면 과하다). 그래서:

- 증강 슬러그를 파일 상단 `augIds` 사전으로 빼고 행에는 **인덱스만** 싣는다
- 한 줄을 튜플로 눕힌다 — `[augIds 인덱스, 승률×10000, 소스 티어]`
- 판수(`games`)는 버린다. 새 카드가 쓰지 않는다(아이템은 객체 그대로, 판수 유지)

결과 **297KB**(155KB → 1.9배). 추정했던 450KB보다 작게 끝났다.

| 요소 | 색 |

펼침은 `useState` 하나다. 별도 라우트를 만들지 않았다.

### Findings

- **번들 반영 전에 캡처하면 옛 화면을 본다.** 처음 캡처에서 미리보기 6개 제한이 안 먹은
  것처럼 보였는데, 앱을 한 번 더 재시작하니 정상이었다. 구조가 바뀌는 변경은 재시작 후
  ax 라벨 수로 확인하는 편이 스크린샷 눈대중보다 확실하다.
- 소스의 증강 티어는 1~4 뿐이다(5 없음). `augTierOf()` 는 S/A/B/C 로만 매핑된다.
- 등급 정렬은 `sort((a, b) => a.tier - b.tier)` 한 줄이다. 행이 이미 승률 내림차순이고
  `Array.sort` 가 안정 정렬이라 같은 등급 안의 승률 순서는 저절로 남는다 — 2차 키가 필요 없다.
