# 첫 설치 프리웜 — 증강 폴백 주소 + 아이템 진열 풀만

- 날짜: 2026-09-19
- 기기: iPhone 17 Pro (iOS 26.5, 402×874 pt)
- 빌드: 기존 설치본 + 이 워크트리 Metro(JS만 변경)
- **Verdict: PASS**

## 무엇을 바꿨나

1. **증강 아이콘을 실제로 그려질 주소로 받는다.** 프리웜은 `_large` 한 주소만 받았는데, CDN에 HEAD로
   찍어 보니 모드 풀 증강 아이콘 206개 중 11개는 `_large` 가 404다(곰 투하·도란 열혈 팬·들이켜 등).
   화면(`AugmentImage`)은 이들을 base 로 폴백해 그리므로, 프리웜을 거쳐도 첫 표시 때 네트워크를 탔다.
   이제 프리웜 항목 하나가 폴백 주소 목록이고, `Image.prefetch` 가 `false`(404)면 다음 주소를 받는다.
   순서는 `AUGMENT_IMAGE_VARIANTS`(`ddragon.ts`) 하나를 화면과 프리웜이 같이 쓴다.
2. **아이템은 두 모드 진열 풀만 받는다.** 전체 목록 404개(협곡 254 · 클래식 150) → 진열 풀 192개
   (칼바람 111 · 클래식 81). 나머지 212개는 옛 빌드 조회에만 쓰인다.

## Steps

1. 앱 종료 → 이미지 캐시(`Library/Caches/com.hackemist.SDImageCache/default`, 815장)를 스크래치패드로
   옮겨 비우고, AsyncStorage 에서 `prewarm:done:*` 과 `builds:v1` 을 지웠다. 빌드를 비운 건 홈 카드가
   이미지를 불러와 캐시를 오염시키지 않게 하려는 것이다.
2. 앱 실행 → 설치 화면이 뜨고 캐시가 0 → 67 → … → 577장으로 늘었다. **약 55초** 뒤
   `prewarm:done:16.16.1` 이 찍히고 홈(빈 상태, 칼바람/클래식 세그먼트)으로 넘어갔다.
3. 앱과 같은 URL 빌더로 기대 주소를 만들어 캐시 파일(`md5(url)` + 확장자)과 대조했다:

   | 항목 | 캐시됨 |
   | --- | --- |
   | 챔피언 사각 | 172 / 172 |
   | 증강 아이콘(large 또는 base) | 206 / 206 |
   | └ `_large` 없는 11개의 base | **11 / 11** |
   | 진열 아이템 | 192 / 192 |
   | 진열 밖 아이템 | **0 / 212** |

   합계 172 + 6(역할 아이콘) + 206 + 192 = 576에 1장 차이다. 홈 화면이 그린 1장으로 보인다.
4. 앱 종료 → AsyncStorage(빌드 31개 · 프리웜 플래그)와 원래 캐시 815장을 되돌렸다. 재실행 후 홈에
   2026.9.18 · 9.17 · 9.4 섹션이 그대로 보였다.

## Findings

1. **기존 설치본엔 이번 수정이 닿지 않는다.** 완료 플래그가 ddragon 버전 키(`prewarm:done:16.16.1`)라
   이미 받은 사용자는 다음 버전 전까지 프리웜을 다시 돌지 않는다. 11개 base 는 처음 볼 때 받는다.
2. **프리웜한 이미지가 캐시에서 빠져 있었다(원인 추정, 미수정).** 수정 전 캐시에는 완료 플래그가
   있는데, 옛 방식이면 받았어야 할 진열 밖 아이템이 0 / 212였다. 남은 815장은 수정일이 8월 것도
   있지만 접근일은 전부 최근 4일 안이다. SDWebImage 기본 `maxDiskAge`(1주)가 접근일 기준으로
   만료시킨다면 설명된다(SDWebImage 소스로는 확인 안 함). 맞다면 첫 설치 프리웜은 일주일 넘게 안 본
   아이콘까지 붙잡아 두지 못한다.
3. 검증 중 실수: 백업 명령의 zsh 글롭(`$S/*`)이 "no matches found"로 실패해 `&&` 체인이 멈췄는데, 뒤의
   저장소 정리 스크립트는 별도 줄이라 실행돼 백업 없이 `builds:v1` 이 지워졌다. 이전 검증 때 남긴
   백업(같은 31개)으로 되돌렸다. 시뮬레이터 저장소를 만질 땐 백업을 먼저 확인하고 정리하는 한
   명령으로 묶을 것.
