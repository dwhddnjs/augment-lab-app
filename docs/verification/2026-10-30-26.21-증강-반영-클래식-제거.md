## 2차 — 흰 아이콘 10개를 게임 원본 컬러로 교체 (같은 날)

**문제**: 신규 10개 증강의 아이콘이 흰색으로 떠서 다른 증강들과 어울리지 않았다.

| 등급 | 증강 |
| --- | --- |
| 실버 | 푸른 방어막 |
| 골드 | 벌이다!!!, 붐 앤 베이스, 왕관의 무게, 장갑 충격, 전부 다 무너뜨려, 죽지 않아, 황홀한 나비 |
| 프리즘 | 묵직한 한 방, 죽음의 춤 |

**원인**
- CDragon(latest·PBE 모두)에는 이 10개의 `_large`·base 파일이 없다.
- 남은 `_small`(64px)은 그레이스케일 흰 실루엣이다. 다른 증강은 등급색 문양에 어두운 테두리가
  들어간 컬러 `_large`를 쓴다.

**1차 시도(폐기)**: `AugmentImage` small 단계에 등급색 `tintColor`를 입혔다.
- 사용자 피드백: "너무 튄다, 인위적이다".
- expo-image iOS는 tint 시 `.alwaysTemplate`으로 그려서, 불투명 픽셀을 밝기와 상관없이 단색으로
  칠한다. 원래 아이콘의 어두운 테두리와 밝은 문양 구분이 사라져 납작한 덩어리가 된다.
- 카드 테두리용 밝은 색(`#F2D98F` 등)을 썼던 것도 실제 문양 톤과 달랐다. 실측한 문양 톤은 골드
  `#E9D3B0`, 실버 `#ACC1C5`, 프리즘 `#F1DBF7`이다.
- 앱·검수 페이지 모두 되돌렸다.

**해결**: 다른 사이트처럼 게임 원본을 쓴다.
- 위키 `<이름>_mayhem_augment.png`(256px)를 받아 `assets/augments/`에 넣었다.
- `src/lib/ddragon.ts`의 `LOCAL_AUGMENT_ICONS` / `localAugmentIcon()`을 `AugmentImage`가 CDN보다
  먼저 쓴다. 첫 설치 프리웜과 드래프트 카드 프리페치는 이 10개를 건너뛴다(받을 게 없음).
- 검수 페이지는 같은 파일을 data URI로 심고 "앱 내장 ·" 표시를 붙였다.

**원본 검증**
- 양쪽에 다 있는 비전 원칙으로 위키 이미지와 CDragon `arcaneaxiom_large.png`를 비교했다.
  **RMSE 0**, 즉 픽셀 단위로 동일하다.
- 10개 모두 게임의 흑백 `_small` 옆에 나란히 놓고 같은 그림인지 눈으로 확인했다.
- 장갑 충격과 죽지 않아는 게임 데이터에서도 같은 그림이다(흑백 원본 md5 동일).

**앱 확인** (iPhone 17 Pro, Metro 재시작으로 번들 2059 → 2069 모듈)
- 커스텀 골드: 비전 원칙(CDN) · 장갑 충격 · 벌이다!!!(내장)가 한 줄에서 같은 톤으로 보인다.
- 커스텀 실버: 푸른 방어막이 죽음의 무도 업그레이드 · 과일화 · 가라앉은 자의 축복과 같은 회청 톤이다.
- 커스텀 프리즘: 죽음의 춤이 해악의 숫자 3 옆에서 같은 홀로그램 톤이다.
- 묵직한 한 방은 스크롤로 아이콘을 화면에 잡지 못해 검수 페이지 캡처로만 확인했다.

**프리웜**: 486 → 476장. 내장 10개를 받지 않는다.

**후속**: CDragon이 이 10개의 `_large`를 내면 `LOCAL_AUGMENT_ICONS`와 `assets/augments/`를 지운다.

- 로컬 아이콘 예외를 `augmentImageUrls` 한 곳으로 옮겼다. 내장 아이콘이면 빈 목록을 돌려주므로,
  프리웜과 드래프트 프리페치가 따로 거를 필요가 없다.
- `PickedDrawer`의 `slots` prop을 없애고 `ARAM_ROUNDS + 1`에서 슬롯 수를 계산한다.
- 영문 설명 3건에 빠진 내용을 채웠다: 튕기는 꿀벌(퀘스트 10/40/163회) · 붐 앤 베이스(2초에 걸쳐
  감소) · 모시핏 괴물(범위 증가).
- 나머지는 스크립트·문서만 바꿨다. 검수 페이지의 내장 아이콘 판정, ko 한글 검사, 패치 스크립트의
  nameId 우선 매핑과 개명 아이콘 리포트화, 죽은 토큰, 낡은 주석, lockfile 노이즈가 여기에 든다.

**Steps**
1. 앱을 실행했다. 저장소에는 빌드 31개(칼바람 20 · 클래식 11)가 있다.
   - ax 덤프로 센 홈 카드는 **31개**다. 2차까지는 20개였다.
2. 2026.8.28 섹션의 가렌을 봤다. 클래식 빌드이고, 저장된 아이템은 레트로 `773116` 하나다.
   - 카드에 증강 아이콘 2개만 있고 아이템 줄이 없다. 빈 칸이나 깨진 이미지는 없다.
   - 같은 섹션의 갈리오(클래식, 아이템 `3091` + 레트로 5개)는 증강 2개와 아이템 1개(마법사의 최후)를 그린다.
3. 가렌 카드 → 상세로 갔다.
   - 헤더, 날짜 2026. 8. 28., "증강 2"(적응형 능력치 · 육중한 힘)가 설명과 함께 보인다.
   - 아이템 섹션은 없고, 합산 스탯(체력 690 · 공격력 69 …)은 정상으로 그려진다.
4. 뒤로 → `+` → 칼바람 → 가렌 → 시작하기.
   - 가로 드래프트 `0 / 4`가 떴고, 카드 3장의 아이콘과 설명이 정상이다.
5. 픽 현황 서랍을 열었다. **"증강 0/5"**와 빈 칸 5개가 보인다(3+2).
6. 저장하지 않고 앱을 종료했다. 저장소를 백업과 `diff -r`로 대조했더니 **변화가 없다**.
   - 읽기만으로는 디스크를 다시 쓰지 않는다.
   - 다음 저장 때 클래식 11개는 `mode: 'aram'`으로 디스크에 써진다(`check-build-storage.ts` 5번이 확인한다).

**Findings**
- 살린 클래식 빌드는 날짜 섹션 안에서 칼바람 빌드와 구분되지 않는다. 모드 배지를 지웠기 때문이고,
  모드가 하나뿐이니 의도한 결과다.
- 아이템을 전부 레트로로 채운 클래식 빌드는 "증강만 있는 빌드"로 보인다. 원래 아이템을 되살리려면
  레트로 아이템 데이터를 다시 넣어야 하는데, 클래식 운영 종료(1월)를 앞두고 그럴 이유는 없다고 봤다.
- 내장 아이콘 프리웜 제외(476장)는 이번에 다시 재지 않았다. `augmentImageUrls`가 빈 목록을 주고
  프리웜이 빈 목록을 거르는 건 코드에서 확인했다. 장수 자체는 2차와 같다.
