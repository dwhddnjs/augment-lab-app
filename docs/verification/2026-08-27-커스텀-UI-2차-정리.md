# 커스텀 화면 UI 2차 정리 검증

- 날짜: 2026-08-27
- 기기: iPhone 17 Pro (iOS 26.5, `5FC3FF75-7D05-47F7-ABD9-E042378149AB`), Debug 빌드(dev client)
- 대상: `src/features/custom/**`

## 무엇을 바꿨나

**설정 드로어** — 증강 개수 섹션 제거, 챔피언 변경·선택 초기화 버튼 제거, 퀵모드 행 카드 제거,
섹션 제목 `caption`(12pt) / 행 글자 `footnote`(13pt)로 통일, "제목+컨트롤"을 한 행 안의
`VStack`으로 묶어 그룹 안팎 간격을 분리, 상단 여백 확보.

**커스텀 화면** — 챔피언 행 끝에 아이콘 버튼 2개(챔피언 변경 / 선택 초기화), 검색 필드를
높이 32의 리퀴드글라스 pill 로 축소, `SafeAreaView` 에서 `bottom` edge 제거 + 리스트
contentContainer 가 홈 인디케이터만큼만 띄우기, 헤더 좌우 여백 24 → 12, 우측 패널
`paddingHorizontal` 을 그리드 contentContainer 와 같은 8 로 맞춤.

증강 카드 4열은 한 번 넣었다가 **되돌렸다**(요청). 3열·원래 치수 그대로다.

## 관찰 결과 (PASS)

- **드로어 레이아웃**: 제목 아래 컨트롤까지 13pt, 그룹 사이 26~34pt — 픽셀로 재서 묶음이 갈린다.
  이전에는 둘 다 28~33pt 라 구분이 없었다. 퀵모드 뒤 카드 없음, 스크롤 인디케이터 없음,
  첫 섹션이 천장에서 52pt 아래.
- **드로어 컨트롤 폭**: 세그먼트·토글이 좌 32 / 우 30pt 로 대칭. `ignoreSafeArea="all"` 전에는
  오른쪽 60pt 를 못 쓰고 잘려 있었다(아래 Findings).
- **챔피언 행 버튼**: 사람↔사람 아이콘 탭 → 챔피언 변경 오버레이가 뜨고 갈리오가 선택 상태로 표시.
  휴지통 탭 → 담아둔 증강이 즉시 비워짐.
- **드래그 담기**: 카드 롱프레스(450ms) 후 우측 패널로 끌어 놓으니 "적응형 능력치"가 그대로 담김.
  `SafeAreaView` edges 를 바꿨어도 드롭 경계(`insets.left + leftW`)는 그대로다.
- **하단**: 그리드·우측 박스가 화면 맨 아래까지 내려가고, 마지막 줄은 홈 인디케이터에 안 물린다.
- **검색 필드**: 32pt pill, 글래스 림만으로 경계가 보이고 플레이스홀더 정상.
- **카드**: 3열 원래 크기로 복귀 확인(아이콘 72 / 이름 12 / 설명 8pt).

## 3차 수정 관찰 (PASS)

- **그리드 컨테이너 borderRadius 제거** — 위·오른쪽 경계가 각지게 떨어진다.
- **담은 목록 박스 하단 여백** — 좌우와 같은 8pt + 홈 인디케이터만큼 떠 있다.
- **드로어 섹션 제목** — `secondaryLabel`(시스템) 대신 테마 `text.secondary`.
- **드롭존 하이라이트** — 카드를 끌고 있는 동안 우측 박스가 민트 테두리 + `accent.subtle`
  배경으로 바뀌는 것을 드래그 도중 캡처로 확인(고스트는 아이콘만). 테두리 굵기는 1 고정이라
  강조가 켜져도 안쪽 목록이 밀리지 않는다.
- 드래그 중간 프레임은 `sleep N; simctl io screenshot` 을 4·6·8·10·12·14초로 여러 개 예약해두고
  마지막 지점에서 9초 버티는 `touch_path` 를 실행해 잡았다. 도구 왕복이 5초 안팎이라
  단발 예약으로는 매번 놓친다.

## 챔피언 변경 오버레이 (PASS)

- 시트가 화면 세로 한가운데(위 55 / 아래 58pt). `SafeAreaView` edges 에서 `top`·`bottom` 을
  빼야 대칭이 된다 — 가로 모드의 홈 인디케이터 21pt 를 먹으면 그만큼 위로 쏠린다.
  가로 inset(노치)은 남긴다.
- 닫기 ✕ 흰색, 검색 입력과 16pt 간격.
- 챔피언 그리드가 시트 하단까지 흘러 다음 줄이 잘린 채 이어진다(스크롤 여지가 보인다).
  시트 `paddingBottom` 과 `gridContent.paddingBottom` 을 둘 다 없애고 `overflow: hidden` 으로
  모서리만 잘랐다.

## Findings

1. **`Host` 가 창의 안전영역을 물고 들어온다.** 드로어가 화면 trailing 끝에 붙어 있어 SwiftUI
   콘텐츠가 오른쪽 약 60pt 를 쓰지 못했다(가로 모드의 노치 inset 폭과 같다). `ignoreSafeArea="all"`
   로 해결. RN 쪽 `SafeAreaView` 가 이미 top/bottom 을 처리하므로 중복도 아니다.
2. **`Host` 의 RN style padding 은 SwiftUI 콘텐츠를 밀지 못한다.** 부모 `View` 에 padding 을 줘도
   마찬가지였다. 여백은 SwiftUI 쪽(`padding` 모디파이어)이나 `List` 의 기본 인셋에 맡겨야 한다.
3. **`VStack` 은 제안 폭을 자식에게 강제하지 않는다.** 세그먼트 Picker 가 제 글자 폭까지 쪼그라든다.
   `frame({ maxWidth: 10000 })` 도 안 먹었다. `List` 행 안에 넣으면 행 폭을 받아 제대로 펴진다 —
   드로어를 순수 `VStack` 으로 짜려던 걸 되돌리고 `List` 를 유지한 이유.
4. **`matchContents={{ vertical: true }}` 는 가로도 건드린다.** 세로만 켰는데 콘텐츠가 이상적인
   가로 폭으로 측정돼 드로어 밖으로 16pt 씩 삐져나왔다. 쓰지 않는다.
5. `numColumns` 를 고친 뒤에는 fast refresh 가 아니라 **리로드**가 필요하다(RN 이 레드박스로
   `Changing numColumns on the fly is not supported` 를 띄운다). 코드 문제는 아니다.

## 한계

시뮬레이터 터치 주입 좌표는 **세로 기준(402×874)** 이라 가로 화면 좌표를
`portrait = (402 - app_y, app_x)` 로 변환해야 한다. 이걸 모르면 탭이 엉뚱한 곳에 떨어져
"버튼이 안 눌린다"로 오진하기 쉽다(실제로 초반에 그렇게 헤맸다).

## 프리즘 컬러 토큰 밝게 (PASS)

`AugmentRarityColors.prismatic` 의 `border`/`badge` 를 `#C6A1FF` → `#E0D6FF`,
`glow` 를 같은 값의 45% 로 올렸다(gradient 는 이미 밝은 무지개라 유지).

시뮬레이터(iPhone 17 Pro / iOS 26.5, `5FC3FF75-…`) `/custom` 프리즘 필터 화면에서
확인한 반영 지점 — 좌측 티어 레일의 선택 상태(아이콘·라벨), 담은 목록 행의 증강
이름·좌측 rarity 바, `AugmentTile` 테두리. 진보라 → 밝은 라벤더로 바뀌어 어두운
배경 위 작은 글자의 탁한 느낌이 사라졌다. 카드 프레임(`rarity-card-frame.tsx` 의
`RARITY`)은 별도 팔레트라 그대로 — 프레임 자체가 이미 무지개라 영향 없음.

## 코드 리뷰 지적 15건 반영 (PASS)

리뷰에서 나온 15건을 모두 고치고 시뮬레이터에서 재확인했다.

- **희귀도 색 모드 분기** — `AugmentRarityColors` 에서 실제로 읽히는 값은 `border`
  하나뿐이었다(`gradient`·`glow`·`badge`·`badgeText` 는 참조 0건 → 삭제).
  다크 팔레트는 그대로 두고 라이트 짝(`AugmentRarityColorsLight`)을 추가한 뒤
  `useRarityColors()`(`src/hooks/`)로 고르게 했다. 밝은 배경 위에 색을 올리는
  6곳(aram picked-drawer, arena summary·drawer, builds augment-list, items
  augment-card, custom selected-panel·tier rail)을 훅으로 전환.
  `AugmentTile` 만 예외 — 모드 무관 어두운 타일을 깔아서 다크 값을 직접 쓴다.
- **키보드 탭 소비** — 증강 그리드와 담은 목록 FlatList 에
  `keyboardShouldPersistTaps="handled"`. 검색 직후 첫 탭/롱프레스가 먹힌다.
- **하단 인셋 일원화** — 화면이 `insets.bottom` 을 재서 두 리스트에 `bottomInset`
  prop 으로 내려보낸다. 담은 목록은 `listContent` 에서 띄우므로 박스의
  `marginBottom: Spacing.two`(요청값)는 그대로다.
- **드롭 강조가 위치 기반** — `useAnimatedReaction` 으로 `ghostX` 가 `dropBoundary`
  를 넘나들 때만 JS 로 알린다(매 프레임 아님). 좌측에서 놓으면 강조되지 않는다.
- **챔피언 행 항상 렌더** — 챔피언을 못 찾아도 변경·초기화 버튼이 남는다.
- 그 밖에: 증강 그리드 빈 결과 문구, `add()` 중복 판정을 `prev` 기준으로,
  `TIER_ICONS` 키 타입 좁히기, 시트를 `GlassSurface` 로, `cell` 폭 하한,
  검색 필드 간격을 토큰 값으로, 헤더 좌우 12 → 8(본문과 통일), 풀 순회 1회로.

시뮬레이터(iPhone 17 Pro / iOS 26.5) 확인: 커스텀 화면 정상 렌더, 헤더 좌우가
본문과 맞음, 챔피언 변경 오버레이가 글라스 시트로 뜨고 뒤 화면이 은은히 비치되
목록 가독성 유지. 라이트 모드는 앱 자체 테마 설정을 따르므로
`simctl ui appearance` 로는 전환되지 않아 여기서 확인하지 않았다 — 라이트 값은
흰 배경 대비 5:1 이상으로 계산해 잡았다.
