## Findings

### 1. 클래식 진입이 **영구 정지**했다 — 이번 검수의 본체 (수정함)

`+` → 클래식 → 챔피언 → ✓ → "예"를 누르면 챔피언 선택 모달이 **가로로 누운 채 화면 절반이
검게 남고 거기서 멈췄다.** 드래프트로 영영 넘어가지 않는다. 칼바람은 같은 코드 경로인데 멀쩡했다.

원인은 알럿이었다. 시뮬레이터 로그를 보면 회전 자체는 **성공한다**:

```
04:20:51.815  Scene updated orientation preferences: ( Pu Ll Lr ) -> ( Pu )    ← 알럿 dismiss 시작
04:20:52.233  Scene updated orientation preferences: ( Pu Ll Lr ) -> ( Ll Lr ) ← lockAsync 적용
04:20:52.303  Scene will change interface orientation: landscapeRight (3)      ← 실제 회전
```

회전은 걸렸는데 **`lockAsync`의 Promise가 resolve되지 않는다.** `handleStart`가 그 await에
걸려 `router.replace`가 영영 실행되지 않은 것. 알럿 dismiss 트랜지션이 진행 중일 때 잠그면
scene geometry 업데이트 완료 콜백이 유실된다.

두 겹으로 고쳤다:

- `askClassicRounds`가 **dismiss가 끝난 뒤에 resolve**한다(`ALERT_DISMISS_MS = 300`).
  그러면 `lockAsync`가 정상 resolve하고, 그 뒤 코드는 칼바람과 **문자 그대로 동일한 경로**가 된다.
- 그래도 못 받는 경우를 대비해 `lockOrientation()`이 `Promise.race`로 700ms 타임아웃을 건다.
  회전은 잠금 요청 시점에 이미 걸리므로 완료 통보를 못 받아도 진행해도 안전하고,
  각 드래프트 화면의 `useFocusEffect` 재잠금이 최종 방어선이다.

**같은 데드락 클래스가 두 곳 더 있었다** — `item-select-screen.tsx:217`, `arena-screen.tsx:226`.
둘 다 세로 복귀를 await한 뒤 `dismissTo("/")`를 부른다. 한 곳만 막지 않고 세 호출부를
공용 헬퍼로 통일했다. 아레나 종료 경로를 실제로 굴려 세로 복귀가 정상임을 확인했다(Step B-14).

### 2. 아이템 선택 화면에서 챔피언 역할 태그가 영어로 샜다 (수정함)

한국어 상태인데 좌하단 패널이 `Tank · Mage`로 나왔다. `item-detail-panel.tsx`가
`champion.tags.join(" · ")`로 **원본 id를 그대로** 찍고 있었다. 이미 있는
`CHAMPION_TAG_LABELS` + `useTranslation`을 붙여 `탱커 · 마법사`로 고쳤다
(빌드 상세·picked-drawer가 쓰던 그 관례). 클래식 검수 중에 눈에 띈 것이지 클래식 전용 버그는 아니다 —
칼바람·아레나 아이템 화면에서도 똑같이 새고 있었다.

### 3. 모드 메타가 3중복이었다

아이콘·라벨이 `mode-select-overlay.tsx`와 `build-list-screen.tsx`에 각각 사본으로 있었다.
이번에 소비처가 카드·상세 2곳 더 늘어나 5중복이 될 참이라 `src/constants/game-modes.ts`로 먼저 모았다.
덕분에 클래식 아이콘 교체가 **한 줄**로 끝났고 네 화면에 동시에 반영됐다.
모드 순서는 홈(칼바람→아레나)과 오버레이(FAB에서 가까운 아래부터)가 **의도적으로 반대**라
오버레이가 `[...GAME_MODES].reverse()`로 뒤집어 쓴다.

### 4. 카드 배지에 쓸 토큰이 이미 있었다

`HeroOverlay.chipBg`가 "날짜 칩 배경"용으로 정의만 되고 아무도 안 쓰고 있었다. 새 색을 만들지 않고 재사용했다.
카드 안은 라이트/다크 무관하게 어두운 splash 위라, 배지도 테마 토큰이 아니라 이 고정 톤을 써야 라이트에서 안 날아간다.

### 5. 알럿 응답 후 회전까지의 300ms 동안 ✓ 가 계속 눌린다

수정으로 생긴 창이다. 가드가 없으면 `router.replace`가 두 번 나가 드래프트가 겹쳐 뜬다.
`useRef` 재진입 가드를 넣었다. (iOS에서 UIAlertController가 떠 있는 동안은 터치가 막히므로
알럿이 **떠 있는** 중의 중복 탭은 원래 불가능하다 — 문제는 알럿이 닫힌 **뒤**의 공백이다.)

### 6. 레트로 아이템이 여러 탭에 동시에 샜다 (재분류)

지정받은 19건의 **현재 상태를 먼저 계산해 보니 18건이 전부 틀려 있었다.** 유형이 둘이었다:

- **중복 노출(11건)** — `Aura`/`SpellVamp`/`ManaRegen` 태그가 붙었다는 이유로 서포터 탭에 같이 걸렸다.
  심연의 홀·얼어붙은 심장·마법공학 총검·슈렐리아의 몽상·지휘관의 깃발·일라이자의 기적 등이
  `마법사+서포터` / `탱커+서포터`처럼 두 탭에 동시에 나왔다.
- **엉뚱한 탭(7건)** — 삼위일체가 `원거리딜러+마법사`(CriticalStrike·SpellDamage 태그 때문),
  아트마의 창이 `원거리딜러`, 최후의 속삭임이 `암살자`, 얼어붙은 건틀릿이 `마법사`,
  리글의 랜턴·야생의 섬광·도마뱀 장로의 영혼이 `전사`로 잡혔다.

레트로 태그는 현대 태그 규칙과 어긋나서 추론이 구조적으로 안 맞는다. 진열되는 레트로
아이템은 태그에 맡기지 않고 **전부 손으로 지정**하는 쪽으로 방침을 바꿨다(36건).

남은 것: `얼음 정수의 파편`·`고대인의 의지` 2건이 아직 `마법사+서포터`로 중복 노출된다.
지정 목록에 없어 임의로 정하지 않고 남겨 뒀다. 어느 탭에도 안 걸리는 아이템은 0건.

### 7. 세그먼트 슬라이드 애니메이션 (수정함 — 두 번 고쳤다)

**1차: `withTiming` 을 `useAnimatedStyle` 안에서 부르고 있었다.**
Reanimated 4.3.1 + React Compiler 조합에서 이 패턴은 worklet 이 새 값으로 다시 돌긴 해도
(그래서 pill 위치는 맞게 바뀐다) **보간 없이 순간이동한다.** duration 을 8초로 늘려도
중간 프레임이 한 장도 안 잡혔다. 애니메이션을 shared value 로 빼고 `useAnimatedStyle` 은
읽기만 하도록 바꾸니 8초/1초에서 중간 프레임이 잡혔다.

**2차: 그런데도 "한 칸 이동은 여전히 애니메이션이 없다"는 리포트가 왔다.**
칼바람→아레나(두 칸)는 보이는데 아레나→클래식/칼바람(한 칸)은 안 보인다는 것.

처음엔 "카드 목록 재렌더가 UI 스레드를 수백 ms 막아 애니메이션을 삼킨다"고 봤다.
프레임 캡처에서 탭 직후 첫 프레임의 pill 이 이미 85% 지점에 있었기 때문이다.
**이 추론은 틀렸다.** `simctl io screenshot` 은 한 장에 ~150ms 걸리고 캡처 루프 자체가
시뮬레이터를 붙잡는다. 85% 는 앱의 멈춤이 아니라 **샘플링 지연**이었다.

화면에 실측값을 찍어 확인했다(탭 → 목록 커밋 → 첫 페인트):

| 구성 | js | paint |
| --- | --- | --- |
| 그대로 | 87ms | **111ms** |
| `useDeferredValue` + `initialNumToRender=3` 등 추가 | 45ms | 80ms |

즉 커밋은 **~110ms** 이지 수백 ms 가 아니다. 리스트 최적화는 30ms 를 줄일 뿐
문제의 원인이 아니어서 **되돌렸다**(목록 동작만 바뀌고 값을 못 한다).

진짜 원인은 **애니메이션 시작 시점**이었다. press 시점에 걸면 그 ~110ms 커밋이
애니메이션 시간에서 그대로 깎인다. 목록이 비는 아레나로 갈 때는 커밋이 싸서 온전히
보이고, 카드가 있는 모드로 갈 때는 앞부분이 잘린다 — **리포트된 방향 비대칭과 정확히 일치**한다.
그래서 시작을 커밋 이후(`useEffect`)로 두어 어느 방향이든 전체 구간이 보이게 했다.
그리고 한 칸 이동(트랙의 1/3)이 눈에 읽히도록 **200ms → 280ms** 로 올렸다.
상단 세그먼트와 헤더 토글이 `progress` shared value 하나를 공유하도록 묶어 둘이 항상 같이 움직인다.

**측정의 한계(솔직히)**: 280ms 자체가 보간되는 프레임은 이 도구로 못 잡았다.
`simctl io screenshot` 샘플링(~150ms)이 280ms 애니메이션을 분해할 수 없고 ffmpeg 도 없다.
근거는 (a) 8초·1초에서 보간이 확인됐고 (b) 커밋이 110ms 로 실측됐다는 두 가지의 결합이다.
최종 체감은 사람 눈으로 확인해야 한다.

### 7-1. 움직이는 인디케이터가 **네이티브 글래스**여서 끊겼다 (수정함)

280ms 로 올린 뒤에도 "이동이 뚝뚝 끊긴다, 스크롤 헤더 쪽은 더 심하다"는 리포트.

원인은 **움직이는 물체가 `GlassSurface`(= iOS 26 네이티브 `GlassView`)** 였다는 것.
리퀴드글라스는 뒤 배경에 대해 굴절/블러를 매 프레임 다시 계산하는데, 그걸 `translateX`
로 움직이면 배경이 계속 바뀌어 프레임을 떨군다. 헤더 토글이 더 심했던 건 그쪽이
**네이티브 헤더(그 자체가 글래스) 위에 글래스를 겹쳐** 움직였기 때문이다.

둘 다 단색으로 바꿨다. 원래도 위에 `accent.subtle` / `glass.fill` 을 덮고 있어서
글래스가 시각적으로 드러나지도 않았다 — 비용만 내고 있었다.
**정지해 있는 트랙은 글래스 유지**(움직이지 않으므로 재계산이 없다).

design-system 스킬의 "본문·고밀도 영역에 글라스 남발 금지(성능)"가 가리키던 사례가 이것이다.
**움직이는 표면에는 글래스를 쓰지 않는다** 를 규칙으로 추가할 만하다.

덤으로 카드 splash 에 `recyclingKey` + `cachePolicy="memory-disk"` 를 달았다.
필터를 오갈 때마다 splash 를 다시 디코드하면 그 완료가 슬라이드 도중에 떨어져 프레임이 튄다.

### 8. 아레나 세그먼트가 안 눌리는 건 앱이 아니라 dev-client FAB였다

"클래식에서 아레나로 전환이 안 된다"를 재현해 보니 **모드와 무관하게** 아레나 세그먼트가
안 먹었다. 좌표를 바꿔 가며 찍어 원인을 좁혔다:

| 탭 좌표(pt) | 결과 |
| --- | --- |
| (290, 195) | ✅ 전환됨 |
| (321, 190) | ✅ 전환됨 |
| (321, 206) | ❌ 무반응 (2회) |

같은 x인데 y가 16pt 아래면 죽는다. 바로 아래 (360, 258)에 **expo dev-launcher의 톱니 FAB**가
떠 있고, 이 버튼의 pan 영역이 보이는 원보다 위로 넓다. 아레나 라벨 중앙이 정확히 그 영역에
걸려서 "아레나만 안 눌린다"로 보였다. **릴리스 빌드에는 이 FAB가 없다 — 앱 코드 문제가 아니다.**
(verify skill에 이미 "dev-launcher FAB가 헤더 우측 버튼을 덮는다"고 적혀 있던 함정의 다른 얼굴)

### 9. 범위 밖 — 손대지 않고 기록만

- `settings-row.tsx`가 `onPress`만 있으면 무조건 chevron을 붙여, 화면 이동이 아닌 시트/알럿 행에도 `>`가 뜬다.
  (`2026-08-21-데이터-관리-ui-개편.md` Finding #2에 이미 기록된 미수정 건 — 이번에도 그대로 재현)

### 10. `지크의 전령`이 데이터에는 **개명 전 이름**으로 들어 있다

지정 목록 19건 중 이것만 이름 매칭이 안 됐다. 클래식 데이터 전체에 `지크`가 들어간 이름이 없다.
사용자가 아이콘을 직접 보여 줘서 확정했다 — `773050`, 데이터상 이름은 **`스타크의 열정`**
(Stark's Fervor)이다. Riot이 나중에 Zeke's Herald(지크의 전령)로 개명했는데
map453 bin이 개명 전 이름을 들고 있다. `서포터` → `전사`로 바꾸고, 나중에 또 못 찾는 일이
없도록 매핑 줄 주석에 두 이름을 같이 적어 뒀다.

**이름으로 못 찾으면 아이콘으로 찾아야 한다.** DDragon에서 `{id}.png`를 받아 눈으로
대조하는 게 확실하다 — 레트로 세트는 이런 개명 케이스가 더 있을 수 있다.

또 `행운 피크`(773098)는 데이터에는 있으나 **진열 풀(81개) 밖**이라 화면에 안 나온다.
지정대로 `서포터`로 매핑은 해 뒀다(풀에 들어오면 바로 적용된다).

## 함정 메모

- **알럿 직후의 `lockAsync`는 믿을 수 없다.** 회전은 되는데 Promise가 안 온다.
  orientation 잠금을 await한 뒤 navigation하는 코드는 전부 타임아웃을 끼워야 한다.
- 이 정지는 **로그에 에러가 한 줄도 안 남는다.** `Scene will change interface orientation`까지
  정상으로 찍히고 그 뒤가 조용하다. 화면이 멈춘 걸 눈으로 보고 "칼바람은 되는데 클래식은 안 된다"로
  좁히지 않았으면 못 찾았다. **대조군을 돌리는 게 로그를 뒤지는 것보다 빨랐다.**
- 시뮬레이터 파일 앱이 비어 복원 왕복을 못 돌 뻔했다.
  `.alab`을 `Containers/Shared/AppGroup/<id>/File Provider Storage/`에 직접 복사하면 피커에 바로 뜬다.
- 복원 검증은 **일부러 다른 개수의 구버전 백업**을 골라야 의미가 있다. 같은 파일로 복원하면
  전후가 똑같아 "교체가 실제로 일어났는가"를 구분할 수 없다.
