# 모드 세그먼트/헤더 토글 애니메이션 끊김 수정 검증

- 날짜: 2026-08-25
- 기기: iPhone 17 Pro (iOS 26.5, `5FC3FF75-7D05-47F7-ABD9-E042378149AB`), Debug 빌드
- 대상: `src/features/builds/screens/build-list-screen.tsx`

## 증상

칼바람/클래식/아레나 세그먼트와 스크롤 헤더 토글이 "이동"이 아니라 뚝뚝 끊겨 보임.
헤더 토글 쪽이 더 심함.

## 원인

1. **목록 커밋이 애니메이션과 같은 구간에서 일어남.** 모드를 바꾸면 SectionList 셀이
   통째로 갈리는데(챔피언 스플래시 포함) 그 커밋이 UI 스레드를 잡아 이동 중 프레임을 먹었다.
   기존 코드는 `setMode` 커밋 **이후** `useEffect`에서 애니메이션을 시작해, 커밋과 이동이
   정확히 겹쳤다.
2. **활성 라벨 굵기가 500↔700으로 바뀜.** 전환마다 글자 폭이 달라져 텍스트 레이아웃을 다시 잡았다.
3. **헤더 토글이 트랙 너비를 `onLayout`으로 잼.** 스크롤로 토글이 등장하는 첫 프레임에
   `trackWidth`가 0이라 원이 왼쪽으로 튀었다가 제자리를 찾았다 — 헤더 쪽이 더 심했던 이유.

## 수정

- `progress` shared value를 선택 위치의 단일 출처로 삼고 **press 즉시** `withTiming` 시작.
  목록 필터(`setMode`)는 `withTiming` 완료 콜백에서 `runOnJS`로 호출 → 애니메이션 구간에 커밋 0.
- 라벨/아이콘 색을 `mode` state가 아니라 `progress` 거리 기반 `interpolateColor`로 파생
  (커밋을 기다리지 않고 즉시 물듦). 굵기는 `Typography.label`(600) 고정.
- 헤더 토글 세그먼트 너비를 상수(`HEADER_SEG = 34 + Spacing.two`)로 고정, `onLayout` 제거.

## 관찰 결과

- 상단 세그먼트 칼바람→아레나→칼바람: pill 이동·라벨 색 전환·목록 교체 모두 정상. 레드박스 없음.
- 스크롤로 헤더 토글 등장: 원이 **첫 프레임부터 눈송이 위에 정확히** 위치(과거의 좌측 점프 없음).
- 헤더 토글 아레나→칼바람→클래식: 원 이동·아이콘 하이라이트·목록 교체 정상.
- **커밋 분리 확인**: duration을 임시로 8000ms로 올려 탭했더니, 원은 이동 중이고 아이콘은 이미
  아레나가 민트인데 **목록은 여전히 칼바람(갈리오/갱플랭크)** 이었고, 이동이 끝난 뒤 스크린샷에서야
  아레나(진)로 교체됐다. 의도한 순서(이동 → 완료 → 목록 교체)가 그대로 관찰됨. 이후 260ms로 원복.

## 한계

스크린샷 왕복이 1초 이상이라 260ms 구간의 중간 프레임은 도구로 캡처할 수 없다.
"부드러움" 자체는 눈으로 봐야 하며, 여기서 확인한 것은 위 순서와 최종 상태다.
시뮬레이터 Debug 빌드는 iOS 26 글래스 렌더가 실기보다 무겁다는 점도 감안할 것.
