# 1.6.1 출시 후 수정 — 저장 전환 흔들림·빈 화면 원인 확정 외 4건

- 날짜: 2026-11-23
- 기기: iPhone 17 Pro 시뮬레이터 (iOS 26.5, `5FC3FF75-7D05-47F7-ABD9-E042378149AB`)
- 빌드: **Release** 시뮬레이터 빌드(dev client 없음). 측정 빌드에만 PostHog·Sentry 를 껐다(테스트 세션이 실제 지표에 섞이지 않게).
- **Verdict: PASS** (실기기는 미검증 — 아래)

## 왜 Release 로 봤나

Debug 는 dev client 의 떠 있는 도구 버튼이 **별도 UIWindow** 다. 그 창이 회전을 좌우해 나가기 뒤 홈이 가로로 남는 등 앱에 없는 증상이 섞였다.
Release 에서는 재현되지 않았다.

## 2. 저장 → 빌드 상세 — 흔들림과 빈 화면은 한 문제의 양면

### 첫 수정이 틀렸다 (빈 화면이 돌아왔다)

처음에는 RNS 패치로 `'none'` push 를 `animated:NO` 로 바꿨다(부하 재현 5/8 → 0/16). 회전 로그만 봐서 흔들림이 사라진 것만 확인했다.
그런데 화면 밝기로 다시 재 보니 저장 직후 **#1C1C1E 빈 화면이 약 0.4초** 있었다(25프레임). 사용자가 직접 써 보고 짚었다.
그래서 패치를 걷어내고 원인을 다시 쟀다. 측정은 영상 프레임 밝기(빈 화면), JS `Dimensions` 순서(회전 횟수), 네이티브 임시 로그(닫기 시작·완료, push 완료, 메인 스레드 정지)를 **함께** 봤다.

### 확정 원인

- **빈 화면:** 챔피언 시트(pageSheet)가 낀 모달 묶음을 애니메이션 없이 닫으면, iOS 가 약 0.25초를 기다렸다가 닫기를 끝낸다. 그동안 화면을 비운다.
  - 묶음을 둘로 나눠 닫아 보니 단계별로 갈렸다. 시트 위 전체 화면 모달은 6ms, 시트는 247ms 였다.
  - 그 사이 메인 스레드 정지는 없었다. 회전을 막아도(가로 잠금), push 를 미리 끝내 놔도, `performWithoutAnimation` 으로 감싸도 똑같았다.
- **빈 화면이 1.6.1 에 없던 이유:** 같은 순간 루트 스택에서 빌드 상세 push 전환(`'none'` 도 전환이다)이 진행 중이면, 시트가 기다림 없이 약 9ms 만에 닫힌다.
- **흔들림:** 그 push 전환은 빌드 상세 첫 렌더 동안 메인 스레드가 바빠 늦게 끝난다. 그 전에 세로 회전이 시작돼 먼저 끝나면, iOS 가 가로로 되돌렸다가 다시 세로로 돌린다(PLP).
  - 회전 뒤 홈 스택 재생성까지 겹치면 push 완료가 +380~460ms 까지 밀렸다.
- 결국 1.6.1 은 진행 중인 push 덕에 빈 화면이 없었고, 같은 push 때문에 흔들렸다. 내 첫 패치는 push 를 없애 흔들림을 지웠지만 빈 화면을 되살렸다.

### 수정

- push 는 1.6.1 그대로 `'none'` 전환으로 둔다. RNS 패치와 patch-package 는 걷어냈다.
- 저장으로 닫기 직전 `lockAsync(LANDSCAPE)` 로 가로를 붙잡는다. 빌드 상세 `transitionEnd`(= push 전환 끝)에서 세로로 푼다(`src/lib/orientation.ts`).
  - 회전은 진행 중인 전환이 없을 때만 시작된다. 그래서 흔들림이 구조적으로 생길 수 없다.
  - 신호가 끝내 오지 않으면 1.5초 뒤 그냥 푼다(가로에 갇히지 않게).
- 나가기는 애니메이션 없이 닫으면 같은 0.25초 빈 화면이 난다. 그래서 페이드로 닫는다.
  - 시트 값은 나가기 확인창이 뜨는 순간 fade 로 바꾸고, 취소하면 cut 으로 되돌린다(`useCloseDraft.confirmExit`). 누르는 순간 바꾸던 경합이 없다.

### 함께 고친 경합 — 시트 닫힘 방식(1.6.1 기준선에서 재현)

1.6.1 은 저장 순간에 시트에 `close=cut` 을 걸고 2프레임 뒤 닫았다. 기준선 실행 중 그 값이 닫힘보다 늦어 **페이드로 닫힌 회차**가 나왔다(`dismiss animated=1`). 그 회차는 빌드 상세가 가로로 보였다가 돌았다.
이제 드래프트를 띄울 때 `close=cut` 을 미리 건다. 수정 회차는 전부 `animated=0` 이었다.

## 4. 커스텀 진입 시 위아래 흔들림

측정 방법: `measureInWindow`·inset 로그(임시). 측정된 inset 변화는 다음 순서였다.

- 회전 직후 약 0.2초: 좌우 62·아래 20 으로 바뀐다. 위는 아직 62 다.
- 약 1초: 상태바가 다 숨은 뒤에야 위가 0 이 된다.

1.6.1 은 가로 크기만 보고 그렸다. 그래서 헤더가 위 inset 62 만큼 내려와 있다가 약 1초 뒤 올라갔다. 사용자 제보("위에 공간이 있다가 없어짐")와 같다.

| | 처음 그린 시점 | 그때 헤더 y | 이후 |
|---|---|---|---|
| 크기만 보는 게이트(예전 동작) | 회전 직후 | 62 | 위 inset 0 이 되며 위로 이동 |
| 새 게이트 | 약 0.18초 | 0 (최종) | 변화 없음 |

새 게이트의 동작은 다음과 같다.

- 가로 화면(커스텀·아이템 선택)은 위 inset 을 쓰지 않는다. iPhone 가로는 위가 항상 0 이다.
- 좌우 inset 이 생겼거나(Face ID 기종), 아래가 0 이면(홈 버튼 기종) 그린다.
- 1.6.1 은 커스텀 진입에 빈 화면이 약 0.25초 있었다. 지금은 0.18초다.
- 녹화 영상에서도 첫 정착 프레임 이후 프레임 간 차이가 0 이다. 회전 중 2~3 프레임은 recordVideo 왜곡이라 근거로 쓰지 않았다.

## 3. 리뷰 다이얼로그

- 첫 설치 후 2번째 빌드 저장에서 빌드 상세가 자리 잡은 뒤(약 1초) iOS 별점 다이얼로그가 떴다. 기기를 가로로 둔 채였는데도 화면은 세로를 유지했다.
- 3번째 이후 저장에서는 뜨지 않았다(`review:requested`).
- `expo-store-review` 는 **56.0.3 으로 고정**했다. 56.0.4 는 설치된 `expo-modules-core`(56.0.17)에 없는 `SceneGeometry` 를 써서 iOS 빌드가 실패한다. Expo SDK 패치를 올리면 풀어도 된다.

## Findings

- **RN `Alert` 는 자기 UIWindow 를 띄워 key window 가 된다.** 루트 VC 는 그냥 `UIViewController`(거꾸로 빼고 전부)다.
  - 기기 방향이 세로(회전 잠금 포함)면 드래프트의 나가기 확인창이 뜨는 동안 화면이 세로로 돌았다가 닫히면 가로로 돌아온다.
  - 이번 범위 밖이라 고치지 않았다. 고치려면 RN 패치나 커스텀 확인 UI 가 필요하다.
- 홈 시작 중복 탭 가드는 시트를 취소한 직후에도 정상이다(스크립트 버그로 의심했다가 확인).

## 미검증

- **실기기.** 같은 빌드에서 붙잡기만 끈 A/B(부하 7/8 흔들림 → 0/10)로 메커니즘을 확인했지만, 실제 폰을 손에 들고 본 것은 아니다.
  - 실기기에서 빌드 상세 첫 렌더가 더 느리면, 가로로 놓인 빌드 상세가 보이는 시간(시뮬레이터 약 0.13초)이 그만큼 길어진다. 흔들림·빈 화면은 생기지 않는다.
- 다크 모드 빈 카드.
