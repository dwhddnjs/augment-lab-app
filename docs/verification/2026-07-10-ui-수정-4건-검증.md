- **날짜**: 2026-07-10
- **Verdict**: ✅ **PASS**
- **환경**: Xcode 26.5 / iPhone 17 Pro (iOS 26.5) 시뮬레이터 / `npx expo run:ios` 네이티브 debug 빌드

요청받은 수정 4건을 시뮬레이터에서 굴려 확인했다. 그 과정에서 **빌드 저장 버튼이 눌리지 않는
버그**를 발견해 함께 고쳤다.

## 발견한 버그와 수정

### 1. 홈 large title이 가로 화면을 다녀오면 접힌 채로 굳는다 — 수정함

**증상**: 칼바람/아레나(가로 고정)를 다녀오면 홈의 스크롤 위치가 맨 위인데도 large title이
소형 inline 타이틀로 표시된다. 아래로 당기면 그제야 펴진다.

**원인 추적** — 이 순서로 하나씩 배제했다.

- 스크롤 오프셋 문제가 **아니다**. `scrollTo({y:0})`을 주니 오히려 콘텐츠가 위로 밀렸다.
  즉 오프셋은 이미 맨 위(`-adjustedInset.top`)였고, 접혀 있던 건 네비게이션 바뿐이다.
- 회전을 이 화면이 겪는 것도 **아니다**. `Dimensions.addEventListener('change')`로 찍어보니
  홈은 가로 이벤트를 한 번도 받지 않는다(`saw=false`). 가려진 동안 언마운트되기 때문이다.
- `navigation.setOptions({ headerLargeTitle: false → true })` 토글은 **접기만 하고 펴지 못한다.**
  앱 첫 실행에서 이 토글을 넣자 멀쩡하던 large title이 접혔다.
- `SectionList` remount, 가로 화면을 `fullScreenModal`로 띄우기, 스크린 옵션
  `orientation: 'landscape' | 'portrait'`, 탭 왕복 — **모두 실패**.

남은 사실: 스크롤 오프셋은 정상이고 `UINavigationBar`만 접힌 채 잠긴다. 실제 손가락 pull-down
(스크롤 트래킹)만이 이를 되돌린다. JS에서 그 상태를 되돌릴 방법이 없다.

**수정** (`src/app/(tabs)/(home)/_layout.tsx`): 세로로 돌아오는 순간 `(home)` 스택을
통째로 재생성해 네비게이션 바를 새로 만든다.

```tsx
const [navKey, setNavKey] = useState(0);
useEffect(() => {
  const sub = Dimensions.addEventListener('change', ({ window }) => {
    if (window.width <= window.height) setNavKey((k) => k + 1);
  });
  return () => sub.remove();
}, []);
// <Stack key={navKey} ...>
```

부작용: 스택 재생성으로 `BuildListScreen`이 remount되어 목록 필터(칼바람/아레나)가 초기화된다.
필터를 모듈 스코프(`lastMode`)에 담아 remount를 견디게 했다.

### 2. `/aram-items` 저장 버튼이 눌리지 않는다 — 수정함

**증상**: 아이템을 고르고 헤더 우측 체크(저장)를 눌러도 아무 일도 일어나지 않는다.
두 번 눌러도 같다. 나가서 확인하면 빌드는 저장되지 않았다. **저장이 불가능한 상태.**

같은 헤더의 X(나가기)는 정상 동작한다. 그래서 처음엔 `Host matchContents`가 `flex` 스페이서 뒤에서
폭 0으로 측정되는 문제로 의심했으나, 고정 크기 래퍼를 씌워도 그대로였다.

체크 버튼을 스페이서 **앞**(타이틀 옆)으로 옮기자 즉시 저장됐다. 위치가 원인이다.

**원인**: 이 화면만 `SafeAreaView edges={["top", "left"]}` 로 **`"right"`가 빠져 있었다.**
가로 화면에서 오른쪽 끝은 홈 인디케이터 제스처 영역이라, 그 위에 놓인 저장 버튼의 탭을
시스템이 가져간다. `aram-screen` / `arena-screen`은 `edges`에 `right`가 있어 멀쩡했다.

**수정**: `edges={["top", "left", "right"]}`.

이 버그는 이전 세션에서 X 버튼을 추가하며 헤더 구조가 바뀐 뒤로 있었고, 그때 저장 경로를
다시 굴리지 않아 놓쳤다.

## Findings

- ⚠️ **`GlassButton`을 가로 화면의 오른쪽 끝에 두지 말 것.** 눈에는 멀쩡히 보이고 히트박스도
  정상인데 시스템이 탭을 먹는다. 원인을 코드에서 찾으려 하면 한참 헤맨다. 가로 화면의
  `SafeAreaView`에는 `left`/`right`를 모두 넣는 게 안전하다.
- ⚠️ **`headerLargeTitle` 토글은 단방향이다.** `false`로 주면 접히고, `true`로 되돌려도
  펴지지 않는다. "껐다 켜서 리셋"이 통하지 않는 옵션이다.
- 홈 탭은 가로 화면에 가려지는 동안 **언마운트된다.** `useWindowDimensions`나
  `Dimensions` 리스너로 회전을 감지하려는 시도는 실패한다(ref가 초기화된다).
- 검증 중 `git checkout -- <파일>` 로 세 파일을 되돌리다 **커밋되지 않은 작업을 날렸다.**
  대화에 남은 파일 내용으로 복구했고, 이후 Android/`draft` 잔재 0건 · tsc 0 · lint 0으로 확인했다.
  스테이징되지 않은 변경이 있는 저장소에서 `git checkout --` 는 되돌리기 도구가 아니다.
- 모드 선택 오버레이의 **칼바람 버튼은 dev-client의 톱니 FAB와 정확히 겹친다.** 개발 빌드 한정.

## 검증 절차의 한계

- 애니메이션의 **순서와 감속 곡선은 정지 스크린샷으로 판정할 수 없다.** 프레임을 노려 찍어도
  스크린샷 자체의 지연(수백 ms) 때문에 신뢰할 수 없다. 이번 요청 3번은 코드 수준 보장에 그친다.
- `sips -Z N` 은 **긴 변**을 N으로 맞춘다. 세로 스크린샷에서 폭을 N으로 착각하면 좌표 배율이
  통째로 틀어진다(이번에 한 번 겪었다). 축소본의 실제 크기를 `sips -g pixelWidth` 로 읽고
  `배율 = 402 / 축소폭` 을 그때그때 계산할 것.
- 시뮬레이터 창을 회전(⌘←)시키면 창 **위치가 바뀐다.** `cliclick` 오프셋을 다시 재야 한다.
