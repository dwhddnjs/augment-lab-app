# 티어리스트 화면 추가 (탭 · 모드 필터 · 챔피언 상세 모달)

- 날짜: 2026-09-08
- 기기: iPhone 17 Pro (iOS 26.5, 402×874 pt)
- 빌드: 기존 설치본 + Metro fast refresh (JS·JSON만 변경, 네이티브 재빌드 없음).
  새 라우트 파일이 추가돼 `terminate` + `launch` 로 앱을 두 번 재시작했다.
- **Verdict: PASS** (검증 중 실제 결함 1건을 찾아 고치고 재검증 — 아래 Findings 1번)

## 무엇을 바꿨나

바텀탭에 **티어리스트**를 추가했다(iOS 26+ `NativeTabs` `sf="chart.bar"`, 미만 폴백은
MaterialIcons `bar-chart`). 화면은 상단 모드 세그먼트(칼바람/아레나) + 챔피언을 S/A/B/C/D로
묶은 4열 격자이고, 챔피언을 누르면 모달에서 그 챔피언에게 맞는 증강(희귀도 3그룹)과
아이템을, 아레나는 프리즘 아이템까지 성적순으로 보여준다.

데이터는 `scripts/fetch-data/fetch-tierlist.ts` 가 빌드타임에 구워 번들에 싣는다
(앱은 런타임에 아무 데도 요청하지 않는다). 칼바람 승률은 aram.gg 백엔드, 아레나는 Blitz
내부 API, id↔슬러그 매핑과 아이템 이름·아이콘은 CommunityDragon.

**클래식(협곡 광란)은 필터에 없다.** Riot이 Mayhem 계열 match-v5를 403으로 막아 둔 탓에
어느 집계처도 그 모드의 승률을 갖고 있지 않다(metasrc는 ARAM+Arena를 합성한 값이다).

## Steps

### 탭 진입 · 모드 전환

1. 앱 재시작 → 홈(내 빌드). **탭바가 메인 / 티어리스트 / 마이페이지 / `+` 4칸으로 늘었고**,
   티어리스트 아이콘이 막대그래프로 떴다. `+` 는 `role="search"` 라 JSX 순서와 무관하게
   맨 뒤에 붙는다.
2. 티어리스트 탭 → large title "티어리스트", 그 아래 세그먼트, S 배지, 4열 격자가 렌더됐다.
   칼바람 1행이 **야스오 56.6% / 그웬 56.3% / 릴리아 55.9% / 트위스티드… 55.8%** 로
   승률 내림차순. 챔피언 이름이 셀 폭을 넘으면 말줄임표로 잘린다(트위스티드 페이트).
3. **아레나 세그먼트** → 목록이 통째로 바뀌었다. **렐 3.23등 / 쉬바나 3.25등 / 사이온 3.25등 /
   레나타 글라… 3.26등** — 지표 라벨이 `%` 에서 `등` 으로 바뀌고 정렬 방향도 뒤집혔다
   (평균 등수는 낮을수록 좋다). 챔피언 구성도 탱커·서포터 위주로 칼바람과 겹치지 않는다.
4. 목록 맨 아래까지 스크롤 → D 티어 끝이 **바드 40.7% / 크산테 40.6%**, 그 아래 출처 푸터가
   "aram.gg 집계 · 패치 16.17 · 2026-09-06 기준 / 챔피언 승률·픽률은 중국(텐센트) 서버 통계,
   증강 승률은 이용자 클라이언트가 업로드한 표본입니다. 아이템은 일반 칼바람(ARAM)
   통계입니다. 표본 편향이 있을 수 있습니다." 로 3줄 표시됐다.

### 챔피언 모달 — 아레나 (쉬바나)

5. 아레나 2위 쉬바나 탭 → 모달이 올라왔다. 헤더 좌측 `xmark`, 타이틀 "쉬바나".
6. 챔피언 헤더: 스플래시 + **S 배지(민트)** + 이름 + "전사 · 탱커" + **"3.25등 · 1등 22.4%"**
   (accent) + **"172명 중 2위"**. 순위·티어가 목록의 S 섹션 위치와 일치한다.
7. **증강이 실버/골드/프리즘 3그룹으로 갈렸고 각 그룹이 4개씩 찼다.** 실버 1위가
   `증강된 힘 평균 2.74등 · 1,084판`. 카드 좌측 테두리가 실버는 은색, 골드는 금색으로
   `useRarityColors()` 값이 그대로 들어갔다. 설명도 잘림 없이 렌더된다.
8. **아이템 6개** — 1위가 **`황금 뒤집개 평균 2.10등 · 908판`**. 이게 이번 설계의 핵심
   확인 지점이다: `224403` 은 아레나 전용이라 앱 `items.ko.json`(254개)에 없고, 앱 데이터에
   조인했다면 **모든 챔피언의 1등 아이템이 통째로 안 보였을 것**이다. CDragon 사전으로
   구운 덕에 이름·아이콘이 정상으로 떴다.
9. **프리즘 아이템 섹션이 별도로** 5개 — 살점포식자 2.72등 · 2,536판 … 조종의 손아귀 2.92등.
   `447` 접두사 분리가 실제로 동작해 일반 아이템 섹션과 섞이지 않았다.
10. 모달 하단 출처: "평균 등수는 낮을수록 좋습니다 · 패치 16.17 · 2026-09-06 기준".

### 챔피언 모달 — 칼바람 (그웬)

11. 칼바람으로 되돌린 뒤 그웬 탭 → **"56.3% · 픽 4.0%"**, **"171명 중 2위"**.
    칼바람은 171명, 아레나는 172명으로 모드별 모수가 다르게 나온다(수집 결과 그대로).
12. 증강 실버 1위 `도주 계획 61.3% · 4,535판`, 골드 1위 `환영 무기 62.8% · 21,351판` —
    승률 내림차순, 표본수 천 단위 구분자 정상.
13. 아이템 섹션에 **프리즘 섹션이 없다**(칼바람이므로 의도대로).
    출처는 "아이템은 일반 칼바람(ARAM) 통계 · 패치 16.17 · 2026-09-06 기준".

### 라이트/다크

14. 마이페이지 → 테마 → 라이트 → 티어리스트 복귀. 배경이 밝은 회색으로 뒤집히고
    **세그먼트가 흰 선택 인디케이터 + 회색 트랙**으로, S 배지는 흰 알약 + 민트 글자로
    전환됐다. 챔피언 이름·승률·출처 푸터 모두 읽힌다.
15. 다크로 되돌린 뒤 재확인 — 원래 톤으로 복귀.

## Findings

1. **[결함 — 고침] 칼바람 아이템에 표본 하한이 없어 71판짜리가 1위로 올라왔다.**
   최초 검증에서 그웬의 아이템 1위가 `리안드리의 고통 66.2% · 71판` 이었다. 그 아래
   `라바돈의 죽음모자 61.4% · 1,042판` 이 있는데도 표본 71판이 위를 차지한 것.
   아레나에는 `num_games >= 200` 을 걸어 뒀는데 칼바람 아이템(dtodo `situationalItems`)에만
   `games > 0` 이었다. dtodo가 **증강에는** `winRateMinimumGames`(255)를 주지만 아이템에는
   안 준다는 걸 놓쳤다. `MIN_GAMES = 200` 을 양쪽에 적용해 재수집.
   → 그웬 아이템이 라바돈(1,042판) 1위로 바뀌고 여전히 6개가 다 찬다. 전체 최소 표본은
   칼바람 202판 / 아레나 200판. `check-tierlist.ts` 에 같은 하한 assert 를 넣어 회귀를 막았다.

2. **SwiftUI segmented Picker 는 폭을 스스로 주장하지 않는다.** 처음엔 세그먼트가 좌측에
   글자 폭만큼 쪼그라들었다. `custom-settings-drawer.tsx` 주석이 경고한 그 현상인데
   (거기선 `List(insetGrouped)` 에 폭을 맡겨 해결했다), **`matchContents` 도
   `frame({ maxWidth })` 도 이걸 펴지 못했다.** Host 의 `style` 에 실제 치수
   (`width: 화면폭 - 인셋*2`, `height: 32`)를 주니 그 값이 SwiftUI 레이아웃의 제안 폭으로
   내려가 전폭이 됐다. 리스트 헤더처럼 `List` 로 감싸기 곤란한 자리에서는 이 방법이 답이다.

3. **선택된 세그먼트가 민트가 아니라 회색이다.** `tint(colors.accent.default)` 를 줬지만
   iOS 26 의 `.pickerStyle(.segmented)` 는 선택 인디케이터 배경에 tint 를 적용하지 않는다
   (UIKit 의 `selectedSegmentTintColor` 영역이고 expo-ui 로는 못 닿는다). 홈의 `mode-switch`
   가 민트인 건 그쪽이 RN 커스텀 컴포넌트라서다. 네이티브 표준 룩이므로 그대로 뒀다 —
   맞추려면 RN 으로 내려가야 하는데 그건 "네이티브가 hero" 원칙에 반한다.

4. **iOS 26 미만 폴백 탭바는 실기로 확인하지 못했다.** 부팅 가능한 시뮬레이터가 iOS 26.1/26.5
   뿐이라 `custom-tabs.tsx` 경로는 코드 수준 보장만 있다. 4칸이 되면서 원형 `+` 버튼을 맨 뒤로
   옮겨 iOS 26+ 순서와 맞췄다(중앙에 두면 4칸 균등 분할에서 정중앙을 벗어난다).

5. **알려진 데이터 한계** — 화면 동작이 아니라 소스의 성질이다.
   - 칼바람 아이템은 `queueId 450`(일반 칼바람) 통계다. 증강은 광란(2400) 기준이라 둘이
     섞여 있고, 그래서 모달·목록 출처에 그 사실을 적어 뒀다. 광란 아이템 승률은 어느
     소스에도 없다(Blitz 가 티어 1~5만 주는데 동점이 수십 개라 정렬이 안 된다).
   - 아레나 증강의 8.4% 가 조인에 실패해 버려진다. 앱 `arena/data/augments.ko.json` 이
     200개인데 CDragon 은 657개라 신규 증강이 앱에 없다. 조인 실패분을 **slice 전에**
     버리므로 희귀도별 4개는 항상 채워진다(실제로 전 챔피언 3희귀도 ≥1 을 assert 로 확인).
   - `805`(Locke)가 빠진다. 앱 챔피언 데이터가 DDragon 16.16.1 스냅샷이라 신규 챔피언이 없다.
   - 두 소스 모두 비공식 내부 API다. 그래서 런타임이 아니라 빌드타임에만 때리고,
     스크립트에 `aram/arena < 150명이면 throw` 가드를 뒀다. 소스가 죽어도 앱은 마지막
     스냅샷으로 동작한다.

6. **검증 수단 메모** — MCP `swipe` 로는 이 화면의 `ScrollView`/`SectionList` 가 스크롤되지
   않았다(같은 좌표로 두 번 시도, 화면 무변화). 중간 샘플을 넣은 `touch_path` 로 바꾸니
   바로 먹었다. 관성 스크롤이 필요한 화면에서는 `touch_path` 를 쓰는 편이 확실하다.
   상태바 탭(맨 위로)도 동작하지 않아 반대 방향 `touch_path` 를 반복했다.

## 생성물

`npx tsx scripts/check-tierlist.ts` 통과:

```
aram: 171명 · S 17 / A 34 / B 52 / C 42 / D 26
arena: 172명 · S 17 / A 35 / B 51 / C 43 / D 26
아이템 사전 197개 · 패치 16.17 · 2026-09-06
```

`tierlist.json` 349KB + `tierlist-items.{ko,en}.json` 각 24KB = 397KB.
백분위 컷(S 10% / A 30% / B 60% / C 85%)이 두 모드 모두 균등하게 찼다.
