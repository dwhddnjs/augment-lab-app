## 수치 출처 — 이번에 확인한 사실

증강 수치를 한 곳에서 가져올 수 없다는 점이 이 작업의 핵심 제약이었다.

- **CDragon `cherry-augments.json`에는 수치가 없다.** 필드가 id·이름·아이콘·rarity 뿐이고
  `dataValues`가 0건이다. stringtable 설명의 수치는 `@HealthThreshold*100@` 같은 플레이스홀더라
  기존 정제 로직이 지우면서 "적을**%** 둔화" 같은 깨진 문장이 나왔다.
- **실제 계수는 게임 bin `map30.bin.json`에 있다.** `Maps/Shipping/Map30/Spells/Augment_<코드명>/mSpell/DataValues`
  경로에 변수→값이 들어 있다(288개 증강). 여기 값으로 `@Var@`를 채우도록 스크립트를 고쳤고,
  수치 미확인 신규가 **27건 → 21건**으로 줄었다.
- **위키 `Module:MayhemAugmentData/data`는 신규 57개를 아직 반영하지 않았다.** 대신 기존 증강의
  실수치는 여기에만 있어 대조용으로만 썼다. Cloudflare 때문에 node `fetch`는 403이라 `curl`로 우회한다.
- **위키 수치를 일괄 반영하지 않았다.** 기존 222개를 대조하니 128건에서 수치가 달랐는데 대부분
  패치 변경이 아니라 서술 상세도 차이였다(`Flashbang`은 앱에만 재사용 대기시간 240이 있고,
  `Heavy Hitter`는 앱에만 3.5가 있다). 앱에 수치가 아예 없는 "명백한 누락"만 보강하고,
  나머지 **71건은 검수 페이지의 "확인 필요" 목록**으로 남겼다.

## 데이터 오류 2건 — 이번에 발견해 고침

1. **설명이 뒤바뀌는 매칭 버그.** `descFrom()`이 아이콘 파일명을 먼저 보고 stringtable을 찾는 바람에,
   아이콘을 돌려 쓰는 증강끼리 설명이 섞였다. `Executioner`(아이콘이 `spiritualpurification`)가
   `Spirit of the Jungle Main`의 설명을 물어왔다. `augmentNameId` 우선으로 순서를 바꿔 해결했다.
2. **게임 내 통계 꼬리.** `@f1@`/`@f2@`는 게임에서 "입힌 피해량: 1,234"처럼 누적 통계를 띄우는
   자리인데 카드에 "입힌 피해량:"만 덩그러니 남았다. 해당 조각을 걷어내도록 했다.

## Findings

- **PASS — 설명 잘림 없음.** 스크린샷으로 확인한 모든 카드에서 말줄임표가 나오지 않았다.
  긴 설명은 `adjustsFontSizeToFit`으로 글자가 줄어들며 전부 들어간다.
- **PASS — 신규 증강 등장·아이콘 정상.** 굴리는 동안 신규 4종(천천히 꾸준히 · 신성한 불길 ·
  악마의 춤 · 거석상의 용기 보강분)이 나왔고 아이콘이 모두 떴다.
  신규 57개 아이콘 URL을 전수 확인한 결과 `_large`는 24개가 404지만 **small 폴백은 57개 전부 200**이라,
  앱의 `AugmentImage` 폴백 체인에서 문제가 없다.
- **PASS — 등급 확률 30/30/40.** `node scripts/check-rarity-odds.mjs`로 20만 회 롤:
  실버 29.98% · 골드 29.98% · 프리즘 40.03% (편차 0.03%p 이내).
  화면에서도 프리즘 라운드가 실제로 등장했다.
- **PASS — 리롤 등급 유지.** 리롤해도 같은 골드가 유지됐다.
- **PASS — 기존 데이터 보존.** 기존 222개의 `id`가 하나도 사라지지 않았다(빌드 저장 데이터의 참조 보호).
  설명 변경은 압축 대상과 누락 보강 대상에만 걸렸다.
- **PASS — 깨진 설명 0건.** 반영 전 16건이던 문장 오류(수치 빈칸·플레이버 꼬리·빈 설명)를 전부 정리했다.
- `npx tsc --noEmit`, `npm run lint` 통과.
