# 커스텀 모드 — 선택 패널 개선 검증

- 날짜: 2026-08-31
- 기기: iPhone 17 Pro 시뮬레이터 (iOS 26.5), Debug 빌드 + Metro
- 대상: 커스텀 화면(`/custom`) 우측 `SelectedPanel` — 담기는 칸 표시 · 드롭 오버레이 ·
  행 제거 버튼 · 칸 탭 전환

## Verdict

**PASS** (검증 중 회귀 1건을 찾아 고친 뒤 재검증)

## 사전 확인

- `npx tsc --noEmit` 통과, `npm run lint` 통과.
- 네이티브 변경 없음 — 기존 설치본에 Metro 번들만 갈아끼워 실행.
- 화면이 landscape 고정이라 시뮬레이터 프레임은 portrait 그대로 두고 좌표를 회전 변환해
  주입했다(`portrait_x = 1206 - landscape_y`, `portrait_y = landscape_x`, ÷3 → point).

| 비활성 칸 목록 스크롤 | 전환 없이 정상 스크롤 |
| 라이트 테마 | 테두리(#18A368)·오버레이·트레이 아이콘 모두 흰 배경에서 읽힌다 |

드래그 중 프레임은 손을 뗀 뒤에만 스크린샷을 찍을 수 있어, `touch_path` 의 마지막 지점을
1.6초 붙잡아 두고 백그라운드에서 2초 뒤 `simctl io screenshot` 을 예약해 잡았다
(이전 검증에서 "확인하지 못한 것"으로 남겼던 항목이다).

## 고친 것

- **칸 전체를 Pressable 하나로 감싸니 안쪽 FlatList 가 스크롤되지 않았다.** 부모 Pressable 이
  터치 시작 단계에서 responder 를 잡아 ScrollView 가 이후 move 를 가져가지 못한다. 담은 게
  6개로 꽉 찬 상태에서 마지막 줄을 볼 수 없었고(회귀), 비활성 칸에서는 스크롤하려는 스와이프가
  칸 전환으로 오발동했다.
  → 껍데기 Pressable 을 걷어내고 **라벨 머리 · 각 행 · 목록 아래 빈 자리**가 각자 같은
  `onPress` 를 들도록 바꿨다. 빈 자리는 `contentContainerStyle.flexGrow: 1` +
  `ListFooterComponent`(flex: 1) 로 채워 목록 아래를 눌러도 전환된다. 재검증에서 활성·비활성
  양쪽 스크롤과 탭 전환이 모두 정상.

## 의외였던 점

- 드래그 중 손가락이 칸 한가운데 있으면 고스트(64pt)가 트레이 아이콘(28pt)을 완전히 가린다.
  아이콘은 칸 중앙 고정이라 손가락을 조금만 비켜도 보인다 — 실사용에서 손가락은 놓을 자리
  근처에 있으므로 그대로 두었다.
- `touch_path` 주입이 드물게 터치를 놓지 않고 남겨, 다음 탭이 그 드래그의 종료로 처리되어
  엉뚱한 항목이 담긴 적이 한 번 있었다. 손으로 다시 굴렸을 때는 재현되지 않았고, 화면에 고스트가
  남아 있는 것으로 구분된다 — 주입 아티팩트로 판단했다.

## 2차 — 배지·말줄임·탭 타깃·드롭 아이콘 (같은 날)

요청 5건(제거 버튼 톤다운·이름 한 줄 말줄임·빈 칸 탭 전환·드롭 아이콘 교체·이름 폭 확대)을
반영하고 같은 기기에서 다시 굴렸다. 네이티브 변경 없어 Metro 번들만 갈아끼움.
`npx tsc --noEmit` 통과, `npm run lint` 통과.

| 확인한 것 | 관찰 |
|---|---|
| 빈 아이템 칸의 점선 **아래 여백** 탭 | 아이템으로 전환 — 토글·좌측 그리드·검색 placeholder 가 함께 바뀐다(요청 3의 원인이던 자리) |
| 목록이 일부 찬 칸의 아래 여백 탭 | 수정 전 **무반응**(회귀 발견) → `ListFooterComponentStyle` 적용 후 정상 전환 |
| 제거 배지 | 행 오른쪽 위 모서리에 회색 `close-circle-outline`. 목록을 훑을 때 빨간 점이 먼저 읽히던 게 사라졌다 |
| 배지 탭 | 그 행만 제거(2/5 → 1/5). 위아래 행은 그대로 |
| 배지 탭(비활성 칸) | 전환 없이 제거만 — 자식 Pressable 이 부모 탭을 가로챈다 |
| 행 본문 탭(반대편 칸) | 제거되지 않고 그 칸으로 전환 |
| 이름 말줄임 | "슈렐리아의…" 처럼 한 줄에서 끊긴다. 두 줄로 늘어나던 행 높이 편차도 사라졌다 |
| 이름 폭 확대 후 | "맬모셔스의 아귀", "지배자의 피갑옷", "루난의 허리케인" 이 잘리지 않고 전부 들어간다 |
| 드롭 오버레이 | 어두운 오버레이 + 민트 `hand-pointing-down`. 아래를 가리키는 손이라 다운로드로 읽히지 않는다 |
| 6/6 목록 스크롤 | 정상 — footer 가 flex 를 가져도 콘텐츠가 넘치면 접혀 스크롤을 막지 않는다 |
| 라이트 테마 | 흰 행 위 회색 배지가 튀지 않게 읽히고, 오버레이·손 아이콘(#18A368)도 또렷하다 |

## 고친 것

- **`ListFooterComponent` 의 `flex: 1` 이 0 으로 접혔다.** FlatList 는 footer 를 높이 auto 인
  wrapper View 로 감싼다 — 그 안에서 자식의 `flex: 1` 은 아무것도 채우지 못한다. 1차 문서에
  "목록 아래 빈 자리도 탭 타깃"이라 적었지만 실제로는 동작한 적이 없었고, 이번에 목록이 두 줄만
  찬 칸에서 눌러 보고 발견했다. `ListFooterComponentStyle: { flex: 1 }` 로 wrapper 에 직접
  flex 를 줘서 고쳤다.
- **빈 칸은 점선 슬롯 높이만 눌렸다.** `styles.empty` 에 `flex: 1` 을 더해 칸 전체가 탭 타깃이 된다.

## 확인하지 못한 것 / 의외였던 점

- **드래그 중 담긴 항목이 하나 사라진 사례 2건**(3/5 → 1/5, 6/6 → 5/6). 둘 다 `touch_path`
  주입이 섞인 구간에서 나왔고, 같은 조작을 손으로 다시 굴렸을 때(배지 위에서 시작한 스와이프,
  단계별 탭)는 **재현되지 않았다**. 1차에서도 같은 성격의 주입 아티팩트를 기록했다 — 합성 터치가
  놓이지 않고 남아 다음 입력이 이전 제스처의 종료로 처리되는 것으로 보인다. 실기기 손 조작에서
  같은 증상이 보이면 그때는 주입 문제가 아니므로 다시 파야 한다.
- 드롭 아이콘은 28pt 라 손 모양의 디테일이 뭉툭하다. 방향(아래)은 그 크기에서도 분명하다.

## 4차 — 아이콘 배경 · 나가기 순서 · 드롭 아이콘 (같은 날)

기기·빌드 동일(iPhone 17 Pro / iOS 26.5, Metro 번들만 갈아끼움).
`npx tsc --noEmit` 통과, `npm run lint` 통과. **라이트 테마**로 굴렸다.

| 확인한 것 | 관찰 |
|---|---|
| 증강 행 아이콘 배경 | 흰 행 위 검은 타일. 회색 판에 아이콘이 떠 있던 게 사라졌다(빌드 상세의 타일과 같은 톤) |
| 아이템 행 아이콘 배경 | 같은 검은 틀. `border.subtle` 테두리는 검은 틀에 묻혀 흰 행 위에서 튀지 않는다 |
| 다크 테마 | 화면 확인 생략 — `surface.sunken`(다크)과 `HeroOverlay.cardBase` 가 둘 다 `#0A0B0D` 라 픽셀이 같다 |
| 드롭 오버레이 아이콘 | 채움 원이 사라지고 **선으로 그린 원 + 화살표**(`arrow-down-circle-outline`). 어두운 오버레이 위에서 덩어리로 뭉치지 않는다 |
| 나가기 → 종료 | 회전 직전 마지막 가로 프레임에 **이미 홈("내 빌드")이 떠 있고**, 그 상태로 세로로 돌아간다 |

## 고친 것

- **`InteractionManager.runAfterInteractions` 로는 안 됐다.** 처음엔 `dismissTo` 뒤에
  이걸 물렸는데, 연속 캡처를 보니 **커스텀 화면이 그대로 회전**하고 그 다음 홈이 떴다 —
  수정 전과 같은 그림이다. 네이티브 스택(react-native-screens)의 dismiss 는
  InteractionManager 핸들을 만들지 않아 콜백이 곧바로 실행된다.
  `setTimeout(420ms)` 으로 바꾸고 나서야 홈이 먼저 뜬 뒤 회전했다.

## 확인하지 못한 것 / 방법 메모

- 같은 나가기 패턴이 `aram-screen` · `arena-screen` · `use-item-select` 에도 있다.
  이번 요청은 커스텀이라 나머지 셋은 손대지 않았고, 굴려 보지도 않았다.
- 드래그 중·회전 중 프레임은 백그라운드 연속 캡처 루프로 잡았다. 루프를 `rm -f x*.png &&`
  로 시작하면 zsh 가 nomatch 로 실패시켜 **뒤의 루프가 통째로 스킵된다**(파일 0개로 확인).
  `;` 로 끊거나 rm 을 빼고 시작할 것.

## 5차 — 라이트 희귀도 색 (같은 날)

라이트 테마, 커스텀 화면에 silver·gold·prismatic 을 한 줄씩 담아 같은 좌표로 크롭 비교.

| 확인한 것 | 관찰 |
|---|---|
| 다크 팔레트로 통일(중간 시도) | silver 는 읽혔지만 gold 가 옅고 **prismatic 이름은 거의 안 읽혔다**("기본으로 돌아…"가 배경에 묻힘). 되돌렸다 |
| 톤 다운 1차(4.6:1) | 세 이름 모두 또렷하고, 이전 먹빛보다 색기가 산다 |
| 톤 다운 2차(3.5:1, 최종) | 요청으로 한 단계 더 낮췄다. 색은 더 살고 세 이름 모두 아직 읽힌다 — 다만 본문 AA 아래다 |
| 행 좌측 보더 | 세 티어 모두 구분된다(3pt) |
| 아이콘 타일 테두리 | 검은 타일 위라 다크 팔레트를 그대로 쓴다 — 이 변경과 무관 |

숫자는 흰 배경(`surface.raised`) 기준 계산값(silver / gold / prismatic):
이전 6.35 / 5.37 / 6.65 → 1차 4.59 / 4.63 / 4.62 → **최종 3.50 / 3.51 / 3.51:1**.
다크 통일안은 2.55 / 1.92 / 1.38:1 이었다.
