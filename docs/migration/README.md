# 네이티브 마이그레이션 — 큰 틀과 세션 규칙

RN(Expo)을 걷어내고 **iOS = SwiftUI → Android = Kotlin + Jetpack Compose** 순서로 다시 만든다.
Android는 Google Play의 기존 앱 porcana(`com.porcana`) 리스팅을 바꿔치기해서 낸다(`porcana-to-augmentlab.md`).
결정 배경 전체: `docs/plans/2026-11-26-네이티브-마이그레이션-작업체계.md`

## 지금 어디까지 했나

```bash
git checkout dev && git pull
bash docs/migration/status.sh      # 완료 / 진행중 / 시작가능 / 대기
```

- **진행중** = `native/<ID>` 브랜치가 있다(다른 세션이 작업 중이거나 PR 대기).
- **시작가능** = 의존 작업이 전부 dev에 머지됐다.
- 작업마다 자세한 상태는 각 작업 파일의 **진행 기록**에 있다.

## 세션 규칙 (매 세션 이것만 읽고 시작)

**토큰 절약 — Pro 플랜**
- 읽는 것은 이 섹션, 지정된 작업 파일 1개, 그 파일의 `spec`·`rn`에 적힌 파일뿐이다. 저장소 전체를 훑지 않는다.
- 서브에이전트는 꼭 필요할 때만 쓴다.
- 시뮬레이터는 띄우지 않는다(사용자가 직접 본다). 세션은 컴파일과 단위 테스트까지만 한다.

### 1. 시작
1. 사용자가 작업 ID를 지정한다. 예: "I-02a 해줘"
2. `bash docs/migration/status.sh`로 해당 작업이 **시작가능**인지 확인한다. 대기·진행중이면 멈추고 알린다.
3. 워크트리를 만든다:
   ```bash
   git worktree add .claude/worktrees/<ID> -b native/<ID> dev
   cd .claude/worktrees/<ID>
   ```
   - 이어서 하는 작업이면 워크트리가 이미 있다 → 그 폴더로 가서 작업 파일의 **진행 기록** 마지막 항목부터 이어 간다.
4. 작업 파일을 열고 목표·체크리스트·spec을 읽는다.

### 2. 작업 중
- **수정할 수 있는 것은 frontmatter `owns` 경로와 자기 작업 파일뿐**이다. 다른 작업이 소유한 파일은 열어 보기만 한다.
- 공용 파일을 바꿔야 하면 멈추지 않는다.
  1. 자기 폴더 안에 임시로 구현한다.
  2. 작업 파일의 **승격 후보**에 적는다.
  3. 나중에 사용자가 짧은 직렬 작업으로 반영한다.
- 다른 화면으로 가는 이동은 `Router` API(I-06a)만 호출한다. 다른 피처의 View를 직접 참조하지 않는다.
  - 예외: I-06a가 만든 스텁 시그니처(예: 홈 안의 `TopTierSection`)
- 의존성(SPM·Gradle) 추가 금지. 필요하면 승격 후보로 적는다.
- **체크리스트 한 줄을 끝낼 때마다**: `- [x]`로 체크하고 로컬 커밋한다(한국어 메시지, 예: `feat(I-02a): 증강 모델 디코딩`).
  - 한도 때문에 갑자기 끊겨도 잃는 것은 진행 중이던 한 줄뿐이다.
- 빌드·테스트 명령은 워크트리 안에서 실행한다:
  - `make -C native/ios build`
  - `make -C native/ios test`
  - derivedData가 워크트리마다 따로 잡혀서 동시에 빌드해도 서로 막지 않는다.

### 3. 끝 (작업 완료)
1. 완료 기준을 체크한다. `bash docs/migration/status.sh diff <ID>` → "owns 밖 변경 없음"이어야 한다.
2. frontmatter를 `status: done`으로 바꾸고 **진행 기록**을 쓴다(날짜 · 한 일 · 주의점 · 사용자가 볼 것).
3. 커밋 → `git push -u origin native/<ID>` → `gh pr create --base dev`
4. 사용자에게 안내한다: "PR 열었음. **사용자 확인** 항목을 시뮬레이터에서 봐 주세요. 리뷰까지 원하면 `/ship`."
5. 사용자가 확인하고 머지하면 완료다. 머지 후 워크트리 정리: `git worktree remove .claude/worktrees/<ID>`
   - **디스크 주의**: 워크트리마다 iOS 빌드 캐시(`.build/ios`)가 약 4.6GB 쌓인다. 머지된 워크트리는 바로 지운다(2026-11-26에 9개가 쌓여 디스크가 가득 찼다).

### 4. 5시간 한도 95% (자동 경고)
훅(`.claude/hooks/usage-guard.sh`)이 95%를 감지하면 이런 지시가 들어온다. 받으면 **새 단계를 시작하지 말고**:
1. 지금 하던 줄까지만 끝낸다(못 끝내면 되돌리지 말고 그대로 둔다).
2. 작업 파일 **진행 기록**에 남긴다: 마친 줄 · 진행 중이던 줄과 상태 · 다음에 할 첫 행동 · 주의점.
3. 커밋(`wip(<ID>): ...`) → `git push -u origin native/<ID>`
4. 사용자에게 알리고 멈춘다: "한도 95% — 기록·push 완료. 리셋 후 '<ID> 이어서'라고 하면 됩니다. PR·리뷰가 필요하면 `/ship`."

`/ship`은 사용자만 입력할 수 있다. PR 생성 + 리뷰 + 감시까지 해서 토큰을 많이 쓰므로 95%일 때 자동으로 돌리지 않는다.

## 멀티 세션 — 왜 충돌이 안 나는가

- **1 작업 = 1 브랜치 = 1 워크트리.** 작업 폴더가 물리적으로 다르다.
- **`owns` 경로는 서로 겹치지 않는다.** 작업 파일 전체에 대해 검사를 마쳤다.
  - 예외: W3 직렬 작업. 이때는 다른 iOS 작업을 돌리지 않는다.
- **Xcode 동기화 폴더**: 파일을 추가해도 `project.pbxproj`가 바뀌지 않는다. pbxproj를 건드리는 것은 I-00과 I-43뿐이다.
- **스텁 계약**
  - I-06a가 모든 피처 진입 View를 시그니처 고정 스텁으로 먼저 만든다.
  - 이후 그 파일은 해당 피처가 소유하므로, 피처끼리 서로를 기다리지 않는다.
- **공유 상태판이 없다.** 상태는 각 작업 파일 frontmatter에만 있다.
  - 이 README의 표는 바뀌지 않는 정보만 담는다 → 같은 파일을 두 세션이 고칠 일이 없다.
- **동시 세션 수**: 5시간 한도를 계정 전체가 공유한다. 2~3개를 권장한다(훅은 모든 세션에 동시에 경고한다).

## 공통 결정 (바꾸려면 사용자와 먼저 합의)

**공통**
1. **동작은 RN과 똑같이 맞춘다.** 고의로 바꾸는 것은 두 가지뿐이다.
   - 신규 설치 언어 = 기기 언어
   - 데이터 관리 busy 가드를 적용이 끝날 때까지 유지
2. **데이터 JSON은 옮기지 않는다** — 세 앱 모두 `src/features/*/data/*.json`을 읽는다. 옮기는 것은 R-01에서.
3. **번역은 파일별 사전**(`{ko:{…}, en:{…}}` + `t(key)`, en 폴백) — RN 규칙 그대로
4. **토큰만 쓴다** — 색·크기 리터럴 금지(디자인 시스템 규칙 그대로)
5. **로직 테스트는 RN 골든 값으로 한다** — 기대값은 RN 함수를 `npx tsx -e`로 실행해 뽑는다

**iOS**
- 최소 17.0
- 순수 로직은 `AugmentCore` 패키지(`swift test`, 시뮬레이터 불필요)
- 의존성 3개: SDWebImageSwiftUI, PostHog, Sentry
- MCI 아이콘은 RN 폰트 파일을 그대로 쓴다

**Android**
- `applicationId = com.porcana`(영구), `namespace = com.augmentlab`
- minSdk 26 / targetSdk 36
- 디자인은 iOS 26 미만 폴백 디자인을 기준으로 삼는다
